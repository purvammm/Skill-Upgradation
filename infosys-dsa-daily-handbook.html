Java collections toolkit

Plan day 1Plan day 1
Use it when
  • Every problem. Know these calls without looking them up.
  • "Have I seen x?" → HashSet · "how many x?" → HashMap or int[26] · "smallest/largest so far?" → PriorityQueue · "nearest key below/above x?" → TreeMap · "last in" → ArrayDeque stack · "first in" → ArrayDeque queue.

How it works

Pick the structure by the question you must answer quickly, then use the call that answers it in one step. The tour below shows the calls you will type most, with the result of each in a comment.

📄Templatememorise
static void toolkitTour() {
    // HashMap: counting and lookups
    int[] a = {3, 1, 3, 2, 3};
    Map<Integer, Integer> freq = new HashMap<>();
    for (int x : a) freq.merge(x, 1, Integer::sum);   // same as put(x, getOrDefault(x, 0) + 1)
    int threes = freq.getOrDefault(3, 0);              // 3
    int nines = freq.getOrDefault(9, 0);               // 0 (missing key, no exception)

    // int[26] is faster than a map for lowercase letters
    int[] cnt = new int[26];
    for (char c : "banana".toCharArray()) cnt[c - 'a']++;   // cnt[0] == 3 (three 'a')

    // Sorting: int[] sorts ascending. Custom order needs int[][] or Integer[] plus a comparator.
    int[][] pairs = {{2, 5}, {1, 9}, {2, 1}};
    Arrays.sort(pairs, (x, y) -> x[0] != y[0] ? Integer.compare(x[0], y[0]) : Integer.compare(x[1], y[1]));
    // pairs is now {1,9}, {2,1}, {2,5}
    Integer[] boxed = {5, 2, 8};
    Arrays.sort(boxed, Collections.reverseOrder());    // 8, 5, 2
    List<String> words = new ArrayList<>(Arrays.asList("bbb", "a", "cc"));
    words.sort((x, y) -> Integer.compare(x.length(), y.length()));   // a, cc, bbb

    // Heaps
    PriorityQueue<Integer> minHeap = new PriorityQueue<>();                          // poll() = smallest
    PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder()); // poll() = largest
    PriorityQueue<long[]> byFirst = new PriorityQueue<>((x, y) -> Long.compare(x[0], y[0]));

    // ArrayDeque is both the stack and the queue (don't use Stack)
    ArrayDeque<Integer> stack = new ArrayDeque<>();
    stack.push(1);
    stack.push(2);
    int top = stack.pop();                             // 2 (last in, first out)
    ArrayDeque<Integer> queue = new ArrayDeque<>();
    queue.offer(1);
    queue.offer(2);
    int front = queue.poll();                          // 1 (first in, first out)

    // TreeMap / TreeSet stay sorted: floor / ceiling in O(log n)
    TreeMap<Integer, String> tm = new TreeMap<>();
    tm.put(10, "a");
    tm.put(20, "b");
    Integer floor = tm.floorKey(15);                   // 10 (largest key <= 15, null if none)
    Integer ceil = tm.ceilingKey(15);                  // 20 (smallest key >= 15)
    TreeSet<Integer> ts = new TreeSet<>(Arrays.asList(4, 1, 7));
    Integer above = ts.higher(4);                      // 7 (strictly greater); ts.lower(4) == 1

    // Strings: build with StringBuilder, compare with equals()
    StringBuilder sb = new StringBuilder();
    sb.append("ab").append(3).reverse();
    String s = sb.toString();                          // "3ba"
    boolean same = s.equals("3ba");                    // true (== compares references, not text)
    char[] chars = s.toCharArray();
    Arrays.sort(chars);
    String sorted = new String(chars);                 // "3ab"
}

Cost: HashMap / HashSet: O(1) average · PriorityQueue add/poll: O(log n), peek: O(1) · TreeMap/TreeSet: O(log n) · ArrayDeque: O(1) at both ends · Arrays.sort: O(n log n)

Variants

  • Collections.sort(list) and list.sort(cmp) sort lists; Arrays.sort sorts arrays.
  • map.computeIfAbsent(k, x -> new ArrayList<>()).add(v) builds groups (Group Anagrams).
Traps
  • Arrays.sort(int[], comparator) doesn't compile: a comparator needs Integer[] or int[][].
  • Comparator (x, y) -> x - y overflows for large values. Use Integer.compare(x, y).
  • == on two Integer objects compares references and fails above 127. Use .equals() or unbox.
  • map.get(k) returns null for a missing key; unboxing null throws NullPointerException. Use getOrDefault.

Fast input and output (FastScanner)

Plan day 1Plan day 1
Use it when
  • You write main yourself and read standard input (Infosys full-program questions, Codeforces).
  • More than about 10⁵ numbers to read, or more than 10⁴ lines to print.
  • On LeetCode you need none of this: your method gets the input as arguments.

How it works

BufferedReader reads the input in big chunks and hands out one line at a time. StringTokenizer splits that line on spaces. next() keeps reading lines until it has a word, so numbers can come one per line or all on one line. All output goes into one PrintWriter that is flushed once at the end. Section 03 of the plan explains each line and compares it with Scanner.

📄Templatememorise
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        FastScanner fs = new FastScanner(System.in);
        PrintWriter out = new PrintWriter(new BufferedWriter(new OutputStreamWriter(System.out)));

        int n = fs.nextInt();                    // works for "one value per line" and "all on one line"
        long[] a = new long[n];
        for (int i = 0; i < n; i++) a[i] = fs.nextLong();

        long sum = 0;
        for (long x : a) sum += x;
        out.println(sum);
        out.flush();                             // without this you print nothing
    }

    /** BufferedReader reads big chunks; StringTokenizer splits a line on spaces. */
    static final class FastScanner {
        private final BufferedReader br;
        private StringTokenizer st;

        FastScanner(InputStream in) {
            br = new BufferedReader(new InputStreamReader(in));
        }

        String next() throws IOException {
            while (st == null || !st.hasMoreTokens()) {   // current line used up: read another
                String line = br.readLine();
                if (line == null) return null;           // end of input
                st = new StringTokenizer(line);
            }
            return st.nextToken();
        }

        int nextInt() throws IOException { return Integer.parseInt(next()); }

        long nextLong() throws IOException { return Long.parseLong(next()); }

        double nextDouble() throws IOException { return Double.parseDouble(next()); }

        String nextLine() throws IOException {           // the next whole line, spaces included
            st = null;                                   // (drops anything left on the current line)
            return br.readLine();
        }
    }
}

Cost: Measured on 10⁶ numbers: Scanner 818 ms, FastScanner 144 ms, byte FastReader 33 ms. Printing 10⁶ lines: println 2.0 s, PrintWriter 0.15 s.

Variants

  • Strings: fs.next() reads one word; fs.nextLine() reads a whole line with its spaces.
  • Unknown number of values: loop while ((s = fs.next()) != null).
Traps
  • Forget out.flush() and the program prints nothing.
  • nextLine() in the middle of a line drops the rest of that line.
  • main needs throws IOException.

Stacks & lists

Linked list moves

Plan day 1Plan day 1
Use it when
  • LeetCode list problems: reverse, middle, cycle, merge.
  • Interview questions on paper; Infosys interviews have asked these.

How it works

Draw three boxes: prev, cur, next. Reversing means: save next, point cur back at prev, move both forward. Fast/slow pointers: fast moves two steps, slow moves one. When fast reaches the end, slow is in the middle; if there is a cycle, fast laps slow and they meet.

📄Templatememorise
static final class ListNode {                       // LeetCode's list node
    int val;
    ListNode next;

    ListNode(int val) { this.val = val; }
}

static ListNode reverse(ListNode head) {
    ListNode prev = null;
    while (head != null) {
        ListNode nxt = head.next;                        // save, point back, move on
        head.next = prev;
        prev = head;
        head = nxt;
    }
    return prev;
}

static ListNode middle(ListNode head) {                  // second middle for even length
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }
    return slow;
}

static boolean hasCycle(ListNode head) {                 // Floyd: fast catches slow inside a cycle
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) return true;
    }
    return false;
}

static ListNode mergeSorted(ListNode a, ListNode b) {
    ListNode dummy = new ListNode(0), tail = dummy;      // a dummy head removes special cases
    while (a != null && b != null) {
        if (a.val <= b.val) {
            tail.next = a;
            a = a.next;
        } else {
            tail.next = b;
            b = b.next;
        }
        tail = tail.next;
    }
    tail.next = (a != null) ? a : b;
    return dummy.next;
}

Cost: O(n) time, O(1) extra memory

Traps
  • Check fast != null && fast.next != null before fast.next.next.
  • A dummy head node removes the special case for the first element.

Prefix sums + HashMap

Plan day 2Plan day 2
Use it when
  • Count or find subarrays whose sum (or remainder, or XOR) equals something.
  • Many range-sum questions on an array that doesn't change.
  • Negative numbers are allowed, so a sliding window won't work.

How it works

Let P be the running sum. The subarray a[l..r] has sum P[r+1] − P[l], so "sum equals k" asks: at index r, how many earlier prefixes equal P − k? Keep a HashMap from prefix value to how often you have seen it, seeded with {0: 1} for the empty prefix.

a = [1, 2, -1, 2, 1], k = 3
i  a[i]  prefix  look up prefix-k  found  total
0    1      1          -2            0      0
1    2      3           0            1      1    a[0..1] = 1+2
2   -1      2          -1            0      1
3    2      4           1            1      2    a[1..3] = 2-1+2
4    1      5           2            1      3    a[3..4] = 2+1
📄Templatememorise
// P[i] = a[0] + ... + a[i-1], so sum(a[l..r]) = P[r + 1] - P[l]
static long[] prefixSums(int[] a) {
    long[] p = new long[a.length + 1];
    for (int i = 0; i < a.length; i++) p[i + 1] = p[i] + a[i];
    return p;
}

// Number of subarrays with sum exactly k (negative numbers allowed)
static long countSubarraysWithSum(int[] a, long k) {
    Map<Long, Integer> seen = new HashMap<>();   // prefix value -> how many times seen so far
    seen.put(0L, 1);                            // the empty prefix
    long prefix = 0, count = 0;
    for (int x : a) {
        prefix += x;
        count += seen.getOrDefault(prefix - k, 0);   // earlier prefix p with prefix - p == k
        seen.merge(prefix, 1, Integer::sum);
    }
    return count;
}

Cost: O(n) time, O(n) memory.

Variants

  • Divisible by k: store Math.floorMod(prefix, k) and look up the same remainder.
  • Longest subarray with sum k: store the FIRST index of each prefix instead of a count.
  • XOR instead of sum: prefix ^= x, look up prefix ^ k (see Bit tricks).
Traps
  • Forgetting seen.put(0L, 1) misses every subarray that starts at index 0.
  • Use long for prefixes: 10⁵ values of 10⁹ overflow int.
  • Java's % can be negative: −3 % 5 is −3.

Difference array (many range adds)

Plan day 2Plan day 2
Use it when
  • Many updates "add v to every element from l to r", and you read the array only at the end.
  • How many intervals cover each point.

How it works

Instead of touching every element, write +v at l and −v at r + 1. A running sum over d rebuilds the real array: the +v starts adding at l and the −v cancels it after r. Each update costs O(1).

n = 5, add 3 to [1..3], then add 2 to [2..4]
d after the updates:  [0, 3, 2, 0, -3, -2]
running sum = array:  [0, 3, 5, 5, 2]
📄Templatememorise
// Apply many "add v to a[l..r]" updates, then read the array once. O(n + updates).
static long[] applyRangeAdds(int n, int[][] updates) {   // each update = {l, r, v}, inclusive
    long[] d = new long[n + 1];
    for (int[] u : updates) {
        d[u[0]] += u[2];          // start adding at l
        d[u[1] + 1] -= u[2];      // stop after r
    }
    long[] a = new long[n];
    long running = 0;
    for (int i = 0; i < n; i++) {
        running += d[i];
        a[i] = running;
    }
    return a;
}

Cost: O(n + updates)

Variants

  • Updates and queries mixed together: Fenwick tree or lazy segment tree instead.
  • 2D: +v at (r1, c1), −v at (r1, c2+1) and (r2+1, c1), +v at (r2+1, c2+1).
Traps
  • Size d as n + 1 so that d[r + 1] exists when r = n − 1.

Two pointers on a sorted array

Plan day 3Plan day 3
Use it when
  • Pairs or triples with a target sum, after sorting.
  • "Count pairs with sum ≤ X", closest sum, boats/people pairing.

How it works

Put l at the start and r at the end. Sum too small: only l++ can grow it. Too big: r−−. Each step discards one element for good, so the scan is O(n). For counting: if a[l] + a[r] ≤ target, then a[l] pairs with every index from l + 1 to r.

📄Templatememorise
// Sorted array, pointers at both ends: does any pair add up to target?
static boolean hasPairWithSum(int[] sorted, long target) {
    int l = 0, r = sorted.length - 1;
    while (l < r) {
        long s = (long) sorted[l] + sorted[r];
        if (s == target) return true;
        if (s < target) l++;      // need a bigger sum
        else r--;                 // need a smaller sum
    }
    return false;
}

// Count pairs i < j with sorted[i] + sorted[j] <= target
static long countPairsAtMost(int[] sorted, long target) {
    long count = 0;
    int l = 0, r = sorted.length - 1;
    while (l < r) {
        if ((long) sorted[l] + sorted[r] <= target) {
            count += r - l;       // sorted[l] pairs with every index in (l, r]
            l++;
        } else {
            r--;
        }
    }
    return count;
}

Cost: O(n) after an O(n log n) sort

Variants

  • 3Sum: fix i, run two pointers on the rest, skip equal values to avoid duplicate triples.
Traps
  • Sorting changes indices. If the answer needs the original indices, sort an array of indices instead.
  • Cast before adding: (long) a[l] + a[r].

Sliding window (variable size)

Plan day 3Plan day 3
Use it when
  • Longest or shortest contiguous subarray / substring with a condition.
  • The condition stays true when you shrink a valid window: at most k distinct, at most k zeros, sum ≤ X with positive numbers.

How it works

Move r one step at a time and add a[r]. While [l, r] breaks the rule, remove a[l] and move l right. Then [l, r] is the longest valid window ending at r. Both pointers only move forward, so the total work is O(n).

a = [1, 2, 1, 3, 3, 2], at most 2 distinct
r  a[r]  window after shrinking         best
0    1   [1]                              1
1    2   [1, 2]                           2
2    1   [1, 2, 1]                        3
3    3   [1, 3]       (l moved 0 -> 2)    3
4    3   [1, 3, 3]                        3
5    2   [3, 3, 2]    (l moved 2 -> 3)    3
📄Templatememorise
// Longest subarray with at most k distinct values.
// Template: grow r, shrink l while the window is invalid, then record the answer.
static int longestAtMostKDistinct(int[] a, int k) {
    Map<Integer, Integer> cnt = new HashMap<>();
    int best = 0;
    for (int l = 0, r = 0; r < a.length; r++) {
        cnt.merge(a[r], 1, Integer::sum);                       // 1. add a[r]
        while (cnt.size() > k) {                                // 2. shrink while invalid
            if (cnt.merge(a[l], -1, Integer::sum) == 0) cnt.remove(a[l]);
            l++;
        }
        best = Math.max(best, r - l + 1);                       // 3. [l, r] is valid
    }
    return best;
}

// Shortest subarray with sum >= target (all values positive)
static int shortestSumAtLeast(int[] a, long target) {
    int best = Integer.MAX_VALUE;
    long sum = 0;
    for (int l = 0, r = 0; r < a.length; r++) {
        sum += a[r];
        while (sum >= target) {                                 // valid: record, then shrink
            best = Math.min(best, r - l + 1);
            sum -= a[l++];
        }
    }
    return best == Integer.MAX_VALUE ? 0 : best;
}

// Count subarrays with EXACTLY k distinct values = atMost(k) - atMost(k - 1)
static long countExactlyKDistinct(int[] a, int k) {
    return countAtMostKDistinct(a, k) - countAtMostKDistinct(a, k - 1);
}

static long countAtMostKDistinct(int[] a, int k) {
    if (k < 0) return 0;
    Map<Integer, Integer> cnt = new HashMap<>();
    long count = 0;
    for (int l = 0, r = 0; r < a.length; r++) {
        cnt.merge(a[r], 1, Integer::sum);
        while (cnt.size() > k) {
            if (cnt.merge(a[l], -1, Integer::sum) == 0) cnt.remove(a[l]);
            l++;
        }
        count += r - l + 1;                                     // every subarray ending at r
    }
    return count;
}

Cost: O(n): l and r each move at most n times

Variants

  • Shortest window with sum ≥ target (positive numbers): record inside the while loop, then shrink.
  • Count windows: add r − l + 1 for each r (all windows ending at r).
  • Exactly k = atMost(k) − atMost(k − 1).
Traps
  • With negative numbers, shrinking doesn't keep the condition true. Use prefix sums.
  • Bringing a count down to 0 doesn't remove the key; remove it yourself or size() is wrong.

Window maximum (monotonic deque)

Plan day 3Plan day 3
Use it when
  • Maximum or minimum of every window of fixed size k.
  • DP where dp[i] needs the best dp among the last k positions.

How it works

Keep the window's indices in a deque with values decreasing from front to back. A new value removes every smaller value at the back: those can never be the maximum while the new one is in the window. The front is the maximum; drop it when it falls out of the window.

a = [1, 3, -1, -3, 5, 3, 6, 7], k = 3
i  a[i]  deque (values)   window max
0    1   [1]
1    3   [3]
2   -1   [3, -1]              3
3   -3   [3, -1, -3]          3
4    5   [5]                  5
5    3   [5, 3]               5
6    6   [6]                  6
7    7   [7]                  7
📄Templatememorise
// Maximum of every window of size k, O(n). The deque holds indices; their values decrease.
static int[] windowMax(int[] a, int k) {
    int n = a.length;
    int[] res = new int[n - k + 1];
    ArrayDeque<Integer> dq = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        while (!dq.isEmpty() && a[dq.peekLast()] <= a[i]) dq.pollLast();   // they can never win now
        dq.addLast(i);
        if (dq.peekFirst() <= i - k) dq.pollFirst();                       // front left the window
        if (i >= k - 1) res[i - k + 1] = a[dq.peekFirst()];
    }
    return res;
}

Cost: O(n): each index enters and leaves the deque once

Traps
  • Store indices, not values, so you can tell when the front has left the window.
  • For the minimum, flip the comparison: pop while the back is ≥ a[i].

Intervals: sort, then sweep

Plan day 4Plan day 4
Use it when
  • Meetings, trains, bookings, ranges on a line.
  • "Merge", "most you can keep", "fewest rooms / platforms", "fewest arrows".

How it works

Sort first; the sort key decides the algorithm. Merge: sort by start and extend the last interval while they overlap. Keep the most non-overlapping: sort by END and take every interval that starts after the last one you took (finishing early leaves the most room). Fewest platforms: sort starts and ends separately and sweep; the busiest moment is the answer.

📄Templatememorise
// Merge overlapping intervals {start, end}
static int[][] merge(int[][] iv) {
    Arrays.sort(iv, (x, y) -> Integer.compare(x[0], y[0]));    // sort by start
    List<int[]> out = new ArrayList<>();
    for (int[] cur : iv) {
        int[] last = out.isEmpty() ? null : out.get(out.size() - 1);
        if (last != null && cur[0] <= last[1]) last[1] = Math.max(last[1], cur[1]);
        else out.add(new int[]{cur[0], cur[1]});
    }
    return out.toArray(new int[0][]);
}

// Most intervals you can keep with no overlap (touching ends allowed): sort by END
static int maxNonOverlapping(int[][] iv) {
    Arrays.sort(iv, (x, y) -> Integer.compare(x[1], y[1]));
    int count = 0;
    long end = Long.MIN_VALUE;
    for (int[] cur : iv) {
        if (cur[0] >= end) {
            count++;
            end = cur[1];
        }
    }
    return count;
}

// Most intervals covering one point = minimum platforms / meeting rooms.
// Closed intervals: a train that arrives at the minute another leaves needs its own platform.
static int maxOverlap(int[][] iv) {
    int n = iv.length;
    int[] starts = new int[n], ends = new int[n];
    for (int i = 0; i < n; i++) {
        starts[i] = iv[i][0];
        ends[i] = iv[i][1];
    }
    Arrays.sort(starts);
    Arrays.sort(ends);
    int best = 0, busy = 0;
    for (int i = 0, j = 0; i < n; i++) {
        while (j < n && ends[j] < starts[i]) {   // use <= if touching intervals can share
            j++;
            busy--;
        }
        busy++;
        best = Math.max(best, busy);
    }
    return best;
}

Cost: O(n log n) for the sort, O(n) for the sweep

Variants

  • Fewest to remove (LC 435) = n − maxNonOverlapping.
  • Fewest arrows (LC 452) = most non-overlapping when touching counts as overlap (use > instead of >=).
Traps
  • Decide whether touching endpoints overlap ([1,2] and [2,3]). The statement decides, and it turns < into <=.
  • Sorting int[][] needs a comparator; use Integer.compare, not subtraction.

Greedy with a heap

Plan day 5Plan day 5
Use it when
  • Options unlock over time (capital, deadlines, positions) and you always want the best unlocked one.
  • "In any order", "at most k times", "ladders and bricks".

How it works

Two shapes. Unlock + heap: sort by the unlock condition, push options into a heap as they unlock, and take the heap's best. Regret: take every option as you go, remember them in a heap, and when you break a limit, undo the worst one you took.

📄Templatememorise
// Unlock + heap (LeetCode 502 IPO): do at most k projects, each needs capital <= w and adds profit
static long maxCapital(int k, long w, int[] profit, int[] capital) {
    int n = profit.length;
    Integer[] idx = new Integer[n];
    for (int i = 0; i < n; i++) idx[i] = i;
    Arrays.sort(idx, (x, y) -> Integer.compare(capital[x], capital[y]));   // unlock order
    PriorityQueue<Integer> unlocked = new PriorityQueue<>(Collections.reverseOrder());
    int i = 0;
    while (k-- > 0) {
        while (i < n && capital[idx[i]] <= w) unlocked.add(profit[idx[i++]]);
        if (unlocked.isEmpty()) break;
        w += unlocked.poll();                     // best project we can afford right now
    }
    return w;
}

// Regret greedy (LeetCode 1642): give ladders to the biggest climbs seen so far
static int furthestBuilding(int[] h, int bricks, int ladders) {
    PriorityQueue<Integer> ladderClimbs = new PriorityQueue<>();   // min-heap
    for (int i = 0; i + 1 < h.length; i++) {
        int climb = h[i + 1] - h[i];
        if (climb <= 0) continue;
        ladderClimbs.add(climb);
        if (ladderClimbs.size() > ladders) bricks -= ladderClimbs.poll();  // smallest pays bricks
        if (bricks < 0) return i;
    }
    return h.length - 1;
}

Cost: O(n log n)

Variants

  • RPG monsters (Infosys repeat): sort by power and walk while experience ≥ power. No heap needed because bonuses are non-negative.
  • Course Schedule III: sort by deadline, max-heap of durations, drop the longest when over time.
Traps
  • Check the greedy on small cases against a brute force before trusting it.
  • A max-heap needs Collections.reverseOrder(); the default is a min-heap.

Binary search: lower and upper bound

Plan day 6Plan day 6
Use it when
  • A sorted array: first position ≥ x, last position ≤ x, how many times x appears.
  • Any yes/no question over indices that flips once from no to yes.

How it works

Keep the answer inside [lo, hi). Look at mid: if it already satisfies the condition, the answer is mid or to its left (hi = mid); otherwise it is to the right (lo = mid + 1). The loop ends at lo == hi, the first index that satisfies the condition.

📄Templatememorise
// First index with a[i] >= x (a.length if none). a must be sorted.
static int lowerBound(int[] a, int x) {
    int lo = 0, hi = a.length;              // answer is in [lo, hi]
    while (lo < hi) {
        int mid = (lo + hi) >>> 1;
        if (a[mid] >= x) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}

// First index with a[i] > x. Count of x = upperBound(a, x) - lowerBound(a, x).
static int upperBound(int[] a, int x) {
    int lo = 0, hi = a.length;
    while (lo < hi) {
        int mid = (lo + hi) >>> 1;
        if (a[mid] > x) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}

Cost: O(log n)

Traps
  • Arrays.binarySearch returns any matching index, not the first.
  • (lo + hi) / 2 can overflow for large values; use (lo + hi) >>> 1 or lo + (hi − lo) / 2.

// "Minimise the maximum": smallest capacity that ships all packages, in order, within `days` days
static long minCapacity(int[] weights, int days) {
    long lo = 0, hi = 0;
    for (int w : weights) {
        lo = Math.max(lo, w);                   // must carry the heaviest package
        hi += w;                                // one day for everything always works
    }
    while (lo < hi) {
        long mid = lo + (hi - lo) / 2;
        if (daysNeeded(weights, mid) <= days) hi = mid;   // mid works: try smaller
        else lo = mid + 1;                              // mid fails: need bigger
    }
    return lo;
}

static int daysNeeded(int[] weights, long cap) {         // greedy check, O(n)
    int d = 1;
    long load = 0;
    for (int w : weights) {
        if (load + w > cap) {
            d++;
            load = 0;
        }
        load += w;
    }
    return d;
}

// "Maximise the minimum": largest gap when placing m balls at sorted positions
static int maxMinGap(int[] sortedPos, int m) {
    int lo = 0, hi = sortedPos[sortedPos.length - 1] - sortedPos[0];
    while (lo < hi) {
        int mid = lo + (hi - lo + 1) / 2;       // round UP here, or the loop never ends
        if (canPlace(sortedPos, m, mid)) lo = mid;
        else hi = mid - 1;
    }
    return lo;
}

static boolean canPlace(int[] sortedPos, int m, int gap) {
    int placed = 1, last = sortedPos[0];
    for (int i = 1; i < sortedPos.length; i++) {
        if (sortedPos[i] - last >= gap) {
            placed++;
            last = sortedPos[i];
        }
    }
    return placed >= m;
}

  • Choose lo and hi so the answer is surely inside (here lo = heaviest package, hi = total weight).
  • In "largest x" searches, mid = lo + (hi − lo + 1) / 2, or the loop never ends.
  • Sums inside ok() can overflow; use long.

// Index of the next strictly greater element to the right (-1 if none). O(n).
static int[] nextGreater(int[] a) {
    int n = a.length;
    int[] res = new int[n];
    Arrays.fill(res, -1);
    int[] st = new int[n];          // indices whose answer is still unknown; values decrease
    int top = 0;
    for (int i = 0; i < n; i++) {
        while (top > 0 && a[st[top - 1]] < a[i]) res[st[--top]] = i;   // a[i] answers them
        st[top++] = i;
    }
    return res;
}

// Sum of min(subarray) over all subarrays: a[i] is the minimum of (i - left) * (right - i) of them
static long sumSubarrayMins(int[] a) {
    int n = a.length;
    int[] left = new int[n], right = new int[n];
    ArrayDeque<Integer> st = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {            // left[i]: previous index with a smaller value
        while (!st.isEmpty() && a[st.peek()] >= a[i]) st.pop();
        left[i] = st.isEmpty() ? -1 : st.peek();
        st.push(i);
    }
    st.clear();
    for (int i = n - 1; i >= 0; i--) {       // right[i]: next index with a smaller-or-equal value
        while (!st.isEmpty() && a[st.peek()] > a[i]) st.pop();
        right[i] = st.isEmpty() ? n : st.peek();
        st.push(i);
    }
    long total = 0;
    for (int i = 0; i < n; i++) total += (long) a[i] * (i - left[i]) * (right[i] - i);
    return total;                            // LeetCode 907 wants this mod 1e9+7
}

Cost: O(n)

  • Contribution: a[i] is the minimum of (i − left[i]) × (right[i] − i) subarrays, with left/right = the previous/next smaller element.
  • Remove k digits / smallest subsequence: pop while the top is bigger than the current digit.
Traps
  • Ties: use < on one side and ≤ on the other, or equal values are counted twice.
  • Multiply as long: a[i] × count can exceed int.

How it works

In a sum of XORs every bit is independent: bit b adds 2ᵇ for each pair where exactly one number has it, so count the ones per bit. XOR also cancels itself (x ^ x = 0), which makes prefix XORs work like prefix sums: xor(l..r) = P[r+1] ^ P[l].

// Sum of (a[i] xor a[j]) over all pairs i < j. Bits are independent, so count per bit.
static long sumPairXor(int[] a) {
    long total = 0;
    for (int b = 0; b < 31; b++) {
        long ones = 0;
        for (int x : a) ones += (x >> b) & 1;
        long pairs = ones * (a.length - ones);     // one number has the bit, the other doesn't
        total += pairs << b;
    }
    return total;
}

// Number of subarrays with XOR exactly k: prefix XOR + HashMap (same idea as prefix sums)
static long countSubarraysWithXor(int[] a, int k) {
    Map<Integer, Integer> seen = new HashMap<>();
    seen.put(0, 1);
    int prefix = 0;
    long count = 0;
    for (int x : a) {
        prefix ^= x;
        count += seen.getOrDefault(prefix ^ k, 0); // earlier p with prefix ^ p == k
        seen.merge(prefix, 1, Integer::sum);
    }
    return count;
}

  • Single Number: XOR everything; pairs cancel.

  • Precedence: a & b == 0 means a & (b == 0). Always use brackets.
  • 1 << 31 is negative and 1 << 32 is 1. Use 1L << b.

Binary trie for XOR

Plan day 8Plan day 8
Use it when
  • Maximum XOR of a pair.
  • Count pairs with XOR less than k, or inside a range.
  • Queries "max x ^ y over the y in a set".

How it works

Store each number as a path of bits from the highest bit down. To maximise x ^ y, walk down and take the child with the opposite bit whenever it exists. For "xor < k", walk along k: wherever k has a 1, every number in the child that makes this XOR bit 0 is smaller, so add that child's count, then continue down the other child.

📄Templatememorise
// Binary trie over non-negative ints, highest bit first
static final class XorTrie {
    static final int B = 31;
    final int[][] child;           // child[node][bit], 0 = missing (the root is never a child)
    final int[] cnt;               // how many inserted numbers pass through this node
    int size = 1;

    XorTrie(int maxInserts) {
        child = new int[maxInserts * B + 1][2];
        cnt = new int[child.length];
    }

    void insert(int x) {
        int node = 0;
        for (int b = B - 1; b >= 0; b--) {
            int bit = (x >> b) & 1;
            if (child[node][bit] == 0) child[node][bit] = size++;
            node = child[node][bit];
            cnt[node]++;
        }
    }

    // max of (x ^ y) over inserted y. Trie must not be empty.
    int maxXor(int x) {
        int node = 0, res = 0;
        for (int b = B - 1; b >= 0; b--) {
            int want = ((x >> b) & 1) ^ 1;          // the opposite bit makes this xor bit 1
            if (child[node][want] != 0) {
                res |= 1 << b;
                node = child[node][want];
            } else {
                node = child[node][want ^ 1];
            }
        }
        return res;
    }

    // how many inserted y have (x ^ y) < k
    long countXorLess(int x, int k) {
        long res = 0;
        int node = 0;
        for (int b = B - 1; b >= 0; b--) {
            int xb = (x >> b) & 1, kb = (k >> b) & 1;
            if (kb == 1) {
                if (child[node][xb] != 0) res += cnt[child[node][xb]];   // xor bit 0 < 1: all count
                node = child[node][xb ^ 1];                               // xor bit 1: keep going
            } else {
                node = child[node][xb];                                   // xor bit must be 0
            }
            if (node == 0) break;
        }
        return res;
    }
}

Cost: O(31) per insert or query · up to 31 nodes per number

Traps
  • Size the node arrays as inserts × bits + 1, or you run out of bounds.
  • Pairs with XOR in [lo, hi] = countLess(hi + 1) − countLess(lo).

XOR basis (maximum subset XOR)

How it works

Gaussian elimination with XOR. Keep at most one basis number per highest bit. To add x, cancel its high bits with the basis numbers; whatever is left becomes a new basis number. The maximum is built from the top: take a basis number whenever it makes the result bigger.

📄Templatememorise
// Linear XOR basis: the XOR of any subset can be built from at most 61 basis numbers
static final class XorBasis {
    final long[] b = new long[61];               // b[i] has highest bit i, or is 0

    boolean add(long x) {                        // returns false if x was already reachable
        for (int i = 60; i >= 0; i--) {
            if (((x >> i) & 1) == 0) continue;
            if (b[i] == 0) {
                b[i] = x;
                return true;
            }
            x ^= b[i];
        }
        return false;
    }

    long max() {                                 // maximum XOR of any subset
        long r = 0;
        for (int i = 60; i >= 0; i--) r = Math.max(r, r ^ b[i]);
        return r;
    }
}

Brute force first, then stress test

Plan day 9Plan day 9
Use it when
  • Every exam problem: write the slow but obviously correct version first (5–10 minutes).
  • No fast idea yet: submit the brute force to collect the small test files.
  • Your fast solution is wrong and you can't see why.

How it works

Marks come from test cases, and the small ones usually allow brute force: bitmasks for subsets (n ≤ 20), recursion for orders (n ≤ 10). The stress tester then compares your fast and slow answers on thousands of tiny random inputs and stops at the first input where they differ.

📄Templatememorise
import java.util.*;

/** Compare a fast solve() with an obviously-correct brute() on thousands of tiny random inputs. */
public class Stress {
    public static void main(String[] args) {
        Random rnd = new Random(1);
        for (int iter = 1; iter <= 100000; iter++) {
            int n = 1 + rnd.nextInt(8);                    // tiny inputs expose bugs fastest
            int[] a = new int[n];
            for (int i = 0; i < n; i++) a[i] = rnd.nextInt(21) - 10;
            long fast = solve(a), slow = brute(a);
            if (fast != slow) {
                System.out.println("Mismatch on iteration " + iter + ": " + Arrays.toString(a));
                System.out.println("fast=" + fast + "  brute=" + slow);
                return;                                     // smallest failing case is now on screen
            }
        }
        System.out.println("All random tests passed");
    }

    // Example: maximum subarray sum. Replace both methods with your problem.
    static long solve(int[] a) {                           // Kadane, O(n)
        long best = Long.MIN_VALUE, cur = 0;
        for (int x : a) { cur = Math.max(x, cur + x); best = Math.max(best, cur); }
        return best;
    }

    static long brute(int[] a) {                           // every subarray, O(n^2)
        long best = Long.MIN_VALUE;
        for (int l = 0; l < a.length; l++) {
            long s = 0;
            for (int r = l; r < a.length; r++) { s += a[r]; best = Math.max(best, s); }
        }
        return best;
    }
}

Traps
  • Keep random inputs tiny (n ≤ 8, values ≤ 10); small failing cases are easy to check by hand.
  • Compare with the brute force, not with what you expect the answer to be.

Number theory

gcd, fast power, inverse, nCr

Plan day 10Plan day 10
Use it when
  • "Answer modulo 10⁹+7", counting ways, combinations.
  • gcd or lcm of arrays, "gcd exactly p".

How it works

Take the modulus after every multiplication so numbers stay below 10⁹+7 and the product of two still fits in a long. Fast power squares the base and halves the exponent: O(log e). When the modulus is prime, a⁻¹ = a^(MOD−2). With factorials and inverse factorials precomputed, nCr is three multiplications.

📄Templatememorise
static final long MOD = 1_000_000_007L;

static long gcd(long a, long b) {
    while (b != 0) {
        long t = a % b;
        a = b;
        b = t;
    }
    return Math.abs(a);
}

static long lcm(long a, long b) {
    return a / gcd(a, b) * b;                    // divide first so it doesn't overflow
}

static long power(long base, long exp, long m) {  // base^exp mod m in O(log exp)
    long r = 1 % m;
    base %= m;
    if (base < 0) base += m;
    while (exp > 0) {
        if ((exp & 1) == 1) r = r * base % m;
        base = base * base % m;
        exp >>= 1;
    }
    return r;
}

static long inverse(long a) {                    // only when MOD is prime (Fermat)
    return power(a, MOD - 2, MOD);
}

static long[] fact, invFact;

static void initFactorials(int n) {
    fact = new long[n + 1];
    invFact = new long[n + 1];
    fact[0] = 1;
    for (int i = 1; i <= n; i++) fact[i] = fact[i - 1] * i % MOD;
    invFact[n] = inverse(fact[n]);
    for (int i = n; i > 0; i--) invFact[i - 1] = invFact[i] * i % MOD;
}

static long nCr(int n, int r) {
    if (r < 0 || r > n) return 0;
    return fact[n] * invFact[r] % MOD * invFact[n - r] % MOD;
}

Sieve, prime factors, square-free kernel

Plan day 10Plan day 10

How it works

The smallest-prime-factor sieve stores spf[x] for every x. To factorise x, repeat p = spf[x], x /= p: O(log x) per number. A product is a perfect square exactly when every prime appears an even number of times, so x · y is a square ⇔ kernel(x) == kernel(y), where the kernel keeps only the primes with an odd exponent.

12 = 2^2 * 3    -> kernel 3
27 = 3^3        -> kernel 3     12 * 27 = 324 = 18^2   (same kernel: square)
18 = 2 * 3^2    -> kernel 2     12 * 18 = 216          (different: not a square)

// spf[x] = smallest prime factor of x, for every x <= n. x is prime when spf[x] == x.
static int[] smallestPrimeFactors(int n) {
    int[] spf = new int[n + 1];
    for (int i = 2; i <= n; i++) {
        if (spf[i] != 0) continue;
        for (int j = i; j <= n; j += i) if (spf[j] == 0) spf[j] = i;
    }
    return spf;
}

// Square-free kernel: product of the primes with an odd exponent.
// x * y is a perfect square  <=>  kernel(x) == kernel(y)
static int kernel(int x, int[] spf) {
    int k = 1;
    while (x > 1) {
        int p = spf[x], odd = 0;
        while (x % p == 0) {
            x /= p;
            odd ^= 1;
        }
        if (odd == 1) k *= p;
    }
    return k;
}

// All divisors of x in increasing order, O(sqrt x)
static List<Long> divisors(long x) {
    List<Long> small = new ArrayList<>(), big = new ArrayList<>();
    for (long d = 1; d * d <= x; d++) {
        if (x % d != 0) continue;
        small.add(d);
        if (d != x / d) big.add(x / d);
    }
    Collections.reverse(big);
    small.addAll(big);
    return small;
}

Cost: sieve O(n log log n) · factorise O(log x)

  • Divisors of one number: loop d up to √x.

// House Robber. Write these four lines BEFORE any code:
// 1. State:      best[i] = most money from houses 0..i-1
// 2. Transition: best[i] = max(best[i-1], best[i-2] + a[i-1])   (skip house i-1, or rob it)

static long robBottomUp(int[] a) {
    int n = a.length;
    long[] best = new long[n + 1];
    if (n > 0) best[1] = a[0];
    for (int i = 2; i <= n; i++) best[i] = Math.max(best[i - 1], best[i - 2] + a[i - 1]);
    return best[n];
}

static long rob(int[] a, int i) {
    if (i == 0) return 0;
    if (i == 1) return a[0];

}

Knapsack family

Plan day 11Plan day 11
Use it when

How it works

dp[c] = best result with capacity c. Each item updates dp from dp[c − w]. The loop direction decides whether an item can be reused. Going DOWN, dp[c − w] still holds the old value (item not used yet), so each item is used at most once. Going UP, dp[c − w] may already include the item, so it can repeat.

one item: w = 2, v = 3; capacity 4; dp starts all 0
downwards (0/1):     c=4: dp[2]+3 = 3   c=3: 3   c=2: 3    -> dp[4] = 3  (used once)
upwards (unbounded): c=2: 3   c=3: 3   c=4: dp[2]+3 = 6    -> dp[4] = 6  (used twice)

// 0/1 knapsack: each item at most once -> loop capacity DOWNWARDS
static long knapsack01(int[] w, int[] v, int cap) {
    long[] dp = new long[cap + 1];                // dp[c] = best value with weight <= c
    for (int i = 0; i < w.length; i++)
        for (int c = cap; c >= w[i]; c--) dp[c] = Math.max(dp[c], dp[c - w[i]] + v[i]);
    return dp[cap];
}

// Unbounded: each item any number of times -> loop capacity UPWARDS
static long knapsackUnbounded(int[] w, int[] v, int cap) {
    long[] dp = new long[cap + 1];
    for (int i = 0; i < w.length; i++)
        for (int c = w[i]; c <= cap; c++) dp[c] = Math.max(dp[c], dp[c - w[i]] + v[i]);
    return dp[cap];
}

// Fewest coins to make amount (-1 if impossible)
static int minCoins(int[] coins, int amount) {
    int INF = Integer.MAX_VALUE / 2;
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, INF);
    dp[0] = 0;
    for (int a = 1; a <= amount; a++)
        for (int c : coins) if (c <= a) dp[a] = Math.min(dp[a], dp[a - c] + 1);
    return dp[amount] >= INF ? -1 : dp[amount];
}

// Number of coin combinations (order doesn't matter): coins in the OUTER loop
static long countCombinations(int[] coins, int amount) {
    long[] ways = new long[amount + 1];
    ways[0] = 1;
    for (int c : coins)
        for (int a = c; a <= amount; a++) ways[a] += ways[a - c];
    return ways[amount];
}

// Can some subset sum to target?
static boolean subsetSum(int[] a, int target) {
    boolean[] can = new boolean[target + 1];
    can[0] = true;
    for (int x : a)
        for (int s = target; s >= x; s--) if (can[s - x]) can[s] = true;
    return can[target];
}

// dp[i][j] = answer for the first i chars of s and the first j chars of t
static int lcs(String s, String t) {
    int n = s.length(), m = t.length();
    int[][] dp = new int[n + 1][m + 1];
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            dp[i][j] = s.charAt(i - 1) == t.charAt(j - 1)
                    ? dp[i - 1][j - 1] + 1
                    : Math.max(dp[i - 1][j], dp[i][j - 1]);
    return dp[n][m];
}

static int editDistance(String s, String t) {
    int n = s.length(), m = t.length();
    int[][] dp = new int[n + 1][m + 1];
    for (int i = 0; i <= n; i++) dp[i][0] = i;              // delete everything
    for (int j = 0; j <= m; j++) dp[0][j] = j;              // insert everything
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++) {
            if (s.charAt(i - 1) == t.charAt(j - 1)) dp[i][j] = dp[i - 1][j - 1];
            else dp[i][j] = 1 + Math.min(dp[i - 1][j - 1],      // replace
                    Math.min(dp[i - 1][j], dp[i][j - 1]));    // delete, insert
        }
    return dp[n][m];
}

Cost: O(n · m) time; keep two rows if memory is tight

Variants

  • Longest palindromic subsequence = LCS(s, reverse(s)); fewest insertions to make a palindrome = n − that.
  • Print the LCS: walk back from dp[n][m].
Traps
  • Off by one: dp index i refers to character i − 1.

How it works

// Length of the longest strictly increasing subsequence, O(n log n).
// tails[len-1] = smallest possible last value of an increasing subsequence of length len.
static int lisStrict(int[] a) {
    int[] tails = new int[a.length];
    int len = 0;
    for (int x : a) {
        int lo = 0, hi = len;
        while (lo < hi) {                      // first tail >= x  (use > x for non-decreasing)
            int mid = (lo + hi) >>> 1;
            if (tails[mid] >= x) hi = mid;
            else lo = mid + 1;
        }
        tails[lo] = x;
        if (lo == len) len++;
    }
    return len;
}

// Same answer as dp over values: dp(x) = 1 + max dp over values < x.
// A Fenwick tree of maximums gives that max in O(log V). Values must be 1..V (compress first).
// Extra conditions (e.g. "XOR >= M") become an extra dimension: one Fenwick per state.
static int lisWithFenwick(int[] a, int V) {
    int[] fw = new int[V + 1];
    int best = 0;
    for (int x : a) {
        int cur = 1 + prefixMax(fw, x - 1);    // x - 1 for strict, x for non-decreasing
        raise(fw, x, cur);
        best = Math.max(best, cur);
    }
    return best;
}

static int prefixMax(int[] fw, int i) {
    int r = 0;
    for (; i > 0; i -= i & -i) r = Math.max(r, fw[i]);
    return r;
}

static void raise(int[] fw, int i, int v) {    // values only ever go up
    for (; i < fw.length; i += i & -i) fw[i] = Math.max(fw[i], v);
}

Cost: O(n log n)

Variants

  • Non-decreasing: replace the first tail > x (upper bound).
  • Mountain (LC 1671): LIS ending at i from the left, plus from the right, minus 1.
Traps
  • tails is not a real subsequence; only its length means something.
  • The Fenwick version needs values 1..V: compress large values first.

How it works

dp[l][r] = best answer for the segment l..r. Fill by increasing length so smaller segments are ready, and try every split point k. For games, store "my score minus the opponent's" for the player to move: taking a[l] leaves the opponent dp[l+1][r].

📄Templatememorise
// dp[l][r] = best answer for the segment l..r, filled by increasing length.
// Matrix chain: matrix i is d[i] x d[i+1]. Cheapest order of multiplications.
static long matrixChain(int[] d) {
    int n = d.length - 1;
    long[][] dp = new long[n][n];                      // dp[l][l] = 0
    for (int len = 2; len <= n; len++)
        for (int l = 0; l + len - 1 < n; l++) {
            int r = l + len - 1;
            dp[l][r] = Long.MAX_VALUE;
            for (int k = l; k < r; k++)                // last multiplication splits at k
                dp[l][r] = Math.min(dp[l][r], dp[l][k] + dp[k + 1][r] + (long) d[l] * d[k + 1] * d[r + 1]);
        }
    return dp[0][n - 1];
}

// Two players take from either end; both play perfectly. dp = my score minus the opponent's.
static long bestScoreDifference(int[] a) {
    int n = a.length;
    long[][] dp = new long[n][n];
    for (int i = 0; i < n; i++) dp[i][i] = a[i];
    for (int len = 2; len <= n; len++)
        for (int l = 0; l + len - 1 < n; l++) {
            int r = l + len - 1;
            dp[l][r] = Math.max(a[l] - dp[l + 1][r], a[r] - dp[l][r - 1]);
        }
    return dp[0][n - 1];                               // first player wins if >= 0 (LC 486)
}

  • Loop by length, not "l then r", or you read states that aren't filled yet.

// Fewest edges from src to every node (-1 = unreachable)
static int[] bfs(List<Integer>[] g, int src) {
    int[] dist = new int[g.length];
    Arrays.fill(dist, -1);
    ArrayDeque<Integer> q = new ArrayDeque<>();
    dist[src] = 0;
    q.add(src);
    while (!q.isEmpty()) {
        int u = q.poll();
        for (int v : g[u]) {
            if (dist[v] != -1) continue;       // mark when you PUSH, not when you pop
            dist[v] = dist[u] + 1;
            q.add(v);
        }
    }
    return dist;
}

static final int[] DR = {1, -1, 0, 0}, DC = {0, 0, 1, -1};

// Grid BFS from several sources at once ('#' = wall): steps to the nearest source, -1 if none
static int[][] gridBfs(char[][] grid, int[][] sources) {
    int rows = grid.length, cols = grid[0].length;
    int[][] dist = new int[rows][cols];
    for (int[] row : dist) Arrays.fill(row, -1);
    ArrayDeque<int[]> q = new ArrayDeque<>();
    for (int[] s : sources) {
        dist[s[0]][s[1]] = 0;
        q.add(s);
    }
    while (!q.isEmpty()) {
        int[] cur = q.poll();
        for (int d = 0; d < 4; d++) {
            int r = cur[0] + DR[d], c = cur[1] + DC[d];
            if (r < 0 || r >= rows || c < 0 || c >= cols) continue;
            if (grid[r][c] == '#' || dist[r][c] != -1) continue;
            dist[r][c] = dist[cur[0]][cur[1]] + 1;
            q.add(new int[]{r, c});
        }
    }
    return dist;
}

// Iterative DFS (no stack overflow): comp[v] = component number. Returns how many components.
static int components(List<Integer>[] g, int[] comp) {
    Arrays.fill(comp, -1);
    int count = 0;
    ArrayDeque<Integer> stack = new ArrayDeque<>();
    for (int s = 0; s < g.length; s++) {
        if (comp[s] != -1) continue;
        comp[s] = count;
        stack.push(s);
        while (!stack.isEmpty()) {
            int u = stack.pop();
            for (int v : g[u]) {
                if (comp[v] != -1) continue;
                comp[v] = count;
                stack.push(v);
            }
        }
        count++;
    }
    return count;
}

How it works

Count incoming edges. Every node with indegree 0 can go first; removing it may free its neighbours. If some nodes never reach indegree 0, they sit on a cycle. In this order every predecessor is finished before a node, so DP over the order works.

📄Templatememorise
// Kahn's algorithm on a directed graph. Returns a topological order, or null if there is a cycle.
static int[] topoOrder(List<Integer>[] g) {
    int n = g.length;
    int[] indeg = new int[n];
    for (int u = 0; u < n; u++) for (int v : g[u]) indeg[v]++;
    int[] order = new int[n];
    int head = 0, tail = 0;
    for (int u = 0; u < n; u++) if (indeg[u] == 0) order[tail++] = u;
    while (head < tail) {
        int u = order[head++];
        for (int v : g[u]) if (--indeg[v] == 0) order[tail++] = v;
    }
    return tail == n ? order : null;          // some node never reached indegree 0 -> cycle
}

// DP on a DAG in topological order: longest path (in edges) ending at each node
static int[] longestPathEndingAt(List<Integer>[] g, int[] order) {
    int[] best = new int[g.length];
    for (int u : order) for (int v : g[u]) best[v] = Math.max(best[v], best[u] + 1);
    return best;
}

0-1 BFS

Use it when

How it works

Dijkstra with a deque instead of a heap. A 0-cost edge keeps the distance the same, so the node goes to the front; a 1-cost edge goes to the back. The deque stays sorted by distance.

📄Templatememorise
// Weights are only 0 or 1: a deque replaces the heap. Weight 0 -> front, weight 1 -> back.
static int[] zeroOneBfs(List<int[]>[] g, int src) {
    int[] d = new int[g.length];
    Arrays.fill(d, Integer.MAX_VALUE);
    d[src] = 0;
    ArrayDeque<Integer> dq = new ArrayDeque<>();
    dq.add(src);
    while (!dq.isEmpty()) {
        int u = dq.pollFirst();
        for (int[] e : g[u]) {
            int v = e[0], nd = d[u] + e[1];
            if (nd >= d[v]) continue;
            d[v] = nd;
            if (e[1] == 0) dq.addFirst(v);
            else dq.addLast(v);
        }
    }
    return d;
}

Cost: O(V + E)

Traps

Dijkstra

Plan day 17Plan day 17
Use it when
  • Shortest path with non-negative weights.
  • "Minimum effort / time / cost path", network delay.

How it works

Always expand the closest unfinished node, taken from a min-heap. When a node comes out of the heap carrying its current distance, that distance is final. Older heap entries with a larger distance are skipped.

📄Templatememorise
// Non-negative weights. g[u] holds {to, weight}. Returns Long.MAX_VALUE for unreachable nodes.
static long[] dijkstra(List<int[]>[] g, int src) {
    long[] d = new long[g.length];
    Arrays.fill(d, Long.MAX_VALUE);
    d[src] = 0;
    PriorityQueue<long[]> pq = new PriorityQueue<>((x, y) -> Long.compare(x[0], y[0]));
    pq.add(new long[]{0, src});
    while (!pq.isEmpty()) {
        long[] cur = pq.poll();
        int u = (int) cur[1];
        if (cur[0] != d[u]) continue;           // stale entry: u was already finalised
        for (int[] e : g[u]) {
            long nd = d[u] + e[1];
            if (nd < d[e[0]]) {
                d[e[0]] = nd;
                pq.add(new long[]{nd, e[0]});
            }
        }
    }
    return d;
}

  • Distances can exceed int: use long.

Union-find (DSU) and Kruskal

Plan day 17Plan day 17
Use it when
  • Groups that merge: "connected?", "how many components?", edges added over time.
  • Minimum spanning tree: connect all cities at minimum cost.

How it works

Each group has a root. find walks up to the root and shortens the path on the way; union hangs the smaller tree under the larger root. Kruskal sorts edges by weight and keeps an edge whenever it joins two different groups.

📄Templatememorise
static final class DSU {
    final int[] parent, size;

    DSU(int n) {
        parent = new int[n];
        size = new int[n];
        for (int i = 0; i < n; i++) {
            parent[i] = i;
            size[i] = 1;
        }
    }

    int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];          // path halving: keeps trees flat
            x = parent[x];
        }
        return x;
    }

    boolean union(int a, int b) {                    // false if already connected
        a = find(a);
        b = find(b);
        if (a == b) return false;
        if (size[a] < size[b]) {
            int t = a;
            a = b;
            b = t;
        }
        parent[b] = a;                               // attach the smaller tree
        size[a] += size[b];
        return true;
    }
}

// Kruskal: minimum spanning tree weight, -1 if the graph is not connected. edges = {u, v, w}
static long mst(int n, int[][] edges) {
    Arrays.sort(edges, (x, y) -> Integer.compare(x[2], y[2]));
    DSU dsu = new DSU(n);
    long total = 0;
    int used = 0;
    for (int[] e : edges) {
        if (dsu.union(e[0], e[1])) {
            total += e[2];
            used++;
        }
    }
    return used == n - 1 ? total : -1;
}

// Diameter (LeetCode 543): longest path in edges between any two nodes.
static int diameter(TreeNode root) {

    return best[0];
}

static int height(TreeNode node, int[] best) {     // nodes on the longest downward path
    if (node == null) return 0;
    int l = height(node.left, best), r = height(node.right, best);
    best[0] = Math.max(best[0], l + r);              // the path that bends at this node

// Maximum path sum (LeetCode 124): same shape, negative branches are dropped
static int maxPathSum(TreeNode root) {
    int[] best = {Integer.MIN_VALUE};
    gain(root, best);
    return best[0];
}

static int gain(TreeNode node, int[] best) {
    if (node == null) return 0;
    int l = Math.max(0, gain(node.left, best)), r = Math.max(0, gain(node.right, best));
    best[0] = Math.max(best[0], node.val + l + r);
    return node.val + Math.max(l, r);                 // a parent can use only one branch
}

// Lowest common ancestor (LeetCode 236)
static TreeNode lca(TreeNode root, TreeNode p, TreeNode q) {
    if (root == null || root == p || root == q) return root;
    TreeNode l = lca(root.left, p, q), r = lca(root.right, p, q);
    if (l != null && r != null) return root;          // p and q are on different sides
    return l != null ? l : r;
}

// Level-order traversal (LeetCode 102): BFS, one level per outer loop
static List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> levels = new ArrayList<>();
    if (root == null) return levels;
    ArrayDeque<TreeNode> q = new ArrayDeque<>();
    q.add(root);
    while (!q.isEmpty()) {
        List<Integer> level = new ArrayList<>();
        for (int k = q.size(); k > 0; k--) {          // exactly the nodes of this level
            TreeNode node = q.poll();
            level.add(node.val);
            if (node.left != null) q.add(node.left);
            if (node.right != null) q.add(node.right);
        }
        levels.add(level);
    }
    return levels;
}

  • A parent can use only one branch of a child's path; the bend counts only at the top node.

// General tree: nodes 0..n-1, par[root] = -1 (LeetCode style).
// Infosys input is often 1-indexed with par[root] = 0: subtract 1 from every value first.
@SuppressWarnings("unchecked")
static List<Integer>[] childrenOf(int[] par) {
    List<Integer>[] kids = new List[par.length];
    for (int v = 0; v < par.length; v++) kids[v] = new ArrayList<>();
    for (int v = 0; v < par.length; v++) if (par[v] != -1) kids[par[v]].add(v);
    return kids;
}

// BFS order: every parent comes before its children. No recursion, so no stack overflow.
static int[] bfsOrder(int[] par) {
    List<Integer>[] kids = childrenOf(par);
    int n = par.length;
    int[] order = new int[n];
    int head = 0, tail = 0;
    for (int v = 0; v < n; v++) if (par[v] == -1) order[tail++] = v;   // the root
    while (head < tail) {
        int u = order[head++];
        for (int c : kids[u]) order[tail++] = c;
    }
    return order;
}

// "Post-order" without recursion: walk the BFS order BACKWARDS (children before parents)
static int[] subtreeSizes(int[] par) {
    int[] order = bfsOrder(par), size = new int[par.length];
    Arrays.fill(size, 1);
    for (int i = order.length - 1; i > 0; i--) {         // order[0] is the root
        int v = order[i];
        size[par[v]] += size[v];
    }
    return size;
}

// Edge list (LeetCode style) -> parent array rooted at `root`

            par[v] = u;
            q.add(v);
        }
    }
    return par;
}

LCA with binary lifting

Plan day 18Plan day 18
Use it when
  • Distance between two nodes, k-th ancestor, path questions on a fixed tree.
  • Many queries (10⁵) on a big tree (10⁵ nodes).

How it works

up[k][v] is the 2ᵏ-th ancestor of v, and up[k][v] = up[k−1][up[k−1][v]]. To lift v by d levels, follow the binary digits of d. For the LCA, first lift the deeper node to the same depth, then lift both together by the largest jumps that keep them apart; their parent is the LCA.

📄Templatememorise
// Binary lifting: up[k][v] = the 2^k-th ancestor of v. O(n log n) build, O(log n) per query.
static final class LCA {
    final int LOG;
    final int[][] up;
    final int[] depth;

    LCA(int[] par) {                                     // par[root] = -1
        int n = par.length, lg = 1;
        while ((1 << lg) < n) lg++;
        LOG = lg;
        up = new int[LOG][n];
        depth = new int[n];
        for (int v : bfsOrder(par)) {                    // parents are filled in first
            up[0][v] = par[v] == -1 ? v : par[v];        // the root points to itself
            depth[v] = par[v] == -1 ? 0 : depth[par[v]] + 1;
            for (int k = 1; k < LOG; k++) up[k][v] = up[k - 1][up[k - 1][v]];
        }
    }

    int kthAncestor(int v, int k) {                      // -1 if v has fewer than k ancestors
        if (k > depth[v]) return -1;
        for (int b = 0; b < LOG; b++) if (((k >> b) & 1) == 1) v = up[b][v];
        return v;
    }

    int lca(int a, int b) {
        if (depth[a] < depth[b]) {
            int t = a;
            a = b;
            b = t;
        }
        a = kthAncestor(a, depth[a] - depth[b]);          // same depth first
        if (a == b) return a;
        for (int k = LOG - 1; k >= 0; k--) {
            if (up[k][a] != up[k][b]) {                  // jump while still below the LCA
                a = up[k][a];
                b = up[k][b];
            }
        }
        return up[0][a];
    }

    int dist(int a, int b) {
        return depth[a] + depth[b] - 2 * depth[lca(a, b)];
    }
}

Cost: O(n log n) to build, O(log n) per query

Traps
  • Build in BFS order so the parent's rows are ready.
  • dist(a, b) = depth[a] + depth[b] − 2 · depth[lca(a, b)].

// dp[v][state] built from the children. Example: maximum-weight set of nodes, no two adjacent.
// take[v] = best in v's subtree with v chosen, skip[v] = best with v not chosen.
static long maxIndependentSet(int[] par, int[] w) {
    int n = par.length;
    int[] order = bfsOrder(par);
    long[] take = new long[n], skip = new long[n];
    for (int i = n - 1; i >= 0; i--) {                   // children are finished first

        take[v] += w[v];
        int p = par[v];
        if (p == -1) continue;
        take[p] += skip[v];                              // parent chosen -> child must be skipped
        skip[p] += Math.max(take[v], skip[v]);           // parent skipped -> child is free
    }
    int root = order[0];
    return Math.max(take[root], skip[root]);
}

// Answer for EVERY root in O(n). Sum of distances from each node to all others (LeetCode 834).
static long[] sumOfDistances(int n, int[][] edges) {
    int[] par = parentsFromEdges(n, edges, 0);
    int[] order = bfsOrder(par);
    int[] size = new int[n];
    long[] down = new long[n];                           // down[v] = sum of distances inside v's subtree
    Arrays.fill(size, 1);
    for (int i = n - 1; i > 0; i--) {                    // pass 1: children before parents
        int v = order[i], p = par[v];
        size[p] += size[v];
        down[p] += down[v] + size[v];                    // every node below v is 1 step further from p
    }
    long[] ans = new long[n];
    ans[order[0]] = down[order[0]];
    for (int i = 1; i < n; i++) {                        // pass 2: parents before children
        int v = order[i];
        ans[v] = ans[par[v]] - size[v] + (n - size[v]);  // size[v] nodes get closer, the rest further
    }
    return ans;
}

  • Pass 1 walks the BFS order backwards; pass 2 walks it forwards.

    @SuppressWarnings("unchecked")
    HashSet<Integer>[] set = new HashSet[n];
    for (int i = n - 1; i >= 0; i--) {                   // children are merged in before v is used
        int v = order[i];
        if (set[v] == null) set[v] = new HashSet<>();
        set[v].add(color[v]);
        ans[v] = set[v].size();
        int p = par[v];
        if (p == -1) continue;
        if (set[p] == null) {
            set[p] = set[v];                             // first child: just hand the set over

            if (big.size() < small.size()) {
                HashSet<Integer> t = big;
                big = small;
                small = t;
            }
            big.addAll(small);
            set[p] = big;
        }
        set[v] = null;
    }
    return ans;
}

// Iterative DFS that numbers nodes in visit order. Subtree of v = positions tin[v]..tout[v],
// so "subtree sum" becomes "range sum" (Fenwick / segment tree on the tin order).
static int[][] eulerTour(int[] par) {
    List<Integer>[] kids = childrenOf(par);
    int n = par.length, timer = 0, top = 0, root = 0;
    for (int v = 0; v < n; v++) if (par[v] == -1) root = v;
    int[] tin = new int[n], tout = new int[n], next = new int[n], stack = new int[n];
    stack[top++] = root;
    tin[root] = timer++;
    while (top > 0) {
        int v = stack[top - 1];
        if (next[v] < kids[v].size()) {                  // visit the next child
            int c = kids[v].get(next[v]++);
            tin[c] = timer++;
            stack[top++] = c;
        } else {                                         // all children done
            tout[v] = timer - 1;
            top--;
        }
    }
    return new int[][]{tin, tout};
}

    Fenwick(int n) { t = new long[n + 1]; }

Segment tree (iterative)

Plan day 20Plan day 20
Use it when

  • Updates and queries mixed (the sample-paper Medium: gcd under updates).

How it works

Leaves sit at positions n..2n−1, and node i combines its children 2i and 2i + 1. A query climbs from both ends of the range towards the root, adding each node that lies fully inside. Changing op and ID changes the operation.

n = 4, a = [5, 2, 7, 1], op = sum
t[4..7] = 5 2 7 1      (the leaves)
t[2] = 5 + 2 = 7,  t[3] = 7 + 1 = 8,  t[1] = 15
📄Templatememorise
// Iterative segment tree: point set, range query [l, r). Change ID and op for sum / min / max / gcd.
static final class SegTree {
    static final long ID = 0;                            // sum: 0, max: Long.MIN_VALUE, min: Long.MAX_VALUE, gcd: 0

    static long op(long a, long b) { return a + b; }     // or Math.max, Math.min, gcd

    final int n;
    final long[] t;

    SegTree(long[] a) {
        n = a.length;
        t = new long[2 * n];
        for (int i = 0; i < n; i++) t[n + i] = a[i];     // leaves live at n..2n-1
        for (int i = n - 1; i > 0; i--) t[i] = op(t[2 * i], t[2 * i + 1]);
    }

    void set(int i, long v) {
        for (t[i += n] = v; i > 1; i >>= 1) t[i >> 1] = op(t[i], t[i ^ 1]);
    }

    long query(int l, int r) {                           // op over a[l..r-1]
        long resL = ID, resR = ID;
        for (l += n, r += n; l < r; l >>= 1, r >>= 1) {
            if ((l & 1) == 1) resL = op(resL, t[l++]);
            if ((r & 1) == 1) resR = op(t[--r], resR);
        }
        return op(resL, resR);
    }
}

Cost: O(log n) per update and query · 2n longs

Variants

  • gcd: ID = 0, because gcd(0, x) = x. min: ID = Long.MAX_VALUE.
  • Finding the first index that meets a condition needs the recursive version (descend from the root).
Traps

Range data structures

Lazy segment tree (range add, range max)

Plan day 21Plan day 21
Use it when
  • Range updates AND range queries.
  • DP where moving i changes a whole range of earlier states (The Bakery).

How it works

When an update covers a node's whole range, apply it to that node and leave a note (lazy) instead of visiting its children. Before you visit the children later, push the note down to them.

📄Templatememorise
// Lazy segment tree: add v to every a[l..r], ask max of a[l..r] (both inclusive), O(log n)
static final class LazyMax {
    final int n;
    final long[] mx, lz;

    LazyMax(int n) {
        this.n = n;
        mx = new long[4 * n];
        lz = new long[4 * n];
    }

    private void push(int x) {                           // hand the pending add to both children
        if (lz[x] == 0) return;
        for (int c = 2 * x; c <= 2 * x + 1; c++) {
            mx[c] += lz[x];
            lz[c] += lz[x];
        }
        lz[x] = 0;
    }

    void add(int l, int r, long v) { add(1, 0, n - 1, l, r, v); }

    private void add(int x, int lo, int hi, int l, int r, long v) {
        if (r < lo || hi < l) return;
        if (l <= lo && hi <= r) {                        // fully covered: stop here, remember the add
            mx[x] += v;
            lz[x] += v;
            return;
        }
        push(x);
        int mid = (lo + hi) >>> 1;
        add(2 * x, lo, mid, l, r, v);
        add(2 * x + 1, mid + 1, hi, l, r, v);
        mx[x] = Math.max(mx[2 * x], mx[2 * x + 1]);
    }

    long max(int l, int r) { return max(1, 0, n - 1, l, r); }

    private long max(int x, int lo, int hi, int l, int r) {
        if (r < lo || hi < l) return Long.MIN_VALUE;
        if (l <= lo && hi <= r) return mx[x];
        push(x);
        int mid = (lo + hi) >>> 1;
        return Math.max(max(2 * x, lo, mid, l, r), max(2 * x + 1, mid + 1, hi, l, r));
    }
}

Cost: O(log n) per operation · 8n longs

Traps
  • Push before going into the children, in both add and max.
  • Arrays need size 4n, not 2n.

Dynamic programming

Split into K parts (dp[k][i])

Plan day 21Plan day 21
Use it when
  • "Split the array into exactly K contiguous groups / days / boxes", with a cost per group.
  • Infosys repeats: gift boxes (CF 833B) and k segments with minimum cost (CF 1527E).

How it works

dp[k][i] = best answer for the first i elements in k parts. The last part is a[j..i−1], so dp[k][i] = best over j of dp[k−1][j] + cost(j, i−1). That is O(K · n²) and passes the small tests. When moving i changes the cost by a range add over j (distinct counts do), keep dp[k−1][j] + cost in a lazy segment tree and read each dp[k][i] with one range max.

📄Templatememorise
// Split a into exactly K non-empty contiguous parts, minimise the sum of max(part).
// dp[k][i] = best for the first i elements in k parts. O(K * n^2). (LeetCode 1335)
static long splitMinSumOfMax(int[] a, int K) {
    int n = a.length;
    long INF = Long.MAX_VALUE / 4;
    long[][] dp = new long[K + 1][n + 1];
    for (long[] row : dp) Arrays.fill(row, INF);
    dp[0][0] = 0;
    for (int k = 1; k <= K; k++)
        for (int i = k; i <= n; i++) {
            int mx = 0;
            for (int j = i - 1; j >= k - 1; j--) {     // the last part is a[j..i-1]
                mx = Math.max(mx, a[j]);
                if (dp[k - 1][j] < INF) dp[k][i] = Math.min(dp[k][i], dp[k - 1][j] + mx);
            }
        }
    return dp[K][n];                                     // INF if K > n
}

// Faster version for "sum of distinct counts" (Codeforces 833B, the Infosys "gift boxes"):
// tree[j] = dp[k-1][j] + distinct(a[j..i-1]). Moving i adds 1 on a RANGE of j: lazy segment tree.
static long maxDistinctSum(int[] a, int K) {             // values 0..maxV, O(K * n log n)
    int n = a.length, maxV = 0;
    for (int x : a) maxV = Math.max(maxV, x);
    final long NEG = Long.MIN_VALUE / 4;
    long[] prev = new long[n + 1];                       // prev[j] = dp[k-1][j]
    Arrays.fill(prev, NEG);
    prev[0] = 0;
    for (int k = 1; k <= K; k++) {
        LazyMax tree = new LazyMax(n + 1);
        for (int j = 0; j <= n; j++) tree.add(j, j, prev[j]);
        int[] last = new int[maxV + 1];
        Arrays.fill(last, -1);
        long[] cur = new long[n + 1];
        cur[0] = NEG;
        for (int i = 1; i <= n; i++) {
            int x = a[i - 1];
            tree.add(last[x] + 1, i - 1, 1);             // x is new for parts starting after its last copy
            last[x] = i - 1;
            cur[i] = tree.max(0, i - 1);
        }
        prev = cur;
    }
    return prev[n];
}

Cost: simple: O(K · n²) · with the lazy segment tree: O(K · n log n)

Traps
  • Unreachable states (fewer elements than parts) must stay at ±INF.
  • Loop j downwards so the cost of a[j..i−1] can be built step by step.

Brute force

Backtracking and subset enumeration

Plan day 22Plan day 22
Use it when
  • Generate all subsets, permutations or combinations; n ≤ 10–20.
  • Partial marks on a hard problem: enumerate everything for the small tests.

How it works

Choose, recurse, un-choose. The recursion tries every option, and undoing the choice restores the state for the next option. For subsets, a bitmask loop from 0 to 2ⁿ − 1 does the same without recursion.

📄Templatememorise
// All subsets with a bitmask (n <= 20): the brute force behind most partial-credit answers
static List<List<Integer>> subsets(int[] a) {
    List<List<Integer>> out = new ArrayList<>();
    int n = a.length;
    for (int mask = 0; mask < (1 << n); mask++) {
        List<Integer> s = new ArrayList<>();
        for (int i = 0; i < n; i++) if ((mask & (1 << i)) != 0) s.add(a[i]);
        out.add(s);
    }
    return out;
}

// Backtracking = choose, recurse, un-choose. All permutations (n <= 10).
static void permutations(int[] a, boolean[] used, List<Integer> cur, List<List<Integer>> out) {
    if (cur.size() == a.length) {
        out.add(new ArrayList<>(cur));                   // copy: cur keeps changing
        return;
    }
    for (int i = 0; i < a.length; i++) {
        if (used[i]) continue;
        used[i] = true;
        cur.add(a[i]);                                   // choose
        permutations(a, used, cur, out);                 // recurse
        cur.remove(cur.size() - 1);                      // un-choose
        used[i] = false;
    }
}

// Combination Sum (LeetCode 39): candidates may repeat; start index avoids duplicate orders
static void combinationSum(int[] c, int start, int remain, List<Integer> cur, List<List<Integer>> out) {
    if (remain == 0) {
        out.add(new ArrayList<>(cur));
        return;
    }
    for (int i = start; i < c.length; i++) {
        if (c[i] > remain) continue;
        cur.add(c[i]);
        combinationSum(c, i, remain - c[i], cur, out);   // i, not i + 1: c[i] can be used again
        cur.remove(cur.size() - 1);
    }
}

Cost: 2ⁿ subsets, n! permutations

Traps
  • Add a copy (new ArrayList<>(cur)) to the output; cur keeps changing.
  • Combination Sum: recurse with i (reuse allowed) or i + 1 (each used once).

Dynamic programming

Bitmask DP

Plan day 22Plan day 22
Use it when
  • n ≤ 20 and the state is "which items are used".
  • Assignment, travelling salesman, work sessions, visiting all nodes.

How it works

A subset is an int: bit j is 1 if item j is used. Fill dp[mask] (or dp[mask][last]) in increasing mask order, because adding an item always makes the mask bigger. 2²⁰ ≈ 10⁶ masks times 20 transitions is about 2·10⁷ steps.

📄Templatememorise
// n <= 20: a subset is an int mask. Assign n jobs to n workers at minimum total cost.
static int minAssignment(int[][] cost) {
    int n = cost.length;
    int[] dp = new int[1 << n];                        // dp[mask] = jobs in mask are taken
    Arrays.fill(dp, Integer.MAX_VALUE);
    dp[0] = 0;
    for (int mask = 0; mask < (1 << n); mask++) {
        if (dp[mask] == Integer.MAX_VALUE) continue;
        int worker = Integer.bitCount(mask);           // workers 0..worker-1 are done
        if (worker == n) continue;
        for (int job = 0; job < n; job++) {
            if ((mask & (1 << job)) != 0) continue;
            int next = mask | (1 << job);
            dp[next] = Math.min(dp[next], dp[mask] + cost[worker][job]);
        }
    }
    return dp[(1 << n) - 1];
}

// Shortest path visiting every node once (start anywhere): dp[mask][last]
static long shortestHamiltonianPath(long[][] dist) {
    int n = dist.length;
    long INF = Long.MAX_VALUE / 4;
    long[][] dp = new long[1 << n][n];
    for (long[] row : dp) Arrays.fill(row, INF);
    for (int v = 0; v < n; v++) dp[1 << v][v] = 0;
    for (int mask = 1; mask < (1 << n); mask++)
        for (int last = 0; last < n; last++) {
            if (dp[mask][last] >= INF) continue;
            for (int nxt = 0; nxt < n; nxt++) {
                if ((mask & (1 << nxt)) != 0) continue;
                int m2 = mask | (1 << nxt);
                dp[m2][nxt] = Math.min(dp[m2][nxt], dp[mask][last] + dist[last][nxt]);
            }
        }
    long best = INF;
    for (int v = 0; v < n; v++) best = Math.min(best, dp[(1 << n) - 1][v]);
    return best;
}

// Every submask of mask (all masks together: 3^n steps):
// for (int s = mask; s > 0; s = (s - 1) & mask) { ... }   then handle s == 0 separately

Cost: O(2ⁿ · n) or O(2ⁿ · n²)

Variants

  • All submasks of a mask: for (s = mask; s > 0; s = (s − 1) & mask), 3ⁿ steps over all masks.
Traps
  • Bracket bit tests: (mask & (1 << j)) != 0.
  • dp[1 << 20][20] of longs is 160 MB. Check memory first.

Dynamic programming

Digit DP

Plan day 22Plan day 22
Use it when
  • Count numbers in [L, R] (R up to 10¹⁸) with a digit property.
  • Digit sums, no repeated digits, divisible by k with equal even and odd digit counts.

How it works

Build the number one digit at a time from the left. "tight" means the prefix equals R's prefix, so the next digit can't exceed R's digit. Once you go below, every later digit is free (0–9) and the state can be memoised. The answer for a range is f(R) − f(L − 1).

📄Templatememorise
// How many x in [0, N] have a digit sum divisible by D?  For a range [L, R]: f(R) - f(L - 1).
// State: (position, remainder so far, tight = "prefix equals N's prefix").
static char[] dig;
static long[][] digMemo;
static int digMod;

static long countUpTo(long N, int D) {
    dig = Long.toString(N).toCharArray();
    digMod = D;
    digMemo = new long[dig.length][D];
    for (long[] row : digMemo) Arrays.fill(row, -1);
    return digitGo(0, 0, true);
}

static long digitGo(int pos, int rem, boolean tight) {
    if (pos == dig.length) return rem == 0 ? 1 : 0;
    if (!tight && digMemo[pos][rem] != -1) return digMemo[pos][rem];   // memo only free states
    int limit = tight ? dig[pos] - '0' : 9;
    long res = 0;
    for (int d = 0; d <= limit; d++) res += digitGo(pos + 1, (rem + d) % digMod, tight && d == limit);
    if (!tight) digMemo[pos][rem] = res;
    return res;
}
// Add a "started" flag to the state when leading zeros change the answer.

Cost: O(digits · states · 10)

Variants

  • Leading zeros change the answer (digit counts, "no repeated digits"): add a started flag.
Traps
  • Memoise only states with tight == false.
  • f(L − 1) when L = 0: return 0.

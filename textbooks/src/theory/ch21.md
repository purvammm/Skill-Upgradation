Chapter 20 built a segment tree that changes one element at a time and answers questions about ranges. Chapter 2 built a difference array that adds a value to a whole range in O(1), but only if every update arrives before the first question. Many problems mix the two: "add 5 to every element of *a*[2..7]; what is the largest element of *a*[4..9] now?", repeated 10⁵ times. Neither tool handles that quickly. This chapter adds one idea to the segment tree, the *lazy tag*, which postpones the work of a range update until a later operation actually needs it. With it, range updates and range queries both cost O(log *n*).

The second half of the chapter uses the lazy tree as the engine of a dynamic programme. "Split the array into exactly *K* consecutive parts and optimise the total cost of the parts" is a DP with *K* · *n* states, and its natural transition looks at all *n* possible starts of the last part, which gives O(*K* *n*²). For some costs, among them "the number of distinct values in the part", one step of the DP changes the candidate values of a whole *range* of starts by the same amount. That is exactly a range add, and a lazy tree turns the O(*n*) transition into O(log *n*). The Infosys gift-box problem, reported very often for the SP paper, is solved this way.

## Range updates on a segment tree {#sec-21-why}

This chapter uses the recursive layout of a segment tree, because the lazy version is easiest to write and to prove correct in that form. Node 1 covers the whole array *a*[0..*n* − 1]. A node *x* that covers [*lo*, *hi*] with *lo* < *hi* has two children: node 2*x* covers [*lo*, *mid*] and node 2*x* + 1 covers [*mid* + 1, *hi*], where *mid* = ⌊(*lo* + *hi*)/2⌋. A node with *lo* = *hi* is a leaf and stands for one element. Each node stores an aggregate of its range; in this chapter it is mostly the maximum, `mx[x]`.

Chapter 20's operations work as follows in this layout. A point update changes one leaf and recomputes the leaf's ancestors, one per level. A range query walks down from the root and stops at every node whose range lies completely inside [*l*, *r*]; those nodes split [*l*, *r*] into O(log *n*) disjoint pieces, and the answer is the maximum of their stored values.

Now add *v* to every element of *a*[*l*..*r*]. Done as *r* − *l* + 1 point updates, this changes every leaf in the range and every ancestor of those leaves, so at least *r* − *l* + 1 nodes are rewritten. With *n* = 10⁵ and 10⁵ updates over long ranges, that is around 10¹⁰ node changes, a hundred times more than Java does in a second. The difference array of Chapter 2 makes each update O(1), but then a single read needs a running sum over the array, O(*n*) per read when updates and reads alternate.

The query already contains the way out. A range [*l*, *r*] splits into O(log *n*) nodes whose ranges lie inside it. If an update could change only those nodes, it would be as cheap as a query. The values of these nodes are easy to fix: adding *v* to every element of a range adds *v* to its maximum. The trouble is the nodes *below* them, whose stored maxima are now out of date. The lazy idea is to leave them out of date for now, and to write a note at the node where the update stopped that says "everything below me still owes +*v*". The note is passed one level down only when a later operation needs to go below that node.

Throughout the chapter the task is: maintain *a*[0..*n* − 1], initially all zeros, under two operations, `add(l, r, v)` (add *v* to every *a*[*i*] with *l* ≤ *i* ≤ *r*) and `max(l, r)` (return the largest *a*[*i*] with *l* ≤ *i* ≤ *r*).

## Lazy tags and push-down {#sec-21-lazy}

:::definition{#def-21-lazy} Lazy tag, lazy propagation, push-down
A [[lazy tag]] `lz[x]` is an amount that has been added to every element of node *x*'s range, is already included in `mx[x]`, and has not yet been passed on to the children of *x*. The technique of stopping a range update at the nodes whose ranges lie inside the update range, and recording the update in their tags, is called [[lazy propagation]]. The operation `push(x)`, called [[push-down]], passes the tag of *x* to both children, adding it to their values and their tags, and then sets `lz[x]` to 0.
:::

The handbook template below implements range add and range maximum. It is the first card for today, used unchanged.

```java {#lst-21-lazymax} Lazy segment tree: range add, range max (handbook template)
// Lazy segment tree: add v to every a[l..r], ask max of a[l..r] (both inclusive), O(log n)
static final class LazyMax {
    final int n;
    final long[] mx, lz;

    LazyMax(int n) {
        this.n = n;
        mx = new long[4 * n];
        lz = new long[4 * n];
    }

    private void push(int x) {                           // hand the pending add to both children
        if (lz[x] == 0) return;
        for (int c = 2 * x; c <= 2 * x + 1; c++) {
            mx[c] += lz[x];
            lz[c] += lz[x];
        }
        lz[x] = 0;
    }

    void add(int l, int r, long v) { add(1, 0, n - 1, l, r, v); }

    private void add(int x, int lo, int hi, int l, int r, long v) {
        if (r < lo || hi < l) return;
        if (l <= lo && hi <= r) {                        // fully covered: stop here, remember the add
            mx[x] += v;
            lz[x] += v;
            return;
        }
        push(x);
        int mid = (lo + hi) >>> 1;
        add(2 * x, lo, mid, l, r, v);
        add(2 * x + 1, mid + 1, hi, l, r, v);
        mx[x] = Math.max(mx[2 * x], mx[2 * x + 1]);
    }

    long max(int l, int r) { return max(1, 0, n - 1, l, r); }

    private long max(int x, int lo, int hi, int l, int r) {
        if (r < lo || hi < l) return Long.MIN_VALUE;
        if (l <= lo && hi <= r) return mx[x];
        push(x);
        int mid = (lo + hi) >>> 1;
        return Math.max(max(2 * x, lo, mid, l, r), max(2 * x + 1, mid + 1, hi, l, r));
    }
}
```

Both recursive methods sort every node they are called on into one of three kinds.

:::definition{#def-21-partial} Outside, covered and partial nodes
For an operation on [*l*, *r*], a node with range [*lo*, *hi*] is **outside** if the two ranges do not overlap, **covered** if *l* ≤ *lo* and *hi* ≤ *r*, and [[partial|partially covered node]] otherwise, that is, if it overlaps [*l*, *r*] without lying inside it.
:::

An outside node returns at once. A covered node finishes the job on its own: `add` changes its value and its tag, `max` returns its value. Only a partial node looks at its children, and it calls `push` first so that the children are up to date before anyone reads or changes them. After the recursive calls, `add` recomputes the node from its two children.

### Why the tree is always right

The values in the tree are wrong in a controlled way: every node misses exactly the tags that sit above it. The proof makes that precise.

For a node *x*, let above(*x*) be the sum of `lz[y]` over all proper ancestors *y* of *x* (0 for the root). Call the tree **consistent** when, for every node *x* with range [*lo*, *hi*],

`mx[x]` + above(*x*) = max(*a*[*lo*], …, *a*[*hi*]) for the current array *a*.

This is the invariant in symbols: a node's value is correct for its range once all tags above it are applied, and a node's own tag is a debt to its children, not to itself. At the root above(1) = 0, so a consistent tree stores the true maximum of the whole array at node 1.

:::lemma{#lem-21-push} Push-down keeps the tree consistent
If the tree is consistent and *x* is not a leaf, then after `push(x)` the tree is still consistent and `lz[x]` = 0.
:::

:::proof
Let *t* be the old `lz[x]`. The push changes `mx` and `lz` of the two children and sets `lz[x]` to 0; nothing else changes. For *x* and for every node outside the subtree of *x*, neither its value nor the tags of its ancestors changed. For a child *c*, above(*c*) fell by *t* (the tag of *x*) and `mx[c]` rose by *t*, so their sum is unchanged. For a deeper node *d* below child *c*, above(*d*) lost *t* at *x* and gained *t* at *c*, and `mx[d]` did not change. So every node keeps its equation.
:::

:::theorem{#thm-21-correct} Correctness of the lazy tree
If the tree is consistent before `add(l, r, v)` or `max(l, r)`, it is consistent afterwards (with respect to the new array, for `add`), and `max(l, r)` returns max(*a*[*l*], …, *a*[*r*]).
:::

:::proof
*Step 1: when a call reaches node x, every proper ancestor of x has tag 0, so above(x) = 0.* The recursion reaches *x* from the root through its ancestors, and each of them was partial (outside and covered nodes do not recurse). Each partial ancestor ran `push`, which set its tag to 0. A node's tag changes only when the node itself is updated as covered (not the case for an ancestor of a node still being visited) or when its parent pushes, which happened before the node itself pushed. The calls in the sibling subtrees touch only nodes in those subtrees, which are not ancestors of *x*.

*Step 2: max.* By induction from the leaves up, a call on *x* returns the maximum of *a* over [*l*, *r*] ∩ [*lo*, *hi*], or `Long.MIN_VALUE` if that is empty. For an outside node the intersection is empty. For a covered node the intersection is all of [*lo*, *hi*], and by Step 1 and consistency `mx[x]` is exactly its maximum. For a partial node, Lemma @lem-21-push keeps the tree consistent, the two children split [*lo*, *hi*] into two parts, and by induction each returns the maximum over its part. A query changes the tree only by pushes, so consistency is kept.

*Step 3: add.* Think of the whole update as applied to *a* at once, and show by induction from the leaves up that when the call on *x* returns, every node in the subtree of *x* is consistent with the new array. For an outside node nothing in its range changed. For a covered node, every element of its range rose by *v*; `mx[x]` rose by *v* and above(*x*) = 0, so *x* is consistent; every descendant *d* has above(*d*) larger by *v* because of the new tag, and its true maximum is also larger by *v*. For a partial node, after the push `lz[x]` = 0, and by induction both children are consistent when they return, with above equal to above(*x*) + 0 = 0. So their stored values are the true maxima of the two halves, and `mx[x] = max(mx[2x], mx[2x+1])` is the true maximum of [*lo*, *hi*]. Every node outside the subtree of the root call is an ancestor or lies in a disjoint range, so when the root call returns, the whole tree is consistent.
:::

:::note
Leaves also receive tags (`lz[c] += lz[x]` does not check whether *c* is a leaf), but a leaf's tag is never read. `push` runs only on partial nodes, and a leaf is always outside or covered, because a single position is either in [*l*, *r*] or not. That is why @fig-21-tags does not need to show leaf tags.
:::

:::java
`max` returns `Long.MIN_VALUE` for an outside node. That is safe only because the value is fed to `Math.max` and never added to. A tree of sums or a DP that adds to the result needs a different identity. `(lo + hi) >>> 1` is the overflow-free midpoint from Chapter 6; with array indices it is the same as `/ 2`, but it is a good habit.
:::

The tree starts with all zeros. To start from an array *b*, call `add(j, j, b[j])` for every *j*, which costs O(*n* log *n*) in total; the K-parts DP of @sec-21-fast does exactly that.

## Each operation visits O(log n) nodes {#sec-21-cost}

Two facts are needed: the tree is shallow, and an operation calls only a few nodes on each level.

:::lemma{#lem-21-height} Height and array size
Let *n* ≥ 1 and *h* = ⌈log₂ *n*⌉. Every leaf is at depth at most *h*, and every node index is smaller than 4*n*.
:::

:::proof
A node whose range has *s* > 1 elements has children with ⌈*s*/2⌉ and ⌊*s*/2⌋ elements. By induction on the depth *d*, a node at depth *d* covers at most ⌈*n*/2<sup>*d*</sup>⌉ elements, since ⌈⌈*n*/2<sup>*d*</sup>⌉/2⌉ = ⌈*n*/2<sup>*d*+1</sup>⌉. At depth *h*, *n*/2<sup>*h*</sup> ≤ 1, so every node there is a leaf. The root has index 1 and the children of *x* are 2*x* and 2*x* + 1, so the indices at depth *d* lie between 2<sup>*d*</sup> and 2<sup>*d*+1</sup> − 1, and every index is below 2<sup>*h*+1</sup>. Because *h* is the smallest integer with 2<sup>*h*</sup> ≥ *n*, 2<sup>*h*−1</sup> < *n* (for *n* ≥ 2), hence 2<sup>*h*+1</sup> < 4*n*. For *n* = 1 the only index is 1 < 4.
:::

The bound 4*n* is not generous padding. A test over all *n* up to 100 found that *n* = 6 is the smallest size for which 2*n* is too small: the tree uses index 13. For *n* = 35 001 the largest index is 131 041, below 4*n* = 140 004.

:::theorem{#thm-21-visits} At most four nodes per level
In one call of `add` or `max` on [*l*, *r*], at most two partial nodes lie on each level, and at most four nodes are called on each level. For *n* ≥ 2 the total number of calls is at most 4*h* − 1, where *h* = ⌈log₂ *n*⌉.
:::

:::proof
Take a partial node [*lo*, *hi*]. It overlaps [*l*, *r*], so *lo* ≤ *r* and *l* ≤ *hi*, and it is not inside [*l*, *r*], so *lo* < *l* or *hi* > *r*. In the first case *lo* < *l* ≤ *hi*, so the node contains position *l*. In the second case *lo* ≤ *r* < *hi*, so it contains position *r*. The ranges of the nodes on one level are disjoint, so at most one of them contains *l* and at most one contains *r*. Hence at most two nodes per level are partial.

Only partial nodes call their children, two each. So the nodes called on level *d* + 1 number at most 2 × 2 = 4. Level 0 holds one call (the root) and level 1 at most two. By @lem-21-height there are no nodes below level *h*. The total is at most 1 + 2 + 4(*h* − 1) = 4*h* − 1.
:::

## Other operations and tags that compose {#sec-21-compose}

Nothing in @sec-21-lazy depended on "add" and "max" except two facts. Change those facts and the same skeleton gives other trees.

:::definition{#def-21-compose} What a tag must allow
A kind of tag works in a lazy segment tree when (1) applying a tag to a node's stored aggregate can be done from the aggregate alone, without visiting the children, and (2) two tags applied one after the other always equal a single tag of the same kind. Property (2) is [[tag composition]]; it lets a node hold one pending tag however many updates reached it.
:::

For add and max, (1) holds because adding *v* to every element adds *v* to the maximum, and (2) holds because adding *d* and then *v* is adding *d* + *v*. Range **minimum** with range add is the same tree with `Math.min` and `Long.MAX_VALUE`.

### Range add, range sum

For sums, property (1) needs one more number: adding *v* to every element of a node with *len* elements adds *v* · *len* to its sum. So the function that applies a tag must know the node's range, and `push` must pass *lo* and *hi* along.

```java {#lst-21-lazysum} Lazy segment tree: range add, range sum
// Lazy segment tree: add v to every a[l..r], ask the sum of a[l..r] (both inclusive), O(log n)
static final class LazySum {
    final int n;
    final long[] tot, lz;                                // tot[x] = sum of node x's range

    LazySum(int n) {
        this.n = n;
        tot = new long[4 * n];
        lz = new long[4 * n];
    }

    private void apply(int x, int lo, int hi, long v) {  // add v to every element of node x
        tot[x] += v * (hi - lo + 1);                     // the sum grows by v per element
        lz[x] += v;
    }

    private void push(int x, int lo, int hi) {
        if (lz[x] == 0) return;
        int mid = (lo + hi) >>> 1;
        apply(2 * x, lo, mid, lz[x]);
        apply(2 * x + 1, mid + 1, hi, lz[x]);
        lz[x] = 0;
    }

    void add(int l, int r, long v) { add(1, 0, n - 1, l, r, v); }

    private void add(int x, int lo, int hi, int l, int r, long v) {
        if (r < lo || hi < l) return;
        if (l <= lo && hi <= r) {
            apply(x, lo, hi, v);
            return;
        }
        push(x, lo, hi);
        int mid = (lo + hi) >>> 1;
        add(2 * x, lo, mid, l, r, v);
        add(2 * x + 1, mid + 1, hi, l, r, v);
        tot[x] = tot[2 * x] + tot[2 * x + 1];
    }

    long sum(int l, int r) { return sum(1, 0, n - 1, l, r); }

    private long sum(int x, int lo, int hi, int l, int r) {
        if (r < lo || hi < l) return 0;
        if (l <= lo && hi <= r) return tot[x];
        push(x, lo, hi);
        int mid = (lo + hi) >>> 1;
        return sum(2 * x, lo, mid, l, r) + sum(2 * x + 1, mid + 1, hi, l, r);
    }
}
```

The proof of @thm-21-correct carries over word for word with the invariant `tot[x]` + above(*x*) · (*hi* − *lo* + 1) = *a*[*lo*] + ⋯ + *a*[*hi*]. For example, on *a* = [1, 2, 3, 4] the updates +3 and then −1 on the whole array leave one tag +2 at the root and the sum 10 + 4 · 2 = 18, and `sum(1, 2)` then pushes the tag and returns 9.

### Assignment and addition together

Suppose the updates are of two kinds: "set every element of [*l*, *r*] to *c*" and "add *v* to every element of [*l*, *r*]". A node may receive several of them before it pushes, and they do not commute: "add 1, then set 5" leaves 5, while "set 5, then add 1" leaves 6. So the rule for combining them must respect the order in which they arrived.

:::claim{#thm-21-compose} Composing set and add
Write a tag as "add *d*" or "set *c*". Applying an older tag *A* and then a newer tag *B* to every element has the same effect as the single tag: add *d* + *v* if *A* = add *d* and *B* = add *v*; set *c* + *v* if *A* = set *c* and *B* = add *v*; set *c* if *B* = set *c*, whatever *A* is. Moreover, when node *x* pushes, its tag is newer than any tag its children hold.
:::

:::proof
Follow one element with value *y*. Add *d* then add *v* gives *y* + *d* + *v*. Set *c* then add *v* gives *c* + *v* whatever *y* was. Anything followed by set *c* gives *c*. For the second statement: a child's tag changes only when the recursion visits the child or when *x* pushes. The recursion reaches a child only through *x*, and *x* pushes before that, so its tag is 0 at that moment. Therefore any tag currently at *x* arrived after the last change to the children's tags, and `push` must compose it *after* theirs.
:::

```java {#lst-21-assignadd} Range assign and range add with range max: one tag that composes
// Range assign, range add, range max. A pending tag is "set to c" or "add d", never both.
static final class AssignAddMax {
    final int n;
    final long[] mx, tag;
    final boolean[] isSet;                               // tag[x] means "set" if isSet[x], else "add"

    AssignAddMax(int n) {
        this.n = n;
        mx = new long[4 * n];
        tag = new long[4 * n];
        isSet = new boolean[4 * n];
    }

    private void applySet(int x, long c) {               // set wins over any older tag
        mx[x] = c;
        tag[x] = c;
        isSet[x] = true;
    }

    private void applyAdd(int x, long v) {               // add after "set c" = "set c + v"
        mx[x] += v;
        tag[x] += v;
    }

    private void push(int x) {
        for (int c = 2 * x; c <= 2 * x + 1; c++) {
            if (isSet[x]) applySet(c, tag[x]);
            else if (tag[x] != 0) applyAdd(c, tag[x]);
        }
        tag[x] = 0;
        isSet[x] = false;
    }

    void set(int l, int r, long c) { update(1, 0, n - 1, l, r, c, true); }

    void add(int l, int r, long v) { update(1, 0, n - 1, l, r, v, false); }

    private void update(int x, int lo, int hi, int l, int r, long v, boolean set) {
        if (r < lo || hi < l) return;
        if (l <= lo && hi <= r) {
            if (set) applySet(x, v);
            else applyAdd(x, v);
            return;
        }
        push(x);
        int mid = (lo + hi) >>> 1;
        update(2 * x, lo, mid, l, r, v, set);
        update(2 * x + 1, mid + 1, hi, l, r, v, set);
        mx[x] = Math.max(mx[2 * x], mx[2 * x + 1]);
    }

    long max(int l, int r) { return max(1, 0, n - 1, l, r); }

    private long max(int x, int lo, int hi, int l, int r) {
        if (r < lo || hi < l) return Long.MIN_VALUE;
        if (l <= lo && hi <= r) return mx[x];
        push(x);
        int mid = (lo + hi) >>> 1;
        return Math.max(max(2 * x, lo, mid, l, r), max(2 * x + 1, mid + 1, hi, l, r));
    }
}
```

`applyAdd` is one method for both cases of @thm-21-compose: if the node holds "set *c*", adding *v* to `tag[x]` turns it into "set *c* + *v*"; if it holds "add *d*", it becomes "add *d* + *v*". `applySet` overwrites whatever was there. In `push`, the parent's tag is applied to each child with the same two methods, which composes it after the child's own tag, as the claim requires.

:::pitfall
A common wrong design keeps two independent fields, a pending set and a pending add, and in `push` always applies the add first and the set second. After "set 5, then add 1" on the same node, that order produces 5 instead of 6. Either fold the add into the set as above, or define precisely which of the two fields was applied first and keep that order everywhere.
:::

Not every update has a tag. "Multiply every element by −1" in a tree that stores only maxima breaks property (1): the new maximum is minus the old *minimum*, which the node does not store. Storing both the maximum and the minimum repairs it. When a new kind of update appears, check (1) and (2) before you write any code.

## Splitting an array into K parts {#sec-21-kparts}

The second pattern of the day is a DP family that appears whenever a statement says "divide the sequence into exactly *K* consecutive groups (days, boxes, segments) and optimise the total cost of the groups".

:::definition{#def-21-kparts} The K-parts DP
Given *a*[0..*n* − 1], a number of parts *K*, and a cost for every part *a*[*j*..*i* − 1], the [[K-parts DP]] computes dp[*k*][*i*] = the best total cost of splitting the prefix *a*[0..*i* − 1] into exactly *k* non-empty consecutive parts, for 0 ≤ *k* ≤ *K* and 0 ≤ *i* ≤ *n*. The index *j* at which the last part starts is its [[split point]]. States that no split can reach (*i* < *k*, or *k* = 0 < *i*) hold +∞ for a minimum and −∞ for a maximum.
:::

In the five-part recipe of Chapter 11: the **state** is dp[*k*][*i*] as defined; the **transition** chooses the split point; the **base case** is dp[0][0] = 0 (no elements, no parts); the **evaluation order** is by increasing *k*; the **answer** is dp[*K*][*n*].

:::theorem{#thm-21-kparts} The K-parts recurrence
For 1 ≤ *k* ≤ *K* and *k* ≤ *i* ≤ *n*,
dp[*k*][*i*] = best over *k* − 1 ≤ *j* ≤ *i* − 1 of dp[*k* − 1][*j*] + cost(*j*, *i* − 1),
where cost(*j*, *i* − 1) is the cost of the part *a*[*j*..*i* − 1] and "best" is the minimum or the maximum, as the problem asks.
:::

:::proof
Look at the last decision: where the last part starts. In any split of *a*[0..*i* − 1] into *k* non-empty parts, the last part is *a*[*j*..*i* − 1] for some *j*. It is non-empty, so *j* ≤ *i* − 1; the other *k* − 1 parts are non-empty and fill *a*[0..*j* − 1], so *j* ≥ *k* − 1. Removing the last part leaves a split of *a*[0..*j* − 1] into *k* − 1 parts, and conversely any such split followed by the part *a*[*j*..*i* − 1] is a split of *a*[0..*i* − 1] into *k* parts. The total is additive, so for a fixed *j* the best total is the best for the first *j* elements in *k* − 1 parts plus cost(*j*, *i* − 1): if the first *k* − 1 parts were not optimal, replacing them by an optimal split of *a*[0..*j* − 1] would improve the whole. Taking the best over all allowed *j* covers every split. Row *k* reads only row *k* − 1, so filling rows in increasing *k* is a valid order, and the proof template of Chapter 11 applies.
:::

The handbook's baseline uses the cost "maximum of the part" and minimises the total. That is LeetCode 1335 (Minimum Difficulty of a Job Schedule) with *K* days, apart from the problem's request to print −1 when there are fewer jobs than days.

```java {#lst-21-kparts} K parts, O(K n²): minimise the sum of the parts' maxima (handbook template)
// Split a into exactly K non-empty contiguous parts, minimise the sum of max(part).
// dp[k][i] = best for the first i elements in k parts. O(K * n^2). (LeetCode 1335)
static long splitMinSumOfMax(int[] a, int K) {
    int n = a.length;
    long INF = Long.MAX_VALUE / 4;
    long[][] dp = new long[K + 1][n + 1];
    for (long[] row : dp) Arrays.fill(row, INF);
    dp[0][0] = 0;
    for (int k = 1; k <= K; k++)
        for (int i = k; i <= n; i++) {
            int mx = 0;
            for (int j = i - 1; j >= k - 1; j--) {     // the last part is a[j..i-1]
                mx = Math.max(mx, a[j]);
                if (dp[k - 1][j] < INF) dp[k][i] = Math.min(dp[k][i], dp[k - 1][j] + mx);
            }
        }
    return dp[K][n];                                     // INF if K > n
}
```

The inner loop runs *j* **downwards**. Then the last part *a*[*j*..*i* − 1] grows by one element on the left at each step, and its maximum `mx` is updated in O(1) instead of being recomputed in O(*i* − *j*). (`mx` starts at 0 because the problem's values are non-negative.)

### Cost and the unreachable states

Row *k* has at most *n* states and each looks at up to *n* split points, so the method costs O(*K* *n*²) time; the exact number of inner steps is about *K* *n*²/2. It needs O(*K* *n*) memory, or O(*n*) with two rolling rows, because row *k* reads only row *k* − 1.

:::pitfall
Unreachable states must stay at +∞ (or −∞ when maximising). If the table starts at 0 instead, dp[1][0] = 0 claims that zero elements form one part, and empty parts sneak in. For *a* = [3, 4] and *K* = 2, a zero-initialised version of @lst-21-kparts that also lets *j* run down to 0 returns 4 (an empty part plus [3, 4]) instead of 7. The guard `dp[k - 1][j] < INF` also keeps `INF + mx` from being compared as if it were a real total; `Long.MAX_VALUE / 4` leaves room for the addition without overflow.
:::

### The gift-box problem

:::infosys
"Pack gifts into exactly K consecutive boxes, maximise the total of distinct counts" is an SP repeat that the plan rates "very high": 9 independent reports in the community question bank, 2022–2026. Its limits are *N* ≤ 35 000 and *K* ≤ 50, the same as Codeforces 833B (The Bakery), today's bonus problem. The plan notes that the O(*K* *N*²) DP gets the small tests. A related repeat from a PrepInsta SP set splits into *k* ≤ 100 segments with *n* ≤ 35 000 and minimises a different cost; @sec-21-recognise gives its key observation.
:::

In words: the gifts stand in a row, gift *i* has type *a*[*i*], and you must cut the row into exactly *K* non-empty runs of consecutive gifts (the boxes). The value of a box is the number of different types in it, and you want the largest total value. This is the K-parts DP with cost(*j*, *i* − 1) = the number of distinct values in *a*[*j*..*i* − 1], maximised. The baseline changes only the cost: as *j* moves down, the part gains *a*[*j*], and the distinct count grows by 1 exactly when *a*[*j*] has not been seen in this part yet.

```java {#lst-21-slow} Gift boxes in O(K n²): the baseline for partial marks
// Gift boxes in O(K * n^2): exactly K consecutive non-empty boxes,
// maximise the sum of distinct counts.
static long maxDistinctSumSlow(int[] a, int K) {         // values 0..maxV
    int n = a.length, maxV = 0;
    for (int x : a) maxV = Math.max(maxV, x);
    final long NEG = Long.MIN_VALUE / 4;
    long[][] dp = new long[K + 1][n + 1];
    for (long[] row : dp) Arrays.fill(row, NEG);
    dp[0][0] = 0;
    int[] seen = new int[maxV + 1];                      // seen[v] == stamp  <=>  v is in a[j..i-1]
    int stamp = 0;
    for (int k = 1; k <= K; k++)
        for (int i = k; i <= n; i++) {
            stamp++;                                     // a fresh "seen" set for this (k, i)
            int distinct = 0;
            for (int j = i - 1; j >= k - 1; j--) {       // the last box is a[j..i-1]
                if (seen[a[j]] != stamp) { seen[a[j]] = stamp; distinct++; }
                if (dp[k - 1][j] > NEG) dp[k][i] = Math.max(dp[k][i], dp[k - 1][j] + distinct);
            }
        }
    return dp[K][n];                                     // NEG if K > n
}
```

The `stamp` trick gives every pair (*k*, *i*) a fresh empty set without clearing an array: a value counts as seen only if its mark equals the current stamp. Clearing a `boolean[]` of size maxV + 1 for each of the *K* · *n* pairs would cost O(*K* *n* · maxV) on its own.

For *n* = 35 000 and *K* = 50 the inner loop runs about 3.06 · 10¹⁰ times. On the test machine the baseline already needed 1.1 s for *n* = 4000, so the full limits would take over a minute. The next section removes the factor *n*.

## When the cost changes by a range add {#sec-21-fast}

Fix the layer *k* and think of *i* as time. For the current *i*, every split point *j* < *i* has a candidate value

*T*ᵢ[*j*] = dp[*k* − 1][*j*] + distinct(*a*[*j*..*i* − 1]),

and dp[*k*][*i*] is the largest candidate, max over *j* ≤ *i* − 1 of *T*ᵢ[*j*]. The baseline rebuilds all candidates for every *i*. But the first term does not depend on *i* at all, and the second changes very little when *i* grows by one.

:::lemma{#lem-21-range} One new element adds 1 to a range of split points
Let *x* = *a*[*i* − 1] and let *p* be the largest index below *i* − 1 with *a*[*p*] = *x*, or *p* = −1 if there is none. For every split point *j* ≤ *i* − 1,
distinct(*a*[*j*..*i* − 1]) = distinct(*a*[*j*..*i* − 2]) + 1 if *j* > *p*, and distinct(*a*[*j*..*i* − 2]) if *j* ≤ *p*.
(For *j* = *i* − 1 the part *a*[*j*..*i* − 2] is empty and has 0 distinct values.)
:::

:::proof
Appending *x* to the part *a*[*j*..*i* − 2] raises its number of distinct values by 1 if *x* does not occur in it, and leaves it unchanged otherwise. The copies of *x* before position *i* − 1 lie at *p* and further left. If *j* ≤ *p*, the part contains position *p* and so a copy of *x*. If *j* > *p*, every earlier copy lies left of *j*, and the part contains none.
:::

So going from *i* − 1 to *i* adds exactly 1 to the candidates of the split points *p* + 1, …, *i* − 1 and nothing to the others. The positions are consecutive, so it is one range add.

Store the candidates in a LazyMax tree indexed by *j* = 0..*n*. At the start of the layer, put dp[*k* − 1][*j*] at position *j* (the part *a*[*j*..*j* − 1] is empty and has no distinct values). For *i* = 1, 2, …, *n*: add 1 on [*p* + 1, *i* − 1], then read dp[*k*][*i*] as the maximum over [0, *i* − 1].

:::theorem{#thm-21-fast} The layer computed with a lazy tree
In the layer for *k*, just after the range add for *i*, position *j* of the tree holds dp[*k* − 1][*j*] + distinct(*a*[*j*..*i* − 1]) for every *j* ≤ *i* − 1, and dp[*k* − 1][*j*] for *j* ≥ *i*. Consequently `tree.max(0, i - 1)` is dp[*k*][*i*] for every *i* ≥ *k*.
:::

:::proof
By induction on *i*. Before the first step (think of it as *i* = 0) every position holds dp[*k* − 1][*j*], which is the claim with no positions of the first kind. Assume the claim after step *i* − 1. Positions *j* ≤ *i* − 2 hold dp[*k* − 1][*j*] + distinct(*a*[*j*..*i* − 2]), and position *i* − 1 holds dp[*k* − 1][*i* − 1], which equals dp[*k* − 1][*i* − 1] + distinct of the empty part. Step *i* adds 1 exactly on [*p* + 1, *i* − 1], which by @lem-21-range turns each of these into dp[*k* − 1][*j*] + distinct(*a*[*j*..*i* − 1]), and leaves positions ≥ *i* alone. That is the claim for *i*. By @thm-21-correct, the query returns the maximum of positions 0..*i* − 1, which by @thm-21-kparts is dp[*k*][*i*], except that it also looks at split points *j* < *k* − 1. Those hold unreachable values near −∞, so they never win while a reachable split point exists, and *j* = *k* − 1 is reachable when *i* ≥ *k*.
:::

The handbook's fast version is exactly this. The program below wraps it with input reading. The class LazyMax at the end repeats @lst-21-lazymax unchanged so that the file compiles on its own, as it must in the exam.

```java {#lst-21-bakery} Gift boxes / Codeforces 833B in O(K n log n): a complete program (handbook template)
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        StreamTokenizer in = new StreamTokenizer(new BufferedReader(new InputStreamReader(System.in)));
        in.nextToken();
        int n = (int) in.nval;                           // order as in Codeforces 833B: n, K, values
        in.nextToken();
        int K = (int) in.nval;
        int[] a = new int[n];
        for (int i = 0; i < n; i++) {
            in.nextToken();
            a[i] = (int) in.nval;
        }
        System.out.println(maxDistinctSum(a, K));
    }

    // Faster version for "sum of distinct counts" (Codeforces 833B, the Infosys "gift boxes"):
    // tree[j] = dp[k-1][j] + distinct(a[j..i-1]). Moving i adds 1 on a RANGE of j: lazy segment tree.
    static long maxDistinctSum(int[] a, int K) {             // values 0..maxV, O(K * n log n)
        int n = a.length, maxV = 0;
        for (int x : a) maxV = Math.max(maxV, x);
        final long NEG = Long.MIN_VALUE / 4;
        long[] prev = new long[n + 1];                       // prev[j] = dp[k-1][j]
        Arrays.fill(prev, NEG);
        prev[0] = 0;
        for (int k = 1; k <= K; k++) {
            LazyMax tree = new LazyMax(n + 1);
            for (int j = 0; j <= n; j++) tree.add(j, j, prev[j]);
            int[] last = new int[maxV + 1];
            Arrays.fill(last, -1);
            long[] cur = new long[n + 1];
            cur[0] = NEG;
            for (int i = 1; i <= n; i++) {
                int x = a[i - 1];
                tree.add(last[x] + 1, i - 1, 1);  // x is new for parts starting after its last copy
                last[x] = i - 1;
                cur[i] = tree.max(0, i - 1);
            }
            prev = cur;
        }
        return prev[n];
    }

    // Listing 21.1, unchanged
    static final class LazyMax {
        final int n;
        final long[] mx, lz;

        LazyMax(int n) {
            this.n = n;
            mx = new long[4 * n];
            lz = new long[4 * n];
        }

        private void push(int x) {                      // hand the pending add to both children
            if (lz[x] == 0) return;
            for (int c = 2 * x; c <= 2 * x + 1; c++) {
                mx[c] += lz[x];
                lz[c] += lz[x];
            }
            lz[x] = 0;
        }

        void add(int l, int r, long v) { add(1, 0, n - 1, l, r, v); }

        private void add(int x, int lo, int hi, int l, int r, long v) {
            if (r < lo || hi < l) return;
            if (l <= lo && hi <= r) {                   // fully covered: stop here, remember the add
                mx[x] += v;
                lz[x] += v;
                return;
            }
            push(x);
            int mid = (lo + hi) >>> 1;
            add(2 * x, lo, mid, l, r, v);
            add(2 * x + 1, mid + 1, hi, l, r, v);
            mx[x] = Math.max(mx[2 * x], mx[2 * x + 1]);
        }

        long max(int l, int r) { return max(1, 0, n - 1, l, r); }

        private long max(int x, int lo, int hi, int l, int r) {
            if (r < lo || hi < l) return Long.MIN_VALUE;
            if (l <= lo && hi <= r) return mx[x];
            push(x);
            int mid = (lo + hi) >>> 1;
            return Math.max(max(2 * x, lo, mid, l, r), max(2 * x + 1, mid + 1, hi, l, r));
        }
    }
}
```

`last[x]` is the index of the latest copy of *x* seen so far in this layer, which is *p* of @lem-21-range; with no copy it is −1 and the range starts at 0. `prev` is row *k* − 1 and `cur` is row *k*, so only two rows of the table exist at any time.

:::example{#ex-21-layer} The second layer for a = [1, 2, 1, 3, 3, 2, 1] and K = 2
Layer 1 gives dp[1] = [−∞, 1, 2, 2, 3, 3, 3, 3], the distinct counts of the prefixes. The trace of layer 2, printed from a run of the method with the tree read back position by position after each step:

```trace
i  a[i-1]  +1 on j   T[0..7] after the add            dp[2][i] = max T[0..i-1]
1    1     0..0      -inf  1  2  2  3  3  3  3        -inf (unreachable)
2    2     0..1      -inf  2  2  2  3  3  3  3         2
3    1     1..2      -inf  3  3  2  3  3  3  3         3
4    3     0..3      -inf  4  4  3  3  3  3  3         4
5    3     4..4      -inf  4  4  3  4  3  3  3         4
6    2     2..5      -inf  4  5  4  5  4  3  3         5
7    1     3..6      -inf  4  5  5  6  5  4  3         6
```

Positions *j* ≥ *i* still hold dp[1][*j*] and are not read yet. At *i* = 7 the best split point is *j* = 4: dp[1][4] = 3 for [1, 2, 1, 3] plus 3 distinct values in [3, 2, 1], so the answer is 6. The add at *i* = 5 touches only *j* = 4, because the previous 3 sits at index 3: every longer part already contains a 3. At *i* = 1 the "range" 0..0 includes *j* = 0, whose value is −∞ plus 1, still unreachable.
:::

### Cost and limits

Each layer makes *n* + 1 point adds to load row *k* − 1, then *n* range adds and *n* range maxima. By @thm-21-visits each of these 3*n* + 1 operations makes at most 4*h* − 1 calls, where *h* = ⌈log₂(*n* + 1)⌉, so a layer costs O(*n* log *n*) and the whole method O(*K* *n* log *n*) time and O(*n*) memory. For *n* = 35 000 and *K* = 50 that bound is about 3.3 · 10⁸ calls; the measured run took about 0.6 s on the test machine, against more than a minute for the baseline.

The fast and the slow method were compared with an exhaustive search over all splits on 4000 random arrays of up to 10 elements, and with each other on 300 random arrays of up to 200 elements. The complete program was run on the three samples of Codeforces 833B, and through standard input on 500 random inputs (with values one per line or on one line) against the baseline.

:::pitfall
`last` is indexed by value, so the method assumes values between 0 and about 10⁶ (Codeforces 833B has values up to *n*). If the gift types can be as large as 10⁹, compress them to 0..*n* − 1 first (Chapter 20) or keep `last` in a `HashMap<Integer, Integer>`. And keep `NEG = Long.MIN_VALUE / 4`: unreachable values drift upwards by at most *n* · *K* ≈ 1.75 · 10⁶ during the run, which is nothing compared with 2 · 10¹⁸, and the division leaves room so that adding to them never overflows.
:::

:::java
`StreamTokenizer` splits the input at any whitespace, so the program reads "one value per line" and "all values on one line" alike. It stores every number as a `double` in `nval`, which is exact for integers up to 2⁵³, far above any count or value here.
:::

## Recognising a range-add cost {#sec-21-recognise}

The speed-up of @sec-21-fast needs one property of the cost, and it is worth stating in general so that you can test a new problem for it.

:::keyidea
Write Δ(*j*) = cost(*j*, *i* − 1) − cost(*j*, *i* − 2), the change in the candidate of split point *j* when *i* grows by one. If, as a function of *j*, Δ is constant on a few ranges whose ends you can find quickly from *i*, then each step of the layer is a few range adds on a lazy tree followed by one range query, and the K-parts DP costs O(*K* *n* log *n*).
:::

For distinct counts, Δ is 0 on [0, *p*] and 1 on [*p* + 1, *i* − 1]: two pieces, and the boundary is the previous copy of the new element. Two problems of the day fit the same mould.

* **Codeforces 1527E (Partition Game)**, the "*k* segments, minimise the sum of (last − first occurrence)" repeat. Here a value that occurs once in a part costs nothing, and a repeated value costs the distance between its first and last copy in the part. Key observation: when the new element repeats a value whose previous copy is at *p*, every part that starts at or before *p* already contained that copy, and its last copy moves from *p* to the new position, so the cost of every split point *j* ≤ *p* grows by the same amount, the distance from *p* to the new position. Parts that start after *p* contain the value once and their cost does not change. That is one range add, and the DP minimises, so the tree stores minima. The rest is yours.
* **LeetCode 2916 (Subarrays Distinct Element Sum of Squares II)** is not a K-parts problem, but it uses @lem-21-range directly: keep, for every start position, the number of distinct values in the subarray that ends at the current index. A new element adds 1 to a range of starts. The tree is the sum tree of @lst-21-lazysum, not a max tree; working out what else it must report is the exercise.

The other two core problems need no tree. LeetCode 813 (Largest Sum of Averages) is the K-parts DP with the cost "average of the part", computed in O(1) from prefix sums (Chapter 2), and its limits are small enough for the O(*K* *n*²) loop. LeetCode 1335 is @lst-21-kparts itself.

Not every cost has the property. The maximum of a part changes by a different amount for different split points: when the new element is 9, a part whose maximum was 4 gains 5 and a part whose maximum was 8 gains 1. Then Δ has as many pieces as there are different maxima, and the method needs extra ideas.

:::tip
In the exam, write the O(*K* *n*²) baseline first. It earns the small tests on its own, and it is the reference you stress-test the fast version against (Chapter 9). A version of @lst-21-bakery with the off-by-one `last[x]` in place of `last[x] + 1` disagreed with the baseline on the third random case of such a test, and on 340 of 1000 cases.
:::

Table: {#tbl-21-choose} Choosing the method from the limits
| Limits | Method | Steps |
|---|---|---|
| *n* ≤ 1000, any cost you can update as *j* moves down | baseline, @lst-21-kparts / @lst-21-slow | about 2.4 · 10⁷ inner steps for *n* = 1000, *K* = 50 |
| *n* ≤ 35 000, *K* ≤ 100, Δ is a few range adds | lazy tree per layer, @lst-21-bakery | at most 6.6 · 10⁸ calls for *K* = 100 (1.2 s measured for Codeforces 1527E's update) |
| all updates before all reads | difference array (Chapter 2) | O(*n* + updates) |
| interleaved range updates and range reads | lazy segment tree | O(log *n*) per operation |

## Summary

- A range update on a plain segment tree rewrites every leaf in the range. A lazy tree stops at the O(log *n*) nodes that lie inside the range and records the update as a tag.
- A tag at node *x* is a debt to the children of *x*, already included in `mx[x]`. Invariant: a node's value plus the tags of its ancestors is the true aggregate of its range.
- Push before you go into the children, in updates and in queries; recompute the node from its children after an update.
- At most two partial nodes and four calls per level, so at most 4⌈log₂ *n*⌉ − 1 calls per operation. Allocate arrays of 4*n*; 2*n* already fails for *n* = 6.
- A new kind of update works when its tag can be applied to the aggregate directly and two tags compose into one. Sums need the node's length. Set and add compose in order: add after set is a set.
- The K-parts DP: dp[*k*][*i*] = best over *j* of dp[*k* − 1][*j*] + cost(*j*, *i* − 1), unreachable states at ±∞, O(*K* *n*²) with the cost updated as *j* moves down.
- For distinct counts, a new element adds 1 to the candidates of the split points after its previous copy. A lazy max tree per layer gives O(*K* *n* log *n*): the Infosys gift boxes, Codeforces 833B.
- Test a new cost by writing Δ(*j*): if it is constant on a few ranges, the same speed-up applies (Codeforces 1527E with a min tree).

## Review questions

1. Why can a difference array not answer "add 3 to *a*[2..5]; what is *a*[4]?" repeated many times as fast as a lazy tree? What does each structure pay per update and per read?
2. In @fig-21-tags, what does node [4,5] store, what is the true maximum of *a*[4..5], and which tags explain the difference?
3. Someone removes `push(x)` from `max` because "a query does not change anything". Give the smallest input on which the result is wrong, and say what it returns.
4. Why does a tag written on a leaf do no harm, even though `push` writes such tags?
5. In the proof of @thm-21-visits, why can at most one node on a level contain position *l*? Does the argument need the nodes on a level to cover the whole array?
6. Why does `apply` in @lst-21-lazysum need *lo* and *hi* while `push` in @lst-21-lazymax does not?
7. A node of @lst-21-assignadd receives, in this order, add 3, set 2, add 4 and add −1, and no push happens in between. What single tag does it hold, and what is its maximum?
8. In the K-parts DP, why must dp[0][*i*] for *i* > 0 be −∞ when maximising? What would a 0 there allow?
9. Prove the key observation for Codeforces 1527E stated in @sec-21-recognise: why does the cost of exactly the split points *j* ≤ *p* change, and by how much?
10. For *n* = 35 000 and *K* = 50, how many inner steps does the baseline make, and roughly how many tree calls does the fast method make at most?

:::answers
1. A difference array pays O(1) per update, but a read of *a*[4] is a prefix sum of the differences, O(*n*). A lazy tree pays O(log *n*) for both. With *q* alternating updates and reads the difference array costs O(*q* *n*) and the lazy tree O(*q* log *n*).
2. It stores 3, the true maximum is 5. Its own tag +3 is already inside the 3 (and owed to its children); the tag +2 at its parent [4,7] has not been passed down, so 3 + 2 = 5.
3. With *n* = 2, `add(0, 1, 5)` covers the root, which gets value 5 and tag 5. Then `max(0, 0)` finds the root partial, goes to leaf [0] without pushing, and returns its stored 0 instead of 5. (The buggy version gave correct answers in 3000 random runs that used only point updates, because then only leaves ever carry tags.)
4. `push` runs only on partial nodes, and a leaf is never partial: its single position is either inside [*l*, *r*] (covered) or not (outside). So the code never reads a leaf's tag. The leaf's value `mx` is still correct relative to the tags above it.
5. The nodes on one level have pairwise disjoint ranges, so a position lies in at most one of them. The argument does not need them to cover the whole array (the deepest level of an unbalanced tree does not); disjointness is enough.
6. Adding *v* to every element of a range changes its sum by *v* times the number of elements, *hi* − *lo* + 1, and the node does not store its length. Adding *v* to every element changes the maximum by exactly *v*, whatever the length.
7. "set 5": add 3 then set 2 gives set 2; set 2 then add 4 gives set 6; then add −1 gives set 5. The node's maximum is 5, and so is every element below it once the tag is pushed (a run of the class confirmed max = 5 and the root tag "set 5").
8. dp[0][*i*] means "the first *i* elements split into zero parts", which is impossible for *i* > 0. A 0 there says that those *i* elements can be thrown away for free, so the DP may drop a prefix of the array. For the cost "minimum of the part", maximised, with *a* = [1, 9] and *K* = 1, the correct answer is 1, but with dp[0][1] = 0 the DP uses the split point *j* = 1 and returns 0 + 9 = 9 (both values from a run of the DP). With −∞ and the guard on additions, such states lose every comparison.
9. Let the new element *x* be at position *i* − 1 and its previous copy at *p*. A part *a*[*j*..*i* − 2] with *j* ≤ *p* contains *x*, and its last copy of *x* is at *p* (no copy lies between *p* and *i* − 1). Appending position *i* − 1 moves the last copy to *i* − 1 and leaves the first copy and all other values alone, so the cost grows by (*i* − 1) − *p*. A part with *j* > *p* contains no earlier copy, so after the append *x* occurs once and adds 0. Either way the change does not depend on *j* within the two ranges, so it is one range add of (*i* − 1) − *p* on [0, *p*]. A brute-force check over all splits of 4000 random arrays agreed with a DP built on this update.
10. The baseline: about 3.06 · 10¹⁰ inner steps (the exact count for *n* = 35 000, *K* = 50 is 30 583 019 600). The fast method: 50 layers × (3 · 35 000 + 1) operations × at most 63 calls ≈ 3.3 · 10⁸ calls.
:::

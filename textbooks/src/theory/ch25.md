## The paper as a document {#sec-25-paper}

The paper is a PDF on Infosys's recruitment site; the address is in the plan's notes for today and in the workbook's mock sheet. Download it before you start the timer and copy every sample input, with its expected output, into a text file.

It has four problems, labelled **Easy**, **Medium**, **Hard** and **Complex**. Each has a description, a function description, the constraints, the input and output formats, and three sample tests with explanations.

:::definition{#def-25-stub} Function stub
A [[function stub]] is the method header that a statement asks you to complete, such as `get_ans(...)` with fixed parameters and a fixed return type. The judge, or a `main` method supplied with the stub, reads the input and calls it.
:::

The plan's exam rules say to keep a stub's name, parameters and return type exactly as given. In OneCompiler nothing is supplied, so you write a `main` that reads the input and calls your `get_ans`. Keep all the logic inside that method; moving it to the real platform is then a copy and paste.

Table: {#tbl-25-paper} The four problems, paraphrased, with the plan's limits, difficulty estimates (Codeforces ratings) and time budget
| Problem | Limits | Level | Minutes |
|---|---|---|---|
| **Easy.** A rooted tree with a value on every node. For each node, count the pairs of nodes in its subtree whose values multiply to a perfect square; output the sum over all nodes modulo 10⁹ + 7. | *n* ≤ 10⁵, *a* ≤ 10⁹ | ~1800+ | 45 |
| **Medium.** Point updates on an array. After each update, decide whether some subsequence shorter than *n* has gcd exactly *p*; output how many updates were answered YES. | *n*, *q* ≤ 10⁵ | ~1800–2000 | 45 |
| **Hard.** The longest non-decreasing subsequence whose XOR is at least *M*. | *N* ≤ 1000, values ≤ *N* | ~1900–2100 | 60 |
| **Complex.** Flip a matching of tree edges to maximise the root-to-leaf paths that contain a query pattern, at minimum cost; output the sum of the costs over all queries. | *N*, *Q* ≤ 10⁵ | 2400+ | 30, partial marks |

### What the paper shows about the real assessment

The plan draws four lessons from the paper. None of them gives a solution away, so read them now.

**"Easy" is not LeetCode Easy.** The labels give the order within the paper. The plan puts even the Easy problem at about Codeforces 1800, which is why weeks 3 and 4 moved to LeetCode Hards and Codeforces 1600–2200.

**Trust the samples, not the format text.** Chapters 1 and 16 told you where this bites: in the Medium problem, the written input format and the samples disagree about the position of *p*. Run your input code on all three samples before you write any logic.

**Partial marks are real marks.** The reports in the plan say marks come from the tests you pass, so a brute force that is correct on small inputs scores on the small tests.

**Java traps.** Trees arrive as parent arrays with up to 10⁵ nodes, so a recursive depth-first search on a long chain throws `StackOverflowError`. Values up to 10⁹ multiply to 10¹⁸, which overflows `int` and only just fits in `long`.

The same reports describe the real round as three problems in three hours, worth 20, 30 and 50 marks; one 2026 candidate described about four problems. The sample paper has a fourth, and this book scores it separately as "partial".

:::infosys
The plan did not write a full solution to the Complex problem, because the PDF's own explanations for it contradict each other, so the samples cannot settle exactly what is asked. Its day notes say to attempt it only for partial marks. Treat it that way from the first minute.
:::

### One file per problem

OneCompiler compiles one file, `Main.java`, so the class must be `public class Main`. Put everything for a problem in that file: input reading, the fast solution, the brute force, a stress test and a timing test, with a constant that chooses what `main` does. @lst-25-mockfile shows the layout with the Hard problem's input. Its brute force is the fallback the plan already names (all subsequences by bitmask), so it gives nothing away.

```java {#lst-25-mockfile} One OneCompiler file per problem: read STDIN, stress-test, or time a large input
import java.io.*;
import java.util.*;

/** One OneCompiler file per problem (here: the Hard problem's input). MODE picks what main does. */
public class Main {
    static final int MODE = 0;            // 0 = read STDIN, 1 = stress test, 2 = time a large input

    public static void main(String[] args) throws IOException {
        if (MODE == 1) { stress(); return; }
        if (MODE == 2) { timeLarge(); return; }
        FastScanner fs = new FastScanner(System.in);
        int n = fs.nextInt();                          // N, then M, then N values
        int m = fs.nextInt();
        int[] a = new int[n];
        for (int i = 0; i < n; i++) a[i] = fs.nextInt();
        System.out.println(solve(a, m));
    }

    static int solve(int[] a, int m) {                 // your fast solution goes here
        return brute(a, m);
    }

    static int brute(int[] a, int m) {                 // every subsequence: O(2^N * N)
        int n = a.length, best = 0;
        if (n > 24) throw new IllegalArgumentException("brute force needs N <= 24");
        for (int mask = 1; mask < (1 << n); mask++) {
            int last = 0, x = 0, len = 0;
            boolean ok = true;
            for (int i = 0; i < n && ok; i++) {
                if ((mask >> i & 1) == 0) continue;
                if (a[i] < last) ok = false;           // not non-decreasing
                last = a[i];
                x ^= a[i];
                len++;
            }
            if (ok && x >= m) best = Math.max(best, len);
        }
        return best;
    }

    static void stress() {                             // Chapter 9's stress loop
        Random rnd = new Random(1);
        for (int it = 1; it <= 20000; it++) {
            int n = 1 + rnd.nextInt(10);
            int[] a = new int[n];
            for (int i = 0; i < n; i++) a[i] = 1 + rnd.nextInt(n);   // 1 <= A[i] <= N
            int m = 1 + rnd.nextInt(2 * n + 2);
            int fast = solve(a, m), slow = brute(a, m);
            if (fast != slow) {
                System.out.println("Mismatch: " + Arrays.toString(a) + " M=" + m);
                System.out.println("fast=" + fast + "  brute=" + slow);
                return;
            }
        }
        System.out.println("All random tests passed");
    }

    static void timeLarge() {                          // the largest input, built in memory
        int n = 1000;
        int[] a = new int[n];
        Random rnd = new Random(2);
        for (int i = 0; i < n; i++) a[i] = 1 + rnd.nextInt(n);
        long t0 = System.nanoTime();
        int ans = solve(a, n / 2);
        System.out.println(ans + " in " + (System.nanoTime() - t0) / 1000000 + " ms");
    }

    static final class FastScanner {                   // Chapter 1's reader
        private final BufferedReader br;
        private StringTokenizer st;

        FastScanner(InputStream in) { br = new BufferedReader(new InputStreamReader(in)); }

        String next() throws IOException {
            while (st == null || !st.hasMoreTokens()) {
                String line = br.readLine();
                if (line == null) return null;
                st = new StringTokenizer(line);
            }
            return st.nextToken();
        }

        int nextInt() throws IOException { return Integer.parseInt(next()); }
    }
}
```

With `MODE = 0` and the brute force as `solve`, the file prints 2, 1 and 4 on the three Hard samples, the expected outputs. Switch to `MODE = 1` once you have a fast `solve`, and to `MODE = 2` to time it on an input built in memory, which saves pasting thousands of lines into the STDIN box.

:::java
The guard `n > 24` matters for a second reason. Java uses only the lowest five bits of an `int` shift distance, so `1 << 1000` is `1 << 8` = 256. A bitmask loop run by mistake on a large input returns a wrong answer quickly, with no warning. The exception makes the mistake visible.
:::

Only the reader, the generator and the large input change from problem to problem. For Easy, time a chain of 10⁵ nodes (the shape that breaks recursion) and a star (the root has 10⁵ − 1 children). For Medium, time *n* = *q* = 10⁵ with random updates.

### Grading yourself

The plan's instruction is to grade with the samples plus a stress test against your own brute force, and only then to read the walkthroughs. Without hidden tests, the share of tests you would pass has to be estimated.

:::definition{#def-25-share} Estimated share of tests
The [[estimated share of tests]] of a problem is your estimate, between 0 and 1, of the fraction of the hidden tests your final program would pass. The final program is the last version you ran on the samples before time ran out.
:::

To keep Mock 4 comparable with the Codeforces mocks, use one fixed convention. @tbl-25-grade is this book's convention, not an Infosys rule.

Table: {#tbl-25-grade} A convention for grading a problem without a judge
| What your final program does | Share |
|---|---|
| passes the samples, agrees with your brute force on 10,000 tiny random inputs, and finishes the largest inputs (for trees, a chain and a star) in about a second | 100 % |
| the same, but too slow on the largest inputs | 50 % |
| only a brute force is correct: the fast version is missing, or the stress test found a mismatch and you fall back to the brute force | 20 % |
| fails a sample, or disagrees with the brute force and nothing correct is left | 0 % |

"About a second" uses Chapter 9's planning figure of roughly 10⁸ simple operations per second. The weighted score is 20 × Easy + 30 × Medium + 50 × Hard: Easy fully correct and brute forces for the other two give 20 + 6 + 10 = 36. Record Complex in its own column as partial. The plan sets no score target for Mock 4; its checkpoint is the order of work: grade first, compare afterwards.

:::pitfall
A stress test is only as good as its generator. Random values up to 10⁹ almost never multiply to a perfect square, so a uniform generator for the Easy problem tests little except the answer 0. Draw values from a small range or build related values on purpose, and check that the brute force's answers are not all zero. In the Medium problem, make many values multiples of *p*.
:::

## Reading the four statements {#sec-25-read}

Chapter 16 described the first fifteen minutes: strip the story and write down the objects, the question type, the limits and the brute force. This section does that for each problem and stops where the idea would begin. It also gives the largest input on which each brute force finished in about a second on the machine used for this book, which is what the fallback is worth.

### Easy: tree beauty

The plan lists it as *Sample paper · Easy (tree beauty)*. A rooted tree of up to 10⁵ nodes comes as a parent array with root 1, with a value up to 10⁹ on each node. beauty(*u*) counts the unordered pairs of distinct nodes in the subtree of *u* whose values multiply to a perfect square, and the answer is the sum of all beauties modulo 10⁹ + 7. A pair is counted once in every subtree that contains both of its nodes. Use the second sample to confirm that a node does not pair with itself.

A brute force collects each subtree with an explicit stack and tests every pair. Two details make it correct: the product needs `long`, and `Math.sqrt` on a `double` (53 bits) can be off by one near 10¹⁸, so correct the root with two `while` loops before squaring it. Its cost is the sum of the squared subtree sizes, about *n*³/3 on a chain. It took 0.63 s on a chain of 1,000 nodes and 2.1 s on 1,500; a random tree of 10⁴ nodes took 0.46 s. A full solution must do about O(*n* log *n*) work on 10⁵ nodes, without recursion.

### Medium: gcd under updates

The plan lists it as *Sample paper · Medium (gcd under updates)*. An array of up to 10⁵ values, each at most 10⁵, receives up to 10⁵ updates "set position *i* to *j*". After each one, decide whether some non-empty subsequence of length less than *n* has gcd exactly *p*, and count the YES answers.

The gcd ignores order, so "subsequence" means any non-empty set of positions; "length less than *n*" excludes only the whole array; "exactly *p*" excludes 2*p*. For *n* = 1 every answer is NO. The brute force tries all 2ⁿ − 2 proper subsets after each update, about *q* · 2ⁿ · *n* steps. With 100 updates all answered NO (its slowest case) it took 0.42 s for *n* = 16 and 1.75 s for *n* = 18. A full solution can afford about O(log *n*) work per update.

### Hard: LNDS with XOR ≥ M

The plan lists it as *Sample paper · Hard (LNDS with XOR ≥ M)*. Given *N* ≤ 1000 values between 1 and *N* and a number *M*, find the longest subsequence that is non-decreasing (equal neighbours allowed) and whose elements XOR to at least *M*; print 0 if none does. The XOR is over all chosen elements, as the third sample shows: the whole array 1, 2, 3, 4 qualifies, with XOR 4.

The brute force is the bitmask loop of @lst-25-mockfile, O(2ᴺ · *N*). On a sorted array, its worst case, it took 0.22 s for *N* = 22 and 0.89 s for *N* = 24, in line with the plan's "fine up to *N* ≈ 20". For a full solution, *N* = 1000 is small for this paper: O(*N*²) is only 10⁶ steps, and 10⁷ to 10⁸ simple steps still fit. Write down every limit in the statement before you look for an idea.

### Complex: tree edge flipping

The plan lists it as *Sample paper · Complex (partial marks only)*. A tree of *N* ≤ 10⁵ nodes rooted at 0 has a binary value on each node. You may flip a set of parent–child edges no two of which share a node; a flip toggles both ends and costs *M*. For each of *Q* binary patterns, maximise the number of root-to-leaf paths that contain the pattern as a contiguous substring, then minimise the cost; output the sum of the minimum costs.

The plan rates it 2400+ and suggests a brute force for *N* ≤ 15: try every allowed set of edges and test each root-to-leaf path with `String.contains`. Check that your reader consumes exactly the lines of each sample, fix one reading of the statement and keep it, and give this problem only the time the other three leave.

### Easy: square-free kernels and small-to-large maps

The condition "*xy* is a perfect square" involves two values at once. The key step replaces it by equality of one number computed from each value.

:::definition{#def-25-kernel} Square-free kernel
The [[square-free kernel]] ker(*x*) of a positive integer *x* is the product of the primes that appear in *x* with an odd exponent. For example ker(12) = ker(2² · 3) = 3, ker(27) = ker(3³) = 3 and ker(2) = 2.
:::

:::lemma{#lem-25-kernel} Square products and kernels
For positive integers *x* and *y*, the product *xy* is a perfect square if and only if ker(*x*) = ker(*y*).
:::

:::proof
Write *e*ₚ(*z*) for the exponent of the prime *p* in *z*. A positive integer *z* is a perfect square exactly when every *e*ₚ(*z*) is even: if *z* = *s*², each exponent of *z* is twice one of *s*; if every exponent is even, *s* = Π *p*^(*e*ₚ(*z*)/2) satisfies *s*² = *z*, and the factorisation is unique by the fundamental theorem of arithmetic. Since *e*ₚ(*xy*) = *e*ₚ(*x*) + *e*ₚ(*y*), and a sum of two integers is even exactly when they have the same parity, *xy* is a square exactly when, for every prime, *e*ₚ(*x*) and *e*ₚ(*y*) have the same parity: when *x* and *y* have the same set of primes with odd exponent. The kernel is the product of that set, and two products of distinct primes are equal exactly when the sets are equal.
:::

So beauty(*u*) counts the pairs of nodes with **equal kernels** in the subtree of *u*: a kernel occurring *c* times there contributes *c*(*c* − 1)/2. That is the equal-key pair count of Chapter 19, with the kernel as the key.

Values reach 10⁹, too far for a sieve. Chapter 10 computed the kernel anyway by dividing out the 168 primes below 1000.

:::claim{#thm-25-cofactor} The cofactor of a value up to 10⁹
Let *y* be what remains of *x* ≤ 10⁹ after every prime below 1000 is divided out completely. Then *y* is 1, a prime *q*, a square *q*² or a product *qr* of two distinct primes, with *q*, *r* > 1000, and it contributes *y* to ker(*x*) unless *y* is a perfect square, when it contributes 1.
:::

:::proof
Every prime factor of *y* is at least 1009, the smallest prime above 1000. Three of them would give *y* ≥ 1009³ = 1,027,243,729 > 10⁹, so *y* has at most two prime factors counted with multiplicity: the four shapes. In *q* and *qr* every exponent is odd, so they stay in the kernel; in 1 and *q*² every exponent is even, so they drop out. Of the four shapes, exactly 1 and *q*² are perfect squares.
:::

The listing's `kernel` also stops early once *p*² exceeds what is left; the remainder is then 1 or a prime, and the same square test handles it.

Each node keeps a map from kernel to count. Nodes are processed in reverse BFS order, so every child is finished before its parent, and the child's map is merged into the parent's by [[small-to-large merging]]: the map with fewer keys is poured into the one with more. When a key that one map holds *b* times meets *c* copies in the other, *b* · *c* new pairs appear.

:::claim{#thm-25-merge} The merges count every pair once
When the backward loop reaches node *v*, `pairs[v]` equals beauty(*v*) and `mp[v]` holds the count of every kernel in the subtree of *v*.
:::

:::proof
By induction along the backward loop. Each map starts as {ker(*a*[*v*]): 1}. Every child *c* of *v* follows *v* in BFS order, so the backward loop finishes it first and, by induction, merges the kernel counts of its subtree into *v*'s map and adds beauty(*c*) to `pairs[v]`. A merge adds, for every key, the product of its counts in the two maps: exactly the equal-kernel pairs with one node in each map. Now take two nodes of *v*'s subtree with equal kernels. If both lie in one child's subtree, the pair is part of that child's beauty and is added once. Otherwise they lie in two different parts among {*v*}, subtree(*c*₁), subtree(*c*₂), …, and the pair is counted at the merge in which the later of the two parts joins *v*'s map, and at no other, since afterwards both nodes are in one map. Swapping which map is iterated does not change the products.
:::

Chapter 19 proved that small-to-large merging moves O(*n* log *n*) entries in total even when keys repeat, so the merges take O(*n* log *n*) expected time with `HashMap`; the kernels cost at most 168 divisions each, about 1.7 · 10⁷ in all. The modulus is taken once at the end, which is safe: there are *n* beauties of at most *n*(*n* − 1)/2 each, about 5.0 · 10¹⁴ in total, far below the `long` limit of 9.2 · 10¹⁸.

```java {#lst-25-easy} Easy: sum of beauty over all nodes (the plan's walkthrough program)
import java.io.*;
import java.util.*;

/**
 * Infosys sample paper, EASY: sum over u of
 * (# pairs in subtree(u) whose product is a perfect square).
 */
public class Main {
    static final long MOD = 1_000_000_007L;
    static int[] smallPrimes;

    public static void main(String[] args) throws IOException {
        FastReader in = new FastReader(System.in);
        int n = in.nextInt();
        int[] par = new int[n + 1];
        for (int v = 1; v <= n; v++) par[v] = in.nextInt();
        long[] a = new long[n + 1];
        for (int v = 1; v <= n; v++) a[v] = in.nextLong();
        System.out.println(solve(n, par, a));
    }

    static long solve(int n, int[] par, long[] a) {
        buildSmallPrimes();
        // children lists + BFS order (no recursion: a 1e5 chain would overflow the stack)
        int[] head = new int[n + 1], nxt = new int[n + 1];
        Arrays.fill(head, -1);
        int root = 1;
        for (int v = 1; v <= n; v++) {
            if (par[v] == 0) root = v;
            else { nxt[v] = head[par[v]]; head[par[v]] = v; }
        }
        int[] order = new int[n];
        int qh = 0, qt = 0;
        order[qt++] = root;
        while (qh < qt) {
            int u = order[qh++];
            for (int c = head[u]; c != -1; c = nxt[c]) order[qt++] = c;
        }

        @SuppressWarnings("unchecked")
        HashMap<Long, Integer>[] mp = new HashMap[n + 1];
        long[] pairs = new long[n + 1];
        for (int v = 1; v <= n; v++) { mp[v] = new HashMap<>(); mp[v].put(kernel(a[v]), 1); }

        long ans = 0;
        for (int i = n - 1; i >= 0; i--) {          // children are finished before their parent
            int v = order[i];
            ans += pairs[v];                          // beauty(v) is final now
            int p = par[v];
            if (p == 0) continue;
            HashMap<Long, Integer> big = mp[p], small = mp[v];
            if (big.size() < small.size()) { HashMap<Long, Integer> t = big; big = small; small = t; }
            long cross = 0;
            for (Map.Entry<Long, Integer> e : small.entrySet()) {
                int have = big.getOrDefault(e.getKey(), 0);
                cross += (long) have * e.getValue();
                big.put(e.getKey(), have + e.getValue());
            }
            pairs[p] += pairs[v] + cross;
            mp[p] = big;
            mp[v] = null;
        }
        return ans % MOD;
    }

    /** Square-free kernel: x*y is a perfect square  <=>  kernel(x) == kernel(y). */
    static long kernel(long x) {
        long k = 1;
        for (int p : smallPrimes) {                  // primes <= 1000 only (168 of them)
            if ((long) p * p > x) break;
            int e = 0;
            while (x % p == 0) { x /= p; e ^= 1; }
            if (e == 1) k *= p;
        }
        // x has no prime factor <= 1000 left (or x < p*p, so x is 1 or prime)
        // x <= 1e9 < 1009^3, so x is 1, q, q*q or q*r for primes q, r > 1000
        long s = (long) Math.sqrt((double) x);
        while (s * s > x) s--;
        while ((s + 1) * (s + 1) <= x) s++;
        if (s * s != x) k *= x;                      // q or q*r stays in the kernel; q*q vanishes
        return k;
    }

    static void buildSmallPrimes() {
        if (smallPrimes != null) return;
        List<Integer> ps = new ArrayList<>();
        for (int i = 2; i <= 1000; i++) {
            boolean pr = true;
            for (int d = 2; d * d <= i; d++) if (i % d == 0) { pr = false; break; }
            if (pr) ps.add(i);
        }
        smallPrimes = ps.stream().mapToInt(Integer::intValue).toArray();
    }

    static final class FastReader {
        private final DataInputStream in;
        private final byte[] buf = new byte[1 << 16];
        private int len, ptr;
        FastReader(InputStream is) { in = new DataInputStream(is); }
        private int read() throws IOException {
            if (ptr == len) { len = in.read(buf, 0, buf.length); ptr = 0; if (len <= 0) return -1; }
            return buf[ptr++];
        }
        long nextLong() throws IOException {
            int c = read();
            while (c != '-' && (c < '0' || c > '9')) {
                if (c == -1) throw new EOFException();
                c = read();
            }
            boolean neg = c == '-'; if (neg) c = read();
            long r = 0; while (c >= '0' && c <= '9') { r = r * 10 + (c - '0'); c = read(); }
            return neg ? -r : r;
        }
        int nextInt() throws IOException { return (int) nextLong(); }
    }
}

### Medium: the gcd-exactly-*p* lemma and a gcd segment tree

The question ranges over 2ⁿ subsets. One lemma reduces it to a single gcd and a count.

:::lemma{#lem-25-gcd} When a good subsequence exists
Let *S* be the set of positions whose value is a multiple of *p*, and *g* the gcd of the values at *S* (*g* = 0 if *S* is empty). A good subsequence exists if and only if *g* = *p* and either some position is outside *S*, or *S* is every position and some *n* − 1 of the values have gcd *p*.
:::

:::proof
Every element of a good subsequence is divisible by its gcd *p*, so it uses only positions in *S*. Its gcd is a multiple of *g*, since *g* divides every value in *S*; and *p* divides *g*, since *p* divides every value in *S*. So if a good subsequence exists, *g* divides *p* and *p* divides *g*, hence *g* = *p*; when *g* ≠ *p* (including *g* = 0) the answer is NO.

Let *g* = *p*. If some position lies outside *S*, then *S* itself is non-empty, shorter than *n* and has gcd *p*. If *S* is every position, a good subsequence is a non-empty set *T* of fewer than *n* positions with gcd *p*. Any set *U* of *n* − 1 positions containing *T* has a gcd that divides gcd(*T*) = *p* and is a multiple of *p*, so it equals *p*. Hence a good subsequence exists exactly when some *n* − 1 positions have gcd *p*. (For *n* = 1 that set would be empty, so the answer is NO.)
:::

There are *n* sets of *n* − 1 positions, but the bound on the values makes the check unnecessary except for tiny arrays.

:::theorem{#thm-25-seven} Seven elements suffice
If every value is a multiple of *p* and at most 10⁵, and the gcd of all values is *p*, then some at most seven of the values already have gcd *p*. So when *n* ≥ 8, the answer is YES.
:::

:::proof
Divide every value by *p*: the quotients *b*ᵢ are at most 10⁵ and have gcd 1. Pick one, *b*ⱼ, with distinct prime factors *q*₁, …, *q*ₖ. Then *k* ≤ 6, because seven distinct primes multiply to at least 2 · 3 · 5 · 7 · 11 · 13 · 17 = 510,510 > 10⁵. For each *q*ₜ some quotient *b*ⱼₜ is not divisible by *q*ₜ, or *q*ₜ would divide the gcd of all of them, which is 1. Let *T* be *j* together with the positions *j*ₜ: at most seven positions. The gcd over *T* divides *b*ⱼ, so its prime factors are among the *q*ₜ, and none of them divides it, because *q*ₜ does not divide *b*ⱼₜ. So the quotients over *T* have gcd 1 and the values over *T* have gcd *p*. If *n* ≥ 8, *T* has fewer than *n* positions and is a good subsequence.
:::

Small arrays do need the drop-one check. The quotients 15015, 10010, 6006, 4290, 2730 and 2310 (30030 divided by each of 2, 3, 5, 7, 11 and 13) have gcd 1, but every five of them share a prime.

A [[gcd segment tree]] maintains *g*: each leaf holds its value if that is a multiple of *p* and **0** otherwise. Because gcd(0, *x*) = *x* (Chapter 10), a 0 leaf behaves as if the position were absent (Chapter 20), so the root is exactly *g*. A counter `notDiv` tracks the positions outside *S*. An update rewrites one leaf and its ancestors and adjusts the counter; the decision is then four lines that follow @lem-25-gcd and @thm-25-seven.

import java.io.*;
import java.util.*;

/**
 * Infosys sample paper, MEDIUM: after each point update, does a non-empty subsequence
 * of length < n with gcd exactly p exist? Count YES answers.
 * NOTE: the samples put p BEFORE the array (the PDF's written format says after it).
 */
public class Main {
    public static void main(String[] args) throws IOException {
        FastReader in = new FastReader(System.in);
        int n = in.nextInt();
        int p = in.nextInt();
        int[] a = new int[n];
        for (int i = 0; i < n; i++) a[i] = in.nextInt();
        int q = in.nextInt();
        int cols = in.nextInt();                    // always 2, read and ignore
        int[][] qs = new int[q][2];
        for (int i = 0; i < q; i++) { qs[i][0] = in.nextInt(); qs[i][1] = in.nextInt(); }
        System.out.println(solve(n, p, a, qs));
    }

    static long solve(int n, int p, int[] a, int[][] qs) {
        a = a.clone();
        int size = 1; while (size < n) size <<= 1;
        // gcd of elements divisible by p (others stored as 0)
        int[] t = new int[2 * size];
        int notDiv = 0;
        for (int i = 0; i < n; i++) {
            if (a[i] % p == 0) t[size + i] = a[i]; else notDiv++;
        }
        for (int i = size - 1; i > 0; i--) t[i] = gcd(t[2 * i], t[2 * i + 1]);

        long yes = 0;
        for (int[] qu : qs) {
            int i = qu[0] - 1, v = qu[1];
            if (a[i] % p != 0) notDiv--;
            a[i] = v;
            if (a[i] % p != 0) notDiv++;
            int pos = size + i;
            t[pos] = (a[i] % p == 0) ? a[i] : 0;
            for (pos >>= 1; pos > 0; pos >>= 1) t[pos] = gcd(t[2 * pos], t[2 * pos + 1]);

            int g = t[1];                            // gcd of all multiples of p (0 if none)
            boolean ok;
            if (g != p) ok = false;                  // every subset gcd is a multiple of g
            else if (notDiv > 0) ok = true;          // take all multiples: length < n
            // a/p <= 1e5 has <= 6 primes -> gcd-1 subset of size <= 7
            else if (n >= 8) ok = true;
            else ok = existsDropOne(a, p);           // n <= 7: try removing each element
            if (ok) yes++;
        }
        return yes;
    }

    static boolean existsDropOne(int[] a, int p) {
        int n = a.length;
        for (int skip = 0; skip < n; skip++) {
            int g = 0;
            for (int j = 0; j < n; j++) if (j != skip) g = gcd(g, a[j]);
            if (g == p) return true;
        }
        return false;
    }

    static int gcd(int x, int y) { while (y != 0) { int r = x % y; x = y; y = r; } return x; }

    static final class FastReader {
        private final DataInputStream in;
        private final byte[] buf = new byte[1 << 16];
        private int len, ptr;
        FastReader(InputStream is) { in = new DataInputStream(is); }
        private int read() throws IOException {
            if (ptr == len) { len = in.read(buf, 0, buf.length); ptr = 0; if (len <= 0) return -1; }
            return buf[ptr++];
        }
        long nextLong() throws IOException {
            int c = read();
            while (c != '-' && (c < '0' || c > '9')) {
                if (c == -1) throw new EOFException();
                c = read();
            }
            boolean neg = c == '-'; if (neg) c = read();
            long r = 0; while (c >= '0' && c <= '9') { r = r * 10 + (c - '0'); c = read(); }
            return neg ? -r : r;
        }
        int nextInt() throws IOException { return (int) nextLong(); }
    }
}

### Hard: an extra DP dimension for the XOR

The longest non-decreasing subsequence keeps the best length for each last value (Chapter 13) and forgets the XOR, which decides whether a subsequence counts. The bound on the values makes the XOR cheap to remember.

:::lemma{#lem-25-xorbound} XOR stays below a power of two
If every value is less than *B* = 2ᵏ, the XOR of any of them is less than *B*.
:::

:::proof
A number below 2ᵏ has no set bit at position *k* or higher. XOR sets a bit only where an odd number of operands have it, so the result has none there either.
:::

Values are at most *N* ≤ 1000 < 1024, so every XOR lies in 0..1023, an [[extra state dimension]] with at most 1024 states. For each XOR value *x*, `fw[x]` is a Fenwick tree of maxima over the values 1..maxV (Chapter 13): position *w* holds the longest subsequence found so far with XOR *x* and last element *w*, so a prefix query up to *v* returns the best one ending in a value at most *v*.

:::theorem{#thm-25-xordp} Invariant of the XOR DP
Let *L*ᵢ(*x*, *v*) be the largest length of a non-decreasing subsequence of *a*[0..*i* − 1] with XOR *x* and last element at most *v* (0 if none). After the loop has processed *a*[0..*i* − 1], `query(fw[x], v)` = *L*ᵢ(*x*, *v*) for all *x* < *B* and all *v*. So after all *N* elements, the answer is the largest `query(fw[x], maxV)` with *x* ≥ *M*.
:::

:::proof
By induction on *i*. At the start all trees are empty and all *L*₀ are 0. Let *v* = *a*[*i*]. A non-decreasing subsequence ending at index *i* with XOR *x* is either *a*[*i*] alone, when *x* = *v*, or a non-decreasing subsequence of *a*[0..*i* − 1] with last element at most *v* and XOR *x* ⊕ *v*, followed by *a*[*i*]. So the longest has length *E*(*x*) = the larger of 1 (if *x* = *v*) and *L*ᵢ(*x* ⊕ *v*, *v*) + 1 (if that *L* is positive), or 0 if neither applies. The first inner loop computes `cand[x]` = *E*(*x*) for every *x* from the trees as they were before index *i*, which hold *L*ᵢ by the hypothesis. The subsequences of *a*[0..*i*] are those of *a*[0..*i* − 1] and those ending at *i*, so *L*ᵢ₊₁(*x*, *w*) = max(*L*ᵢ(*x*, *w*), *E*(*x*) if *v* ≤ *w*). The second loop raises position *v* of `fw[x]` to `cand[x]`, and a prefix query up to *w* includes position *v* exactly when *v* ≤ *w*. So the invariant holds after index *i*.
:::

The proof needs every `cand` computed before any tree is written. Writing inside the first loop lets one query read an entry that already ends with *a*[*i*], because a non-decreasing query up to *v* includes position *v*, and extend it by *a*[*i*] again. On [1, 1] with *M* = 1 such a version returns 3, a subsequence of three 1s from an array with two.

```java {#lst-25-hard} Hard: longest non-decreasing subsequence with XOR at least M (the plan's walkthrough program)
import java.io.*;
import java.util.*;

/** Infosys sample paper, HARD: longest non-decreasing subsequence whose XOR is >= M. */
public class Main {
    public static void main(String[] args) throws IOException {
        FastReader in = new FastReader(System.in);
        int n = in.nextInt();
        int m = in.nextInt();
        int[] a = new int[n];
        for (int i = 0; i < n; i++) a[i] = in.nextInt();
        System.out.println(solve(a, m));
    }

    // fw[x] = Fenwick over values; prefix max of "longest subsequence with XOR x ending in value <= v"
    static int solve(int[] a, int m) {
        int maxV = 1;
        for (int x : a) maxV = Math.max(maxV, x);
        int B = 1;
        while (B <= maxV) B <<= 1;                   // every XOR of values <= maxV is < B
        int[][] fw = new int[B][maxV + 1];
        int[] cand = new int[B];
        for (int v : a) {
            for (int x = 0; x < B; x++) {
                int best = query(fw[x ^ v], v);      // extend a subsequence whose XOR was x ^ v
                cand[x] = best > 0 ? best + 1 : 0;
            }
            cand[v] = Math.max(cand[v], 1);          // start a new subsequence with v alone
            for (int x = 0; x < B; x++) if (cand[x] > 0) update(fw[x], v, cand[x]);
        }
        int ans = 0;
        for (int x = m; x < B; x++) ans = Math.max(ans, query(fw[x], maxV));
        return ans;
    }

    static int query(int[] f, int i) {
        int r = 0;
        for (; i > 0; i -= i & -i) r = Math.max(r, f[i]);
        return r;
    }

    static void update(int[] f, int i, int v) {
        for (; i < f.length; i += i & -i) if (f[i] < v) f[i] = v;
    }

    static final class FastReader {
        private final DataInputStream in;
        private final byte[] buf = new byte[1 << 16];
        private int len, ptr;
        FastReader(InputStream is) { in = new DataInputStream(is); }
        private int read() throws IOException {
            if (ptr == len) { len = in.read(buf, 0, buf.length); ptr = 0; if (len <= 0) return -1; }
            return buf[ptr++];
        }
        long nextLong() throws IOException {
            int c = read();
            while (c != '-' && (c < '0' || c > '9')) {
                if (c == -1) throw new EOFException();
                c = read();
            }
            boolean neg = c == '-'; if (neg) c = read();
            long r = 0; while (c >= '0' && c <= '9') { r = r * 10 + (c - '0'); c = read(); }
            return neg ? -r : r;
        }
        int nextInt() throws IOException { return (int) nextLong(); }
    }
}

### Complex: partial marks with a brute force over matchings

:::definition{#def-25-matching} Matching
A [[matching]] in a tree is a set of edges no two of which share a node. The Complex problem lets you flip the edges of one matching.
:::

Following the plan, @lst-25-complex enumerates the matchings for *N* ≤ 15, applies the flips and tests every root-to-leaf path with `String.contains`. It backtracks over the edges (*Parent*[*v*], *v*) for *v* = 1, …, *N* − 1 and adds an edge only when both ends are free, so it builds only matchings (Chapter 22): a path of 15 nodes has 987 of them among 2¹⁴ = 16,384 edge subsets.

```java {#lst-25-complex} Complex, partial marks only: every matching, every root-to-leaf path (follows the written statement)
static int n;
static int[] par, val, flip;
static boolean[] used, isLeaf;
static String[] qs;
static int[] bestCount, bestFlips;

// Sum over queries of M * (fewest flips among the matchings that maximise the natural paths). N <= 15.
static long complexBrute(int nn, long m, int[] parent, int[] value, String[] queries) {
    n = nn; par = parent; val = value; qs = queries;
    isLeaf = new boolean[n];
    Arrays.fill(isLeaf, true);
    for (int v = 1; v < n; v++) isLeaf[par[v]] = false;
    used = new boolean[n];
    flip = new int[n];
    bestCount = new int[qs.length];
    Arrays.fill(bestCount, -1);
    bestFlips = new int[qs.length];
    choose(1, 0);
    long total = 0;
    for (int j = 0; j < qs.length; j++) total += m * bestFlips[j];
    return total;
}

static void choose(int v, int flips) {             // decide the edge (par[v], v)
    if (v == n) { evaluate(flips); return; }
    choose(v + 1, flips);                           // do not flip it
    int u = par[v];
    if (!used[u] && !used[v]) {                     // flip it: both ends must be free
        used[u] = used[v] = true;
        flip[u] ^= 1; flip[v] ^= 1;
        choose(v + 1, flips + 1);
        flip[u] ^= 1; flip[v] ^= 1;
        used[u] = used[v] = false;
    }
}

static void evaluate(int flips) {                   // one matching: count natural paths per query
    int[] count = new int[qs.length];
    for (int leaf = 0; leaf < n; leaf++) {
        if (!isLeaf[leaf]) continue;
        StringBuilder sb = new StringBuilder();
        for (int x = leaf; ; x = par[x]) {
            sb.append((char) ('0' + (val[x] ^ flip[x])));
            if (x == 0) break;
        }
        String path = sb.reverse().toString();      // root first
        for (int j = 0; j < qs.length; j++) if (path.contains(qs[j])) count[j]++;
    }
    for (int j = 0; j < qs.length; j++)
        if (count[j] > bestCount[j] || (count[j] == bestCount[j] && flips < bestFlips[j])) {
            bestCount[j] = count[j];
            bestFlips[j] = flips;
        }
}
```

The listing fixes one reading of the statement: every query starts from the original values, and a leaf is a node without children. It matched a second brute force, which enumerates all edge subsets and discards the non-matchings, on 3,000 random trees of up to 10 nodes, and took 9–20 ms for 15 nodes and 1,000 queries. If it disagrees with a sample, the plan's finding applies: the samples cannot settle every rule, so record the problem as partial and stop. For operations that change both ends of an edge, the plan's practice problem is LeetCode 3068 (Find the Maximum Sum of Node Values) from Day 19.

## What the paper teaches for the exam {#sec-25-lessons}

Side by side, the three solved problems have the same shape: a short mathematical step, then a template you already had.

Table: {#tbl-25-lessons} The step, the template, and the limit that made the step work
| Mathematical step | Template | Limit used | Brute force in ~1 s |
|---|---|---|---|
| **Easy:** *xy* square ⇔ equal kernels (@lem-25-kernel) | small-to-large maps (Chapter 19) | values ≤ 10⁹ < 1009³ | chain of 1,000 nodes |
| **Medium:** conditions on the multiples of *p* (@lem-25-gcd); seven elements suffice | gcd tree with 0 at ignored positions (Chapter 20) | values ≤ 10⁵ < 510,510 | *n* = 16, 100 updates |
| **Hard:** XOR stays below 1024 (@lem-25-xorbound) | Fenwick tree of maxima per state (Chapter 13) | values ≤ *N* ≤ 1000 | *N* = 24 |

**The step is the hard part.** No template was new on Day 25, and the statement never names one. Each condition had to be rewritten first: a condition on pairs became equality of a key, a condition on all subsets became one gcd and a count, a condition on the whole subsequence became a small state. When a condition looks too complex to count, ask what single number per element, per set or per prefix would decide it.

**Limits are hints.** Every step used a bound that looks arbitrary in the statement. When a limit looks unusual, ask what it makes small.

**Input is part of the problem.** The samples, not the format text, fixed the Medium input, including a line to read and ignore.

## Summary

- The official sample paper has four problems (Easy, Medium, Hard, Complex) with a `get_ans` function description, one value per input line and three samples each; the plan estimates them at Codeforces 1800 to 2400+.
- Its lessons: the labels are not LeetCode levels; trust the samples over the format text; partial marks count; avoid recursion on parent-array trees and use `long` for products.
- Run the mock in OneCompiler with one file per problem that can read STDIN, stress-test against a brute force, or time a large input built in memory, and grade with a fixed convention before reading any solution.
- Easy: *xy* is a perfect square exactly when ker(*x*) = ker(*y*); for values up to 10⁹, divide out the 168 primes below 1000 and keep the cofactor unless it is a square; count equal kernels per subtree with small-to-large maps in reverse BFS order.
- Medium: a good subsequence exists exactly when the gcd of the multiples of *p* equals *p* and some value is not a multiple, or *n* ≥ 8, or dropping one element keeps gcd *p*; a gcd tree with 0 at ignored positions and a counter answer each update in O(log *n*).
- Hard: XORs of values below 1024 stay below 1024, so the XOR becomes a DP dimension with one Fenwick tree of maxima per XOR value; compute every candidate before writing any.
- Complex: a backtracking search over matchings with `String.contains` collects the small tests.
- Each solution was a mathematical step plus a known template, and each step used a limit of the statement.

## Review questions

1. The radical of a number is the product of its distinct prime factors. Why is it the wrong key for the Easy problem? Give two numbers with the same radical whose product is not a perfect square.
2. Why does the kernel code ask whether the cofactor is a perfect square, not whether it is prime?
3. @lst-25-easy takes the modulus only once, at the end. Why can the sum not overflow a `long` first?
4. Why is the Medium answer always NO when *n* = 1, and which part of @lst-25-medium makes the program agree?
5. What does @lst-25-medium answer for the array 15015, 10010, 6006, 4290, 2730, 2310 with *p* = 1? Does that contradict @thm-25-seven?
6. Why must the Hard DP compute `cand` for every XOR value before writing to any tree? Give an input where writing immediately is wrong.
7. The Hard listing indexes its Fenwick trees by value, with no compression. Why is that possible, and what would fail if values could reach 10⁹?
8. Your Medium program passes all three samples, but the stress tester finds a mismatch on an array of length 1. What do you record under @tbl-25-grade if your brute force is correct, and why?

:::answers
1. A square needs every exponent even, and the radical forgets the exponents. 20 = 2² · 5 and 50 = 2 · 5² both have radical 10, but 20 · 50 = 1000 is not a perfect square; their kernels are 5 and 2.
2. The cofactor is 1, *q*, *q*² or *qr* (@thm-25-cofactor). *qr* is not prime but must stay in the kernel, and *q*² is not prime but must vanish. The square test separates the shapes that stay (*q*, *qr*) from those that vanish (1, *q*²) in one step.
3. There are *n* beauties, each at most *n*(*n* − 1)/2 ≈ 5 · 10⁹ for *n* = 10⁵, so the sum is at most about 5.0 · 10¹⁴, far below 9.2 · 10¹⁸.
4. A good subsequence is non-empty and shorter than the array, and with *n* = 1 only the empty set is shorter. In the program *n* < 8, so a case with *g* = *p* reaches `existsDropOne`, which removes the only element, gets the gcd 0 of nothing, and returns false because *p* ≥ 1.
5. NO. With *n* = 6 the drop-one check runs, and every five of the numbers share one of the primes 2, 3, 5, 7, 11, 13. No contradiction: the theorem promises a subset of at most seven, and here six are needed while a proper subset has at most five. With a seventh value 2310 added, the answer becomes YES.
6. A query could read an entry written in the same step, which already ends with the current element, and extend it by that element again. On [1, 1] with *M* = 1 the answer is 1, but immediate writes give 3.
7. Values are at most *N* ≤ 1000, so arrays of length maxV + 1 can be indexed by value. With values up to 10⁹ the trees would need compression, but the real failure is the XOR dimension: XORs of 30-bit values take up to 2³⁰ values, far too many trees.
8. 20 %: the fast program is wrong on some inputs, so the program you would submit is the brute force, and the plan's rule says a correct brute force scores more than a fast wrong solution. Then fix the *n* = 1 case and run the stress test again.
:::

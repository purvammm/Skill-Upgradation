Chapter 11 built tables indexed by a position in one sequence and, for knapsacks, by a capacity. The tables in this chapter are indexed by a position in each of **two** strings. Such questions ask how alike two strings are: the longest list of letters they share in the same order, the fewest one-letter edits that turn one into the other, the shortest string that contains both. Spell checkers, the `diff` tool and the comparison of DNA sequences all rest on the same table.

The chapter uses the recipe of Chapter 11 (state, transition, base cases, evaluation order, answer) and its proof method: split by the last decision, then cut and paste. Sections 12.1 to 12.5 cover the longest common subsequence and edit distance, how to print an answer, and how to keep only two rows. Section 12.6 turns to one string, the longest palindromic subsequence, which is both a two-string problem (the string against its reverse) and an interval table over substrings, the form Chapter 14 develops. Section 12.7 adapts the table to counting and yes/no questions.

## Two strings, one table {#sec-12-table}

Let *s* have length *n* and *t* have length *m*. "What is the longest list of letters that appears, in order, in both strings?" has an obvious brute force: try each of the 2ⁿ ways to keep some letters of *s* and check each against *t*. For *n* = 30 that is about 1.07 · 10⁹ candidates.

Look instead at the **last** characters, *s*[*n* − 1] and *t*[*m* − 1]. An optimal answer either uses both of them together or ignores at least one. After that decision, what is left is the same question about the strings with their last characters removed. Removing the last character of a prefix gives a shorter prefix, so the family "a prefix of *s* paired with a prefix of *t*" is closed under every step of the argument, and it has only (*n* + 1)(*m* + 1) members, counting the empty prefixes.

:::definition{#def-12-twostring} Two-string DP
A [[two-string DP]] for strings *s*[0..*n* − 1] and *t*[0..*m* − 1] has one state for every pair (*i*, *j*) with 0 ≤ *i* ≤ *n* and 0 ≤ *j* ≤ *m*: dp[*i*][*j*] is the answer for the first *i* characters of *s* and the first *j* characters of *t*. The transition looks at *s*[*i* − 1] and *t*[*j* − 1] and reads dp[*i* − 1][*j* − 1], dp[*i* − 1][*j*] and dp[*i*][*j* − 1]. Row 0 and column 0 are the cases where one string is empty. The answer is dp[*n*][*m*].
:::

If the argument sometimes removed a character from the front and sometimes from the back, the states would be pairs of substrings, about *n*²*m*²/4 of them. Prefixes suffice because the last-character argument only ever shortens a string at its end.

Draw the table with *s* down the side and *t* across the top. Entry (*i*, *j*) reads its neighbours **up-left** (both strings one shorter), **up** (*s* one shorter) and **left** (*t* one shorter).

:::lemma{#lem-12-order} Valid filling orders
If every dp[*i*][*j*] with *i*, *j* ≥ 1 reads only dp[*i* − 1][*j* − 1], dp[*i* − 1][*j*] and dp[*i*][*j* − 1], and row 0 and column 0 are filled first, then each of these orders reads only filled entries: row by row (*j* increasing within a row), column by column, and by increasing *i* + *j*.
:::

:::proof
Each entry read has row index at most *i*, column index at most *j*, and is not (*i*, *j*). Row by row, an entry of row *i* − 1 lies in an earlier row, and (*i*, *j* − 1) comes earlier in the same row. Column by column is the same argument with rows and columns swapped. The entries read have index sums *i* + *j* − 1 or *i* + *j* − 2, both smaller than *i* + *j*.
:::

Row by row is the order you will almost always write, because it also allows the two-row trick of @sec-12-rows. By the template theorem of Chapter 11, a proved recurrence plus a valid order gives a correct table, so below only the recurrences need proofs.

:::pitfall
The handbook's trap for this card is the shift by one: index *i* stands for the first *i* characters, so the character it adds is `s.charAt(i - 1)`. Writing `s.charAt(i)` with loops from 1 to *n* throws `StringIndexOutOfBoundsException`; writing it with loops from 0 to *n* − 1 loses the empty-prefix row, and the base cases are silently wrong.
:::

## The longest common subsequence {#sec-12-lcs}

:::definition{#def-12-lcs} Common subsequence, longest common subsequence
A subsequence of a string keeps some of its characters in their original order and drops the rest. A string is a **common subsequence** of *s* and *t* if it is a subsequence of both. A [[longest common subsequence]] (LCS) is a common subsequence of maximum length; LCS(*s*, *t*) also denotes that length.
:::

For *s* = `listen` and *t* = `silent`, the strings `len`, `ien` and `sen` are common subsequences of length 3, and none is longer. An LCS need not be unique or contiguous: `len` uses positions 0, 4 and 5 of `listen`. Computing the length is LeetCode 1143 (Longest Common Subsequence). Write *L*(*i*, *j*) for the LCS length of *X* = *s*[0..*i* − 1] and *Y* = *t*[0..*j* − 1].

:::theorem{#thm-12-lcs} The LCS recurrence
*L*(*i*, 0) = *L*(0, *j*) = 0. For *i*, *j* ≥ 1:
(a) if *s*[*i* − 1] = *t*[*j* − 1], then *L*(*i*, *j*) = *L*(*i* − 1, *j* − 1) + 1;
(b) otherwise *L*(*i*, *j*) = max(*L*(*i* − 1, *j*), *L*(*i*, *j* − 1)).
:::

:::proof
The empty string has only the empty subsequence, so row 0 and column 0 are 0.

A fact for both cases: take any common subsequence *Z* = *z*₁ ⋯ *z*ₖ of *X* and *Y* with *k* ≥ 1, at fixed positions. Its last character sits at some position *a* ≤ *i* − 1 of *X* and *b* ≤ *j* − 1 of *Y*, and *z*₁ ⋯ *z*ₖ₋₁ sits strictly before *a* and before *b*. So cutting off *z*ₖ leaves a common subsequence of *s*[0..*i* − 2] and *t*[0..*j* − 2], and *L*(*i*, *j*) ≤ *L*(*i* − 1, *j* − 1) + 1 always.

(a) Pasting the common character after an LCS of the shorter prefixes gives a common subsequence of *X* and *Y*, so *L*(*i*, *j*) ≥ *L*(*i* − 1, *j* − 1) + 1, and the fact gives equality.

(b) Common subsequences of *s*[0..*i* − 2] and *Y*, or of *X* and *t*[0..*j* − 2], are also ones of *X* and *Y*, so *L*(*i*, *j*) is at least the maximum. Conversely, take an LCS *Z* of *X* and *Y* at fixed positions. If it avoids the last character of *X*, then |*Z*| ≤ *L*(*i* − 1, *j*). If it uses it, that character is *z*ₖ, since nothing in *X* comes later; if *Z* also used the last character of *Y*, that would be *z*ₖ too, and *s*[*i* − 1] = *z*ₖ = *t*[*j* − 1], which (b) excludes. So *Z* avoids *t*[*j* − 1] and |*Z*| ≤ *L*(*i*, *j* − 1).
:::

This is the cut-and-paste argument of Chapter 11: cut the last decision off an optimal answer and the rest is no better than the best smaller answer; paste a best smaller answer back and you get one that good. Case (a) also says that when the last characters agree, some LCS matches them with each other, so taking the diagonal is never a mistake.

```java {#lst-12-lcs} Length of a longest common subsequence (handbook template)
// dp[i][j] = answer for the first i chars of s and the first j chars of t
static int lcs(String s, String t) {
    int n = s.length(), m = t.length();
    int[][] dp = new int[n + 1][m + 1];
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            dp[i][j] = s.charAt(i - 1) == t.charAt(j - 1)
                    ? dp[i - 1][j - 1] + 1
                    : Math.max(dp[i - 1][j], dp[i][j - 1]);
    return dp[n][m];
}
```

Java initialises `int` arrays to 0, so row 0 and column 0 need no code. There are (*n* + 1)(*m* + 1) entries at O(1) each: O(*nm*) time and memory. For two random strings of 5000 lowercase letters that is 2.5 · 10⁷ entries; on the test machine `lcs` took about 150 to 180 ms (the answer was 1611).

## Walking back: printing the answer {#sec-12-walk}

The table holds lengths. To print an LCS, start at the corner and ask at each cell which case of @thm-12-lcs produced it. If the characters match, case (a) applied: the character is in the answer and the walk moves diagonally. If not, the entry equals the larger of its upper and left neighbours, and the walk moves to one holding the same value. The characters come out last first, so they are reversed at the end.

```java {#lst-12-print} The whole LCS table, and one LCS rebuilt by walking back
// The whole LCS table: dp[i][j] = LCS length of s[0..i) and t[0..j)
static int[][] lcsTable(String s, String t) {
    int n = s.length(), m = t.length();
    int[][] dp = new int[n + 1][m + 1];
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            dp[i][j] = s.charAt(i - 1) == t.charAt(j - 1)
                    ? dp[i - 1][j - 1] + 1
                    : Math.max(dp[i - 1][j], dp[i][j - 1]);
    return dp;
}

// One longest common subsequence, rebuilt by walking back from dp[n][m]
static String lcsString(String s, String t) {
    int[][] dp = lcsTable(s, t);
    StringBuilder sb = new StringBuilder();
    int i = s.length(), j = t.length();
    while (i > 0 && j > 0) {
        if (s.charAt(i - 1) == t.charAt(j - 1)) {          // match: take it, go diagonally
            sb.append(s.charAt(i - 1));
            i--;
            j--;
        } else if (dp[i - 1][j] >= dp[i][j - 1]) {
            i--;                                           // s[i-1] is not needed
        } else {
            j--;                                           // t[j-1] is not needed
        }
    }
    return sb.reverse().toString();                       // collected from the back
}
```

:::claim{#thm-12-walk} The walk back prints an LCS
At the start of each iteration, let *R* be the characters collected so far, in printing order. Then dp[*i*][*j*] + |*R*| = dp[*n*][*m*], and for every common subsequence *Z* of *s*[0..*i* − 1] and *t*[0..*j* − 1], *Z* followed by *R* is a common subsequence of *s* and *t*. When the loop stops, *R* is an LCS of *s* and *t*.
:::

:::proof
At the start *R* is empty and (*i*, *j*) = (*n*, *m*), so both parts hold. On a match *c* = *s*[*i* − 1] = *t*[*j* − 1], the new *R* is *c* followed by the old *R*. For a common subsequence *Z* of the shorter prefixes, *Z* then *c* is a common subsequence of *s*[0..*i* − 1] and *t*[0..*j* − 1], so *Z*, *c*, old *R* is one of *s* and *t*; and dp[*i* − 1][*j* − 1] = dp[*i*][*j*] − 1 by case (a). On a move up, dp[*i* − 1][*j*] ≥ dp[*i*][*j* − 1], so dp[*i* − 1][*j*] = dp[*i*][*j*] by case (b), and common subsequences of the shorter prefixes are also ones of the longer. Moving left is symmetric. At the end *i* = 0 or *j* = 0, so dp[*i*][*j*] = 0, |*R*| = dp[*n*][*m*], and *Z* empty shows that *R* is a common subsequence.
:::

Each step lowers *i* + *j*, so the walk takes at most *n* + *m* steps. On `listen` and `silent` the harness printed the walk of @fig-12-lcs:

```trace

(6,5)     n       n      3   match, take n           n
(5,4)     e       e      2   match, take e           en

The three "up" steps are ties. Other tie-breaks reach `ien` or `sen`, which are equally correct when a problem asks for "one" LCS. If it asks for a particular one, such as the lexicographically smallest, the tie rule becomes part of the algorithm and needs its own proof.

:::tip
Before submitting a two-string DP, run four tiny cases: both strings empty, one empty, two equal strings, and two strings with no common letter. They exercise row 0, column 0, the diagonal and the "up or left" branch.
:::

## Edit distance {#sec-12-edit}

:::definition{#def-12-edit} Edit distance
An edit is one of three operations: **insert** a character anywhere, **delete** a character, or **replace** a character by a different one. The [[edit distance]] (Levenshtein distance) from *s* to *t* is the fewest edits that turn *s* into *t*.
:::

This is LeetCode 72 (Edit Distance). A sequence of edits can be messy: a character may be inserted and deleted again, or replaced twice. A recurrence needs a tidier picture.

:::definition{#def-12-align} Alignment
An [[alignment|alignment (of two strings)]] of *s* and *t* writes *s* above *t* in columns, with gaps "−" inserted into either row, so that both rows have the same length and no column holds two gaps. A column is a **match** (equal letters), a **replacement** (different letters), a **deletion** (a letter over a gap) or an **insertion** (a gap over a letter). Its cost is the number of columns that are not matches.
:::

:::lemma{#lem-12-align} Edit distance is the cheapest alignment
The edit distance from *s* to *t* equals the smallest cost of an alignment of *s* and *t*.
:::

:::proof
*An alignment of cost c gives c edits.* Process the columns left to right with a current string that starts as *s*. After *q* columns let it be the bottom-row letters of columns 1..*q* followed by the top-row letters of the remaining columns; at *q* = 0 this is *s*. The next column (*x*, *y*) concerns the first letter after the finished part: a match changes nothing, a replacement replaces *x* by *y*, a deletion removes *x*, and an insertion puts *y* in front of it. Each non-match costs one edit, and at the end the string is *t*.

*Any k edits give an alignment of cost at most k.* Call the characters of *s* "original" and inserted ones "new". A replacement changes a character's letter, not its identity; a deletion destroys it; no edit changes the order of the characters that remain. So the surviving originals appear in *t* in their order in *s*. Pair each with its final position in *t*; the pairs never cross. Make one column per pair (a match if its letter is unchanged, otherwise a replacement) and, between consecutive pairs, a deletion column for each original destroyed there and an insertion column for each new character of *t* there. Each deletion column needed its own delete, each insertion column its own insert, and each replacement column at least one replace on its character. These edits are different, so *k* is at least the cost.
:::

Write *D*(*i*, *j*) for the edit distance from *s*[0..*i* − 1] to *t*[0..*j* − 1].

:::theorem{#thm-12-edit} The edit-distance recurrence: three moves
*D*(*i*, 0) = *i* and *D*(0, *j*) = *j*. For *i*, *j* ≥ 1,
*D*(*i*, *j*) = min( *D*(*i* − 1, *j* − 1) + δ, *D*(*i* − 1, *j*) + 1, *D*(*i*, *j* − 1) + 1 ),
where δ = 0 if *s*[*i* − 1] = *t*[*j* − 1] and δ = 1 otherwise.
:::

:::proof
By @lem-12-align it is enough to find the cheapest alignment. Aligning *i* letters with the empty string forces *i* deletion columns, and similarly for column 0. For *i*, *j* ≥ 1 the last column is *s*[*i* − 1] over *t*[*j* − 1] (cost δ), *s*[*i* − 1] over a gap (cost 1), or a gap over *t*[*j* − 1] (cost 1). Removing it leaves an alignment of the prefixes (*i* − 1, *j* − 1), (*i* − 1, *j*) or (*i*, *j* − 1), and appending it to any alignment of those prefixes gives one of the longer ones. So the cheapest alignment in each case is the cheapest shorter one plus the column's cost, and *D*(*i*, *j*) is the smallest of the three.
:::

In the table the moves have names: diagonal keeps or **replaces** *s*[*i* − 1], up **deletes** *s*[*i* − 1], left **inserts** *t*[*j* − 1]. The handbook template takes the diagonal at once when the characters agree, which needs a short argument.

:::lemma{#lem-12-match} Equal last characters
If *s*[*i* − 1] = *t*[*j* − 1], then *D*(*i*, *j*) = *D*(*i* − 1, *j* − 1).
:::

:::proof
It suffices that *D*(*i* − 1, *j* − 1) ≤ *D*(*i* − 1, *j*) + 1 and ≤ *D*(*i*, *j* − 1) + 1. Take a cheapest alignment of *s*[0..*i* − 2] with *t*[0..*j* − 1] and erase *t*[*j* − 1] from its bottom row. If it stood under a gap, that column disappears; if under a letter, that column becomes a deletion, costing at most 1 more. Either way the result aligns *s*[0..*i* − 2] with *t*[0..*j* − 2] at cost at most *D*(*i* − 1, *j*) + 1. The other inequality is symmetric.
:::

```java {#lst-12-edit} Edit distance (handbook template)
static int editDistance(String s, String t) {
    int n = s.length(), m = t.length();
    int[][] dp = new int[n + 1][m + 1];
    for (int i = 0; i <= n; i++) dp[i][0] = i;              // delete everything
    for (int j = 0; j <= m; j++) dp[0][j] = j;              // insert everything
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++) {
            if (s.charAt(i - 1) == t.charAt(j - 1)) dp[i][j] = dp[i - 1][j - 1];
            else dp[i][j] = 1 + Math.min(dp[i - 1][j - 1],      // replace
                    Math.min(dp[i - 1][j], dp[i][j - 1]));    // delete, insert
        }
    return dp[n][m];
}
```

The cost is O(*nm*) time and memory. The harness compared @lst-12-edit with a breadth-first search over all strings reachable by single edits, on 4000 random pairs of length up to 5.

## Two rows instead of a table {#sec-12-rows}

Row *i* of either table reads only row *i* − 1 and entries to its left in row *i*. Once row *i* is finished, row *i* − 1 is never read again.

:::definition{#def-12-rolling} Rolling array
A [[rolling array]] keeps only the rows of a DP table that later rows still read, and reuses their storage. A two-string table filled row by row needs two rows of length *m* + 1.
:::

```java {#lst-12-rows} Edit distance with two rows
// Edit distance in O(m) memory: row i is computed from row i-1 alone
static int editDistanceTwoRows(String s, String t) {
    int n = s.length(), m = t.length();
    int[] prev = new int[m + 1], cur = new int[m + 1];
    for (int j = 0; j <= m; j++) prev[j] = j;                 // row 0
    for (int i = 1; i <= n; i++) {
        cur[0] = i;                                          // column 0 of row i
        for (int j = 1; j <= m; j++) {
            if (s.charAt(i - 1) == t.charAt(j - 1)) cur[j] = prev[j - 1];
            else cur[j] = 1 + Math.min(prev[j - 1], Math.min(prev[j], cur[j - 1]));
        }
        int[] tmp = prev;                                    // row i becomes the previous row;
        prev = cur;                                          // the old array is reused for row i+1
        cur = tmp;
    }
    return prev[m];
}
```

:::claim{#thm-12-rows} Correctness of the two-row version
At the start of the pass for row *i*, `prev[j]` = *D*(*i* − 1, *j*) for every *j*; after the last pass, `prev[m]` = *D*(*n*, *m*).
:::

:::proof
Before the first pass `prev` holds row 0. A pass writes only into `cur`, and `cur` and `prev` are different arrays, so `prev` keeps row *i* − 1 during the pass. `cur[0]` = *i* = *D*(*i*, 0). When the loop reaches *j*, `prev[j - 1]` and `prev[j]` hold *D*(*i* − 1, *j* − 1) and *D*(*i* − 1, *j*), and `cur[j - 1]` holds *D*(*i*, *j* − 1) from the step before, so `cur[j]` receives *D*(*i*, *j*) by @thm-12-edit and @lem-12-match. The swap makes `prev` the finished row. If *n* = 0, `prev[m]` = *m* = *D*(0, *m*).
:::

The swap takes three assignments because a Java array variable holds a **reference**. `prev = cur;` alone would make both names refer to one array, and the next row would overwrite entries it still has to read; Workbook Chapter 12 asks you to find that bug. The same change turns @lst-12-lcs into a two-row LCS. Both measures are symmetric (each edit is undone by one edit), so you can swap the strings to make *t* the shorter and use O(min(*n*, *m*)) memory.

The saving at typical limits: for *n* = *m* = 5000 the full `int` table has 5001 × 5001 = 25,010,001 entries, 100,040,004 bytes (about 100 MB, plus a header of about 16 bytes for each of the 5001 row arrays). Two rows take 2 × 5001 × 4 = 40,008 bytes. The time hardly changes: the two-row version took about 70 to 130 ms on the strings used earlier, the full table about 105 to 180 ms. A `long` table of that shape would need 200 MB, so counting tables (@sec-12-variants) should roll whenever only the final number is wanted.

### Why printing needs the whole table

The walk back visits every row from *n* down to 0, but the two-row version has overwritten all rows except the last two. To print, keep one of these:

- the full `int` table (about 100 MB for 5000 × 5000);
- a `short` table: lengths and distances of strings of length at most 5000 fit in a `short` (at most 32 767), about 50 MB;
- one byte per cell recording the move that produced it, next to two rows of numbers: 25,010,001 bytes, about 25 MB.

A divide-and-conquer method, Hirschberg's algorithm, prints an optimal alignment in O(*nm*) time and O(*n* + *m*) memory by running two-row passes from both ends and splitting at the middle row. You will rarely need it in an assessment.

## Palindromic subsequences {#sec-12-pal}

:::definition{#def-12-pal} Palindrome, longest palindromic subsequence
A [[palindrome]] reads the same forwards and backwards, such as `level` or `abba`; the empty string and every single character are palindromes. The [[longest palindromic subsequence]] (LPS) of *s* is a longest subsequence of *s* that is a palindrome; LPS(*s*) also denotes its length.
:::

A palindrome's first and last characters are equal, so the natural subproblem removes a character from the front, the back, or both. That leaves a **substring** *s*[*l*..*r*], not a prefix, and the states are the *n*(*n* + 1)/2 substrings. Write *P*(*l*, *r*) for the LPS length of *s*[*l*..*r*], with *P*(*l*, *l* − 1) = 0 for the empty substring.

:::theorem{#thm-12-lps} The interval recurrence for palindromes
*P*(*l*, *l*) = 1. For *l* < *r*: if *s*[*l*] = *s*[*r*], then *P*(*l*, *r*) = *P*(*l* + 1, *r* − 1) + 2; otherwise *P*(*l*, *r*) = max(*P*(*l* + 1, *r*), *P*(*l*, *r* − 1)).
:::

:::proof
A single character is a palindrome. Let *l* < *r* and let *Q* be a longest palindromic subsequence of *s*[*l*..*r*] at positions *p*₁ < ⋯ < *p*ₖ.

*Equal ends.* Wrapping *s*[*l*] and *s*[*r*] around a palindromic subsequence of *s*[*l* + 1..*r* − 1] gives one of *s*[*l*..*r*], so *P*(*l*, *r*) ≥ *P*(*l* + 1, *r* − 1) + 2. Conversely *k* ≥ 2, since *s*[*l*]*s*[*r*] is a palindrome. Cutting the first and last characters off *Q* leaves a palindrome at positions *p*₂..*p*ₖ₋₁, strictly between *p*₁ ≥ *l* and *p*ₖ ≤ *r*, so *k* − 2 ≤ *P*(*l* + 1, *r* − 1).

*Different ends.* Palindromic subsequences of *s*[*l* + 1..*r*] and *s*[*l*..*r* − 1] are ones of *s*[*l*..*r*]. Conversely, if *Q* used both *l* and *r*, they would be its first and last positions, which hold equal letters, so *s*[*l*] = *s*[*r*], which is excluded. So *Q* lies in *s*[*l* + 1..*r*] or in *s*[*l*..*r* − 1].
:::

Each entry reads (*l* + 1, *r* − 1), (*l* + 1, *r*) and (*l*, *r* − 1), all shorter substrings inside it. Two orders work: by increasing length, or *l* from *n* − 1 **down** to 0 with *r* from *l* + 1 up, since every entry read then has a larger *l* or the same *l* and a smaller *r*. Running *l* upwards reads dp[1][*r*] while computing dp[0][*r*], before row 1 exists; on `badcab` that returns 2 instead of 5, without any error. Chapter 14 proves both orders for interval DPs in general. The cost is O(*n*²) time and memory.

### The string against its reverse

A palindrome equals its own reverse, which turns the question back into a two-string one.

:::theorem{#thm-12-rev} LPS(s) = LCS(s, reverse(s))
For every string *s*, LPS(*s*) equals the LCS length of *s* and its reverse.
:::

:::proof
Let *u* be the reverse of *s*, so *u*[*j*] = *s*[*n* − 1 − *j*].

*LPS ≤ LCS.* If a palindrome *Q* sits in *s* at positions *p*₁ < ⋯ < *p*ₖ, then *u* holds *s*[*p*ₖ], …, *s*[*p*₁] at positions *n* − 1 − *p*ₖ < ⋯ < *n* − 1 − *p*₁. That is *Q* reversed, which is *Q*, so *Q* is a common subsequence.

*LCS ≤ LPS.* Let *c*(1) ⋯ *c*(*k*) be a common subsequence of *s* and *u*, with *c*(*t*) = *s*[*a*(*t*)] for *a*(1) < ⋯ < *a*(*k*) and *c*(*t*) = *u*[*b*(*t*)] for *b*(1) < ⋯ < *b*(*k*). Put *q*(*t*) = *n* − 1 − *b*(*t*); then *c*(*t*) = *s*[*q*(*t*)] and *q*(1) > ⋯ > *q*(*k*). So *a*(*t*) − *q*(*t*) strictly increases with *t*, and the indices split into consecutive groups: the first *x* indices with *a*(*t*) < *q*(*t*); at most one middle index with *a*(*t*) = *q*(*t*) (*e* = 1 if it exists, else 0); the last *y* indices, with *a*(*t*) > *q*(*t*). Here *x* + *e* + *y* = *k*. The positions *a*(1) < ⋯ < *a*(*x*), then the middle position, then *q*(*x*) < ⋯ < *q*(1) increase, and they spell *c*(1) ⋯ *c*(*x*), the middle letter, *c*(*x*) ⋯ *c*(1): a palindrome of length 2*x* + *e*. With *f* = *k* − *y* + 1, the positions *q*(*k*) < ⋯ < *q*(*f*), the middle position, *a*(*f*) < ⋯ < *a*(*k*) likewise spell a palindrome of length 2*y* + *e*. The longer has length at least their average, *x* + *y* + *e* = *k*.
:::

So LeetCode 516 (Longest Palindromic Subsequence) yields to the interval table of @thm-12-lps or to one call of @lst-12-lcs on *s* and its reverse, both O(*n*²). Writing it is left to you.

:::pitfall
The theorem is about lengths: an LCS of *s* and its reverse need not be a palindrome. For *s* = `bacba` (reverse `abcab`) the LCS length is 3, and the harness found six LCS strings: `aba`, `aca`, `bab`, `bcb`, but also `acb` and `bca`. @lst-12-print returns `bab`, but a walk that breaks some ties the other way returns `acb`. To print a palindrome, walk back the interval table instead: equal ends give a pair of letters, different ends move to the larger neighbour.
:::

### Fewest insertions to make a palindrome

LeetCode 1312 (Minimum Insertion Steps to Make a String Palindrome) asks for the fewest characters to insert, anywhere, so that *s* becomes a palindrome. The plan's hint says *n* minus the LPS length; here is why.

:::theorem{#thm-12-ins} Fewest insertions
The fewest insertions that turn *s* into a palindrome is *n* − LPS(*s*).
:::

:::proof
*At least.* Suppose *k* insertions give a palindrome *w* of length *N* = *n* + *k*, and let *S* be the *n* positions of *w* holding original characters (*w* read at *S* is *s*). The mirror of position *q* is *N* − 1 − *q*, and *w* has equal letters at both. Let *T* be the positions in *S* whose mirror is also in *S*. *T* is closed under mirroring, so *w* read at *T* is a palindrome, and a subsequence of *s*: |*T*| ≤ LPS(*s*). Each position in *S* but not in *T* has an inserted character at its mirror, and different positions have different mirrors, so *k* ≥ *n* − |*T*| ≥ *n* − LPS(*s*).

*At most*, by induction on *n*. If *n* ≤ 1, *s* is a palindrome and LPS(*s*) = *n*. If *s*[0] = *s*[*n* − 1], then LPS(*s*) = LPS(*s*[1..*n* − 2]) + 2 by @thm-12-lps; make the middle a palindrome with (*n* − 2) − LPS(middle) = *n* − LPS(*s*) insertions and keep the equal ends around it. Otherwise LPS(*s*) is LPS(*s*[1..*n* − 1]) or LPS(*s*[0..*n* − 2]). In the first case make *s*[1..*n* − 1] a palindrome *w*′ with (*n* − 1) − LPS(*s*) insertions and output *s*[0], *w*′, and an inserted copy of *s*[0]: *n* − LPS(*s*) insertions in all. The second case is symmetric.
:::

For `badcab`, LPS = 5, so one insertion is necessary and enough; the construction keeps the ends `b`, `b` and `a`, `a` and turns the middle `dc` into `dcd`, giving `badcdab`. Deletions behave the same way: what remains after deleting is a palindromic subsequence, so the fewest deletions is also *n* − LPS(*s*).

## Counting, yes/no answers and supersequences {#sec-12-variants}

Changing what an entry holds changes the question; the last-character argument carries over each time with one condition.

### Counting: add disjoint cases

A counting entry holds a number, and the transition **adds** the counts of the cases, which must be disjoint and cover everything. Take a question that is not one of the day's problems: how many pairs (*I*, *J*) are there, with *I* a set of positions of *s* and *J* a set of positions of *t* of the same size, such that *s* read at *I* spells the same string as *t* read at *J*? The pair of empty sets counts once.

:::theorem{#thm-12-count} Counting common subsequences by positions
Let *N*(*i*, *j*) be that number for *s*[0..*i* − 1] and *t*[0..*j* − 1]. Then *N*(*i*, 0) = *N*(0, *j*) = 1 and, for *i*, *j* ≥ 1,
*N*(*i*, *j*) = *N*(*i* − 1, *j*) + *N*(*i*, *j* − 1) − *N*(*i* − 1, *j* − 1) + μ · *N*(*i* − 1, *j* − 1), where μ = 1 if *s*[*i* − 1] = *t*[*j* − 1] and μ = 0 otherwise.
:::

:::proof
With an empty prefix only the empty pair exists. Pairs whose *I* misses position *i* − 1 are the pairs for (*i* − 1, *j*); pairs whose *J* misses *j* − 1 are those for (*i*, *j* − 1). Pairs missing both are counted twice, and there are *N*(*i* − 1, *j* − 1) of them, so the first three terms count each pair missing at least one of the two positions once (inclusion–exclusion, as in the two-dimensional prefix sums of Chapter 2). The other pairs contain both *i* − 1 and *j* − 1, the last positions of *I* and *J*, which therefore spell the same last letter: they exist only if μ = 1, and removing them is a one-to-one map onto the pairs for (*i* − 1, *j* − 1).
:::

```java {#lst-12-count} Counting common subsequences, position by position
// Pairs (subsequence of s, subsequence of t) that spell the same string, counted
// by positions; the pair of empty subsequences is included.
static long countCommon(String s, String t) {
    int n = s.length(), m = t.length();
    long[][] c = new long[n + 1][m + 1];
    for (int i = 0; i <= n; i++) c[i][0] = 1;                // only the empty pair
    for (int j = 0; j <= m; j++) c[0][j] = 1;
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++) {
            // pairs that miss s[i-1] or t[j-1], by inclusion-exclusion
            c[i][j] = c[i - 1][j] + c[i][j - 1] - c[i - 1][j - 1];
            if (s.charAt(i - 1) == t.charAt(j - 1))
                c[i][j] += c[i - 1][j - 1];          // pairs that end with s[i-1], t[j-1]
        }
    return c[n][m];
}
```

:::example{#ex-12-count} Counting for aab and ab
For *s* = `aab` and *t* = `ab` the harness printed:

```trace
        ""  a  b
  ""     1  1  1
  a      1  2  2
  a      1  3  3
  b      1  3  6
```

The corner is 3 + 3 − 3 = 3 pairs that miss a last position, plus c[2][1] = 3 that pair the final `b` with the final `b`: 6. By hand: the empty pair, `a` twice, `b` once and `ab` twice. A brute force over all position sets agreed with @lst-12-count on 4000 random pairs of length up to 7.
:::

Counts grow exponentially. For *s* = *t* = `aa…a` of length *n* the count is the binomial coefficient C(2*n*, *n*): 7,219,428,434,016,265,740 for *n* = 33, which fits in a `long` (maximum 9,223,372,036,854,775,807), but 28,453,041,475,240,576,740 for *n* = 34, for which @lst-12-count silently returned −8,440,446,672,178,526,492. Use `long` from the start, and when testing a counting DP replace `+` by `Math.addExact`, which throws `ArithmeticException` on overflow. If the count is wanted modulo 10⁹ + 7, reduce after every step (Chapter 10) and add the modulus back after the subtraction so the entry stays non-negative.

LeetCode 115 (Distinct Subsequences) counts the position sets of *s* that spell all of *t*. Its key observation is the same split on the last character of *s*: a way either does not use it, or uses it as the last letter of *t*, which needs the letters to agree. These cases are disjoint, so no subtraction is needed.

### Yes/no questions: OR instead of max

For "is it possible?", an entry is a `boolean` and the transition takes the OR of the cases. A different example: a **wildcard pattern** *p* has letters, `?` (any one character) and `*` (any string, possibly empty). Does *p* match the whole of *s*?

:::claim{#thm-12-wild} The wildcard recurrence
Let ok[*i*][*j*] say whether *p*[0..*i* − 1] matches *s*[0..*j* − 1]. ok[0][0] is true and ok[0][*j*] is false for *j* ≥ 1. For *i* ≥ 1, if *p*[*i* − 1] is `*`, then ok[*i*][*j*] = ok[*i* − 1][*j*] or (*j* ≥ 1 and ok[*i*][*j* − 1]); otherwise ok[*i*][*j*] holds exactly when *j* ≥ 1, ok[*i* − 1][*j* − 1] holds, and *p*[*i* − 1] is `?` or equals *s*[*j* − 1].
:::

:::proof
A match gives the last pattern symbol a final piece of *s*. A letter or `?` takes exactly *s*[*j* − 1], which must fit it, and the rest of the pattern matches *s*[0..*j* − 2]. A `*` takes *s*[*k*..*j* − 1] for some *k* ≤ *j*: if that piece is empty, the rest matches *s*[0..*j* − 1]; if not, shortening it by one character gives a match of the same pattern with *s*[0..*j* − 2]. Conversely, lengthening the star's piece by one character turns a match counted by ok[*i*][*j* − 1] into one for ok[*i*][*j*].
:::

```java {#lst-12-wild} Wildcard matching with a boolean table
// Does the pattern p match the whole of s? '?' matches one character, '*' any string.
static boolean wildcardMatch(String p, String s) {
    int n = p.length(), m = s.length();
    boolean[][] ok = new boolean[n + 1][m + 1];   // ok[i][j]: p[0..i) matches s[0..j)
    ok[0][0] = true;                              // empty pattern, empty text
    for (int i = 1; i <= n; i++) {
        char c = p.charAt(i - 1);
        for (int j = 0; j <= m; j++) {
            if (c == '*')                         // the star is empty, or it eats s[j-1]
                ok[i][j] = ok[i - 1][j] || (j > 0 && ok[i][j - 1]);
            else
                ok[i][j] = j > 0 && ok[i - 1][j - 1] && (c == '?' || c == s.charAt(j - 1));
        }
    }
    return ok[n][m];
}
```

The loop over *j* starts at 0 because a pattern such as `**` matches the empty string. The harness compared @lst-12-wild with plain backtracking on 4000 random cases; for instance `a*b?` matches `axyzbc` and `abc` but not `ab`. The cost is O(*nm*).

LeetCode 97 (Interleaving String) asks whether *s*3 is a merge of *s*1 and *s*2 that keeps the order of each: a yes/no table over prefixes of *s*1 and *s*2. The key observation is that no third index is needed, because once *i* characters of *s*1 and *j* of *s*2 are used, exactly *i* + *j* characters of *s*3 have been produced.

### Shortest common supersequence

:::definition{#def-12-scs} Shortest common supersequence
A common supersequence of *s* and *t* has both as subsequences. A [[shortest common supersequence]] is one of minimum length.
:::

The key observation is that its length is *n* + *m* − LCS(*s*, *t*). In a common supersequence *w*, the letters of *s* take *n* positions and those of *t* take *m*; the positions used by both spell a common subsequence, so there are at most LCS(*s*, *t*) of them. A walk back through the LCS table that writes each matched letter once and each dropped letter as it is dropped reaches that length. For `listen` and `silent` it is 6 + 6 − 3 = 9. LeetCode 1092 (Shortest Common Supersequence) asks you to print one; adapting @lst-12-print is the exercise.

## Summary

- A two-string DP has one state per pair of prefixes: dp[*i*][*j*] answers the question for the first *i* characters of *s* and the first *j* of *t*. Row 0 and column 0 are the empty cases, and index *i* adds the character *s*[*i* − 1].
- Each entry reads its up-left, up and left neighbours, so row-by-row filling is valid, and the cost is O(*nm*).
- LCS: a match extends the diagonal by 1, otherwise take the larger of up and left. The proof cuts the last character off an optimal answer and pastes a best smaller answer back.
- To print an answer, walk back from dp[*n*][*m*] asking which case produced each cell; ties give different, equally good answers.
- Edit distance is the cheapest alignment; its moves are diagonal (keep or replace), up (delete) and left (insert), and equal last characters need only the diagonal.
- Two rows give the value in O(min(*n*, *m*)) memory (40 KB instead of 100 MB for 5000 × 5000), but printing needs the full table, a `short` table or a byte per cell.
- LPS uses the interval table dp[*l*][*r*] with *l* running downwards, and equals LCS(*s*, reverse(*s*)); the fewest insertions, or deletions, that leave a palindrome are *n* − LPS.
- Counting tables add disjoint cases and overflow fast (use `long`, test with `Math.addExact`); yes/no tables use OR; the shortest common supersequence has length *n* + *m* − LCS.

## Review questions

1. Why does the LCS table have *n* + 1 rows instead of *n*? What do row 0 and column 0 hold for LCS and for edit distance?
2. Why may the LCS program take the diagonal as soon as the last characters match, without comparing with up and left?
3. Name a valid filling order for the LCS table other than row by row, and an invalid one, with an entry it reads too early.
4. Suppose only insertions and deletions are allowed. Express the fewest edits from *s* to *t* through LCS(*s*, *t*), prove it, and compute it for `listen` and `silent`.
5. Why can @lst-12-rows not print the edits? What is the cheapest extra storage, in bytes, that restores printing for *n* = *m* = 5000?
6. In the interval table for palindromes, what goes wrong if *l* runs upwards?
7. For *s* = `bacba`, `acb` is a longest common subsequence of *s* and its reverse. Why does that not contradict @thm-12-rev?
8. In @lst-12-count, why is c[*i* − 1][*j* − 1] subtracted, and why is it added back when the characters match? Why does every entry fit in a `long` for two strings of length 10?

:::answers
1. Row *i* stands for the prefix of length *i*, and the empty prefix needs its own row and column. For LCS they hold 0 (the empty string has only the empty subsequence). For edit distance dp[*i*][0] = *i* (delete everything) and dp[0][*j*] = *j* (insert everything).
2. Case (a) of @thm-12-lcs gives *L*(*i*, *j*) = *L*(*i* − 1, *j* − 1) + 1 on a match, and the first fact in its proof shows that no entry exceeds *L*(*i* − 1, *j* − 1) + 1. Up and left are at most *L*(*i*, *j*), so they can never beat the diagonal.
3. Column by column, or by increasing *i* + *j*. Filling each row from right to left is invalid: dp[*i*][*j*] reads dp[*i*][*j* − 1], which is still 0. On `listen` and `silent` that order returns 1 instead of 3.
4. *n* + *m* − 2 · LCS(*s*, *t*). An alignment without replacements pairs only equal letters, so its match columns spell a common subsequence of some length *k*; the other *n* − *k* letters of *s* are deletions and *m* − *k* letters of *t* are insertions, costing *n* + *m* − 2*k*, smallest for *k* = LCS(*s*, *t*). The proof of @lem-12-align works unchanged without replacements. For `listen` and `silent`: 6 + 6 − 6 = 6, against 4 with replacements. A breadth-first search agreed with the formula on 3000 random pairs.
5. Printing walks through every row, but only the last two rows survive. The cheapest fix stores one byte per cell recording the move: 5001 × 5001 = 25,010,001 bytes, about 25 MB (a `short` table needs about 50 MB, an `int` table about 100 MB).
6. dp[*l*][*r*] reads dp[*l* + 1][*r* − 1] and dp[*l* + 1][*r*] from row *l* + 1. With *l* upwards, row *l* + 1 is still all 0 when row *l* is computed, so the program returns a wrong number without an error: 2 instead of 5 for `badcab`.
7. The theorem is about lengths. Its proof turns any common subsequence of length *k*, including `acb`, into a palindromic subsequence of length at least *k*; for `bacba` it builds `aba` or `bab`.
8. Pairs missing both last positions are counted in both c[*i* − 1][*j*] and c[*i*][*j* − 1], so subtracting c[*i* − 1][*j* − 1] counts them once. Pairs using both last positions are in none of the three terms; on a match there are c[*i* − 1][*j* − 1] of them, one per pair of the shorter prefixes. For length 10 every count is at most the number of pairs of equal-size position sets, C(20, 10) = 184,756, reached by `aaaaaaaaaa` with itself.
:::

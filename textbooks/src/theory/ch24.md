## Reading a repeat problem {#sec-24-read}

The plan's notes on the official sample paper describe the style of the statements: long and story-like, with the input given one value per line and a function such as `get_ans(...)` to complete. Its Java kit covers the other case: when the platform gives no stub that reads the input, you write `main` yourself and read every number from standard input.

:::definition{#def-24-full} Full program
A [[full program]] is a complete Java source file, here always `public class Main`, whose `main` method reads the whole input from standard input and prints the answer. The alternative is a *function stub*: the platform reads the input and calls a method whose signature you must keep.
:::

Today's solutions are full programs, because a program you can run on a sample file is also a program you can test. If the exam gives you a stub, the body of `solve` moves into the stub unchanged.

### From story to model

Before any code, write down the input in order, the output, the limits and the *model*, the plain mathematical problem behind the story: "Andy has obligations on some days" becomes an array cnt[1..*N*] of non-negative counts. The proofs in this chapter are about the model; the story is what you check it against.

### int or long

Java does not report an `int` overflow; the value wraps silently (Chapter 1). Decide the type of every quantity from the limits.

- **Sums, experience, energy, work: `long`.** A sum of 10⁵ values up to 10⁹ reaches 10¹⁴. The plan's notes ask for `long` for the monsters' experience, the wine work and the XOR sums.
- **Products: cast first.** `100000 * 100000` in `int` is 1410065408; `(long) 100000 * 100000` is 10¹⁰.
- **Counts, days and lengths: `int`.** A day number up to 10⁶ or a length up to 32 is safe.
- **Residues: reduce after every operation.** Below 10000 every residue and every product of two residues fits in `int`, but a sum of 10⁶ residues does not.

### Edge cases to try every time

The samples rarely contain the inputs that break programs. For each problem, run at least the smallest input (*n* = 1, *K* = 0 or *K* = 1), all values equal, an answer that is impossible or zero (the gym's −1, or *E* ≤ 0 at the start) and the largest values, to check the types.

### One file for solving and self-judging

:::definition{#def-24-selfjudge} Self-judging
[[Self-judging|self-judging]] means grading a solution without an online judge: run it on the samples of the statement, then compare it with a brute force on thousands of random small inputs (the stress test of Chapter 9) until no mismatch remains.
:::

The plan's advice for problems without a judge is to write them in OneCompiler, run the samples, then stress-test against a brute force, and its notes for today fix the order: the brute force first, then the fast solution, then the stress test. An online editor holds one file, so the brute force and the stress loop live in the same `Main` class as the solution. @lst-24-layout shows the layout on a small problem that is not one of today's: the largest product of two elements at different positions, with |*a*[*i*]| ≤ 10⁹ so that every product fits in a `long`.

```java {#lst-24-layout} One file for the solution, its brute force and its stress test
import java.io.*;
import java.util.*;

public class Main {
    static final boolean STRESS = false;          // true while you test, false when you submit

    public static void main(String[] args) throws IOException {
        if (STRESS) { stress(); return; }
        FastScanner fs = new FastScanner(System.in);
        int n = fs.nextInt();                         // line 1: n
        long[] a = new long[n];
        for (int i = 0; i < n; i++) a[i] = fs.nextLong();  // lines 2..n+1: one value each
        System.out.println(solve(a));
    }

    // Largest a[i] * a[j] at two different positions (n >= 2). O(n): two largest, two smallest.
    static long solve(long[] a) {
        long max1 = Long.MIN_VALUE, max2 = Long.MIN_VALUE;
        long min1 = Long.MAX_VALUE, min2 = Long.MAX_VALUE;
        for (long x : a) {
            if (x > max1) { max2 = max1; max1 = x; } else if (x > max2) max2 = x;
            if (x < min1) { min2 = min1; min1 = x; } else if (x < min2) min2 = x;
        }
        return Math.max(max1 * max2, min1 * min2);    // two negatives can win
    }

    static long brute(long[] a) {                     // every pair: O(n^2), obviously right
        long best = Long.MIN_VALUE;
        for (int i = 0; i < a.length; i++)
            for (int j = i + 1; j < a.length; j++) best = Math.max(best, a[i] * a[j]);
        return best;
    }

    static void stress() {
        Random rnd = new Random(1);
        for (int iter = 1; iter <= 10000; iter++) {
            int n = 2 + rnd.nextInt(6);               // only what the statement allows: n >= 2
            long[] a = new long[n];
            for (int i = 0; i < n; i++) a[i] = rnd.nextInt(11) - 5;
            long fast = solve(a), slow = brute(a);
            if (fast != slow) {
                System.out.println("iteration " + iter + ": " + Arrays.toString(a)
                        + "  fast=" + fast + "  brute=" + slow);
                return;
            }
        }
        System.out.println("all 10000 tests passed");
    }

    static final class FastScanner {                  // Chapter 1's FastScanner, shortened
        private final BufferedReader br;
        private StringTokenizer st;
        FastScanner(InputStream in) { br = new BufferedReader(new InputStreamReader(in)); }
        String next() throws IOException {
            while (st == null || !st.hasMoreTokens()) {
                String line = br.readLine();
                if (line == null) return null;
                st = new StringTokenizer(line);
            }
            return st.nextToken();
        }
        int nextInt() throws IOException { return Integer.parseInt(next()); }
        long nextLong() throws IOException { return Long.parseLong(next()); }
    }
}
```

Four choices in this file carry over to every program in the chapter.

1. **`main` only reads and prints; `solve` only computes.** The stress loop calls `solve` with arrays it generates, so it tests exactly the method you submit, and the samples test the reading.
2. **The brute force sits beside it, written to be obviously right**, here by trying every pair.
3. **One flag switches between the two uses.** With `STRESS = true` the program ignores standard input and runs the stress loop. Set it back to `false` before you submit.
4. **The scanner is Chapter 1's `FastScanner`, shortened.** Its `next()` reads another line whenever the current one is used up, so one value per line and all values on one line are read the same way.

On the input 4, −7, 100000, 3, 100000, one value per line, the program prints 10000000000; with `int` arrays the product 100000 · 100000 would have printed 1410065408. With `STRESS = true` it prints "all 10000 tests passed". The edge case that the stress loop guards against is two negative numbers. Make `solve` return only `max1 * max2`, and the loop stops at the second input:

```trace
iteration 2: [-2, -4, -1, 1]  fast=-1  brute=8
```

The two largest values give 1 · (−1) = −1, but (−2) · (−4) = 8 is larger. A sample made of positive numbers would never have shown this.

## Sorting greedies: monsters and the gym {#sec-24-greedy}

### RPG: maximum monsters defeated

You start with experience *e*. Monster *i* can be fought only when your experience is at least power[*i*], and beating it adds bonus[*i*] to your experience. You choose the order, and a lost fight ends the run, so you never start a fight you would lose. Find the largest number of monsters you can beat. The plan gives the input as *n*, *e*, the *n* powers and the *n* bonuses, one value per line, and rates the problem very high frequency (11 reports, SP, 2022–2026).

Chapter 9 wrote its brute force, a search over all orders. This section proves the plan's greedy optimal: sort by power and fight while you can.

:::definition{#def-24-beatable} Beatable set
A set *S* of monsters is a [[beatable set]] if some order of *S* lets you fight its monsters one after another, starting with experience *e*, and never face a monster whose power exceeds your experience at that moment.
:::

:::keyidea
With non-negative bonuses your experience never falls, so a monster you can beat now stays beatable. Fighting the weakest remaining monster first can only help.
:::

:::theorem{#thm-24-monsters} The sorted walk contains every beatable set
Let every bonus be non-negative. Sort the monsters by power and fight them in that order until the first one whose power exceeds the current experience, and let *G* be the set beaten. Then every beatable set is a subset of *G*. In particular, |*G*| is the largest number of monsters that can be beaten.
:::

:::proof
The walk fights only monsters whose power is at most the current experience, so *G* is beatable. If the walk beats every monster there is nothing more to prove. Otherwise it stops at a monster *m* with power(*m*) > *E*, where *E* = *e* + Σ bonus(*g*) over *g* ∈ *G* is its final experience. Every monster outside *G* comes at or after *m* in the sorted order, so its power is at least power(*m*) > *E*.

Take any beatable set *S* with an order that beats it, and suppose *S* contains a monster outside *G*. Let *u* be the first monster outside *G* in that order. Every monster fought before *u* is in *G*, so the experience when *u* is fought is *e* plus the bonuses of some monsters of *G*, which is at most *E* because bonuses are non-negative. The fight against *u* is won, so power(*u*) ≤ *E*. But *u* is outside *G*, so power(*u*) > *E*, a contradiction. Hence *S* ⊆ *G*.
:::

The proof uses non-negative bonuses at one step only, the bound "at most *E*". The pitfall below shows what happens without it.

```java {#lst-24-monsters} RPG: maximum monsters defeated (input n, e, n powers, n bonuses)
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        FastScanner fs = new FastScanner(System.in);
        int n = fs.nextInt();                         // input: n, e, n powers, n bonuses
        long e = fs.nextLong();
        long[] power = new long[n], bonus = new long[n];
        for (int i = 0; i < n; i++) power[i] = fs.nextLong();
        for (int i = 0; i < n; i++) bonus[i] = fs.nextLong();
        System.out.println(maxMonsters(e, power, bonus));
    }

    // Most monsters beaten, starting with experience e. Needs every bonus >= 0. O(n log n).
    static int maxMonsters(long e, long[] power, long[] bonus) {
        int n = power.length;
        long[][] mon = new long[n][];
        for (int i = 0; i < n; i++) mon[i] = new long[]{power[i], bonus[i]};
        Arrays.sort(mon, (x, y) -> Long.compare(x[0], y[0]));  // increasing power
        int beaten = 0;
        for (long[] m : mon) {
            if (e < m[0]) break;                      // later monsters are no weaker
            e += m[1];                                // long: the bonuses can add up past 2^31
            beaten++;
        }
        return beaten;
    }

    static final class FastScanner {                  // Chapter 1's FastScanner, shortened
        private final BufferedReader br;
        private StringTokenizer st;
        FastScanner(InputStream in) { br = new BufferedReader(new InputStreamReader(in)); }
        String next() throws IOException {
            while (st == null || !st.hasMoreTokens()) {
                String line = br.readLine();
                if (line == null) return null;
                st = new StringTokenizer(line);
            }
            return st.nextToken();
        }
        int nextInt() throws IOException { return Integer.parseInt(next()); }
        long nextLong() throws IOException { return Long.parseLong(next()); }
    }
}
```

The sort costs O(*n* log *n*) and the walk O(*n*); memory is O(*n*). Sorting `long[]` rows with a comparator sorts objects, which is slower than sorting a primitive array. On the machine used for this book the whole program, JVM start-up included, took 0.16 s for 10⁵ monsters and 0.77 s for 10⁶.

Take *e* = 5, powers [12, 3, 7, 25, 6, 9] and bonuses [4, 2, 0, 10, 3, 1]. After sorting by power:

:::pitfall Negative bonuses break the greedy
The plan warns that the greedy needs non-negative bonuses, and the stress test agrees. Against Chapter 9's search over all orders, @lst-24-monsters matched on 20,000 random instances with up to 7 monsters and bonuses in 0..5. With bonuses in −4..4 the very first instance failed: *e* = 4, powers [3, 1, 2], bonuses [2, 0, −3]. The greedy fights power 1 (experience stays 4), then power 2 (experience drops to 1), and cannot fight power 3: 2 monsters. Fighting power 3 first (experience 6), then power 1, then power 2 beats all 3. If your statement allows negative bonuses it is a different problem, and for small *n* Chapter 22's DP over sets of monsters solves it.
:::

### Gym: fewest exercises to drain energy

You have energy *E* and *n* exercises. Doing exercise *i* once lowers your energy by drain[*i*] > 0, and the plan's version allows each exercise at most twice. Find the fewest exercises that bring the energy to 0 or below, or print −1 if doing every exercise twice is not enough. The plan reports it 5 times (SP, 2020–2025) and gives no input format; this chapter reads *E*, *n* and the *n* drains.

Only the number of exercises counts, not which ones, so the largest drains are the best. To make that precise, list each exercise's drain twice.

:::theorem{#thm-24-gym} Largest drains first
Let *E* > 0, and let *d*₁ ≥ *d*₂ ≥ ⋯ ≥ *d*₂ₙ be the drains with every exercise listed twice, in decreasing order. Write *T*ₖ = *d*₁ + ⋯ + *d*ₖ. The fewest exercises is the smallest *k* with *T*ₖ ≥ *E*, or −1 if *T*₂ₙ < *E*.
:::

:::proof
A plan that does *k* exercises, none more than twice, uses *k* entries of the doubled list: the first use of exercise *i* takes one copy of its drain and the second use the other. Any *k* entries of a list add up to at most the sum of its *k* largest entries, so the plan drains at most *T*ₖ. Hence if *T*ₖ < *E*, no plan with *k* exercises works. Conversely, doing the exercises behind *d*₁, …, *d*ₖ is a legal plan, since every exercise has only two copies, and it drains exactly *T*ₖ. The drains are positive, so *T*₁ < *T*₂ < ⋯ < *T*₂ₙ, and the smallest *k* with *T*ₖ ≥ *E* is the answer. If even *T*₂ₙ < *E*, no plan works.
:::

```java {#lst-24-gym} Gym: fewest exercises, each at most twice (input E, n, n drains)
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        FastScanner fs = new FastScanner(System.in);
        long E = fs.nextLong();                       // input: E, n, then n drains
        int n = fs.nextInt();
        long[] drain = new long[n];
        for (int i = 0; i < n; i++) drain[i] = fs.nextLong();
        System.out.println(fewestExercises(E, drain));
    }

    // Fewest uses (each exercise at most twice) that bring E to 0 or below, or -1. O(n log n).
    static int fewestExercises(long E, long[] drain) {
        if (E <= 0) return 0;                         // nothing to do
        long[] d = drain.clone();
        Arrays.sort(d);                               // ascending; walk from the largest
        int used = 0;
        for (int i = d.length - 1; i >= 0; i--) {
            for (int t = 0; t < 2; t++) {             // each exercise at most twice
                E -= d[i];
                used++;
                if (E <= 0) return used;
            }
        }
        return -1;                                    // even every exercise twice is not enough
    }

    static final class FastScanner {                  // Chapter 1's FastScanner, shortened
        private final BufferedReader br;
        private StringTokenizer st;
        FastScanner(InputStream in) { br = new BufferedReader(new InputStreamReader(in)); }
        String next() throws IOException {
            while (st == null || !st.hasMoreTokens()) {
                String line = br.readLine();
                if (line == null) return null;
                st = new StringTokenizer(line);
            }
            return st.nextToken();
        }
        int nextInt() throws IOException { return Integer.parseInt(next()); }
        long nextLong() throws IOException { return Long.parseLong(next()); }
    }
}
```

The sort dominates: O(*n* log *n*) time and O(*n*) memory for the copy. Sorting a `long[]` in ascending order and walking it from the end avoids a `Long[]` with a reversed comparator.

On *E* = 30 with drains 4, 9, 2, 7 the program uses 9, 9, 7, 7, the energy goes 21, 12, 5, −2, and it prints 4. With *E* = 44 it prints 8: all eight uses drain exactly 44, and an energy of 0 counts as drained. With *E* = 45 it prints −1, and with *E* = 0 it prints 0 without using any exercise.

:::pitfall Read the stopping rule
The plan's rule is "until *E* ≤ 0". If your statement requires the energy to become negative, the test becomes `E < 0`, and the answer for *E* = 44 above becomes −1. Run both readings on the samples and keep the one that matches.
:::

The brute force tries every way to use each exercise 0, 1 or 2 times, 3ⁿ ways in all.

```java {#lst-24-gymbrute} Brute force for the gym problem
// Brute force: use each exercise 0, 1 or 2 times, all 3^n ways. O(3^n * n), fine for n <= 10.
static int gymBrute(long E, long[] drain) {
    int n = drain.length, best = Integer.MAX_VALUE, ways = 1;
    for (int i = 0; i < n; i++) ways *= 3;
    for (int code = 0; code < ways; code++) {         // base-3 digit i = uses of exercise i
        int c = code, uses = 0;
        long total = 0;
        for (int i = 0; i < n; i++) {
            int t = c % 3;
            c /= 3;
            uses += t;
            total += t * drain[i];
        }
        if (E - total <= 0) best = Math.min(best, uses);
    }
    return best == Integer.MAX_VALUE ? -1 : best;
}
```

@lst-24-gym agreed with it on 20,000 random cases with up to 7 exercises. In 6,672 of them the answer was −1 and in 1,674 it was 0.

## Andy's vacation {#sec-24-vacation}

Andy's calendar has days 1..*N*, with *N* ≤ 10⁶, and *M* obligations, each on a given day; several may fall on the same day. He may cancel at most *K* of them. Find the longest run of consecutive days with no obligation left. The plan's samples are (*N* = 10, *K* = 2, days 6 9 3 2 7) → 5 and (*N* = 7, *K* = 0, days 3 4) → 3, and it reports the problem 5 times (SP, 2021–2025).

Chapter 3 met this problem as LeetCode 1004 (Max Consecutive Ones III) on a calendar, together with the trap the plan reports: a day with two obligations is free only when both are cancelled, so it costs 2, not 1.

:::definition{#def-24-weighted} Weighted window
A [[weighted window]] problem gives every position a non-negative cost and asks for the longest contiguous range whose total cost is at most a budget *K*. LeetCode 1004 is the case where every cost is 0 or 1.
:::

:::keyidea
Count the obligations on each day, cnt[*d*]. Freeing the days *l*..*r* costs cnt[*l*] + ⋯ + cnt[*r*] cancellations, so the question is a weighted window, and Chapter 3's sliding window works because no cost is negative.
:::

:::theorem{#thm-24-vacation} The window finds the longest free run
(a) The days *l*..*r* can all be made free with at most *K* cancellations if and only if *C*(*l*, *r*) = cnt[*l*] + ⋯ + cnt[*r*] ≤ *K*.

(b) In @lst-24-vacation, after the loop body for *r*, `l` is the smallest *l* ≤ *r* + 1 with *C*(*l*, *r*) ≤ *K* (the empty range *C*(*r* + 1, *r*) costs 0), and `used` = *C*(`l`, *r*). Hence `best` ends as the length of the longest free run.
:::

:::proof
(a) A day is free exactly when every obligation on it is cancelled. Freeing all of *l*..*r* therefore requires cancelling all *C*(*l*, *r*) obligations in the range, and cancelling exactly those is enough.

(b) Write *L*(*r*) for the smallest valid *l*. Costs are non-negative, so *C*(*l*, *r* + 1) ≥ *C*(*l*, *r*): a left end that is too expensive for *r* is too expensive for *r* + 1, and *L*(*r* + 1) ≥ *L*(*r*). Now use induction on *r*. Before the body for *r* runs, `l` is *L*(*r* − 1) (or 1 when *r* = 1) and `used` = *C*(`l`, *r* − 1). Adding cnt[*r*] makes `used` = *C*(`l`, *r*). The `while` loop moves `l` to the right while the cost exceeds *K*, so it stops at the first *l* ≥ *L*(*r* − 1) with *C*(*l*, *r*) ≤ *K*, at the latest at *l* = *r* + 1, where the cost is 0. No *l* < *L*(*r* − 1) is valid for *r*, by the monotonicity just shown, so the loop stops at *L*(*r*). The window [*L*(*r*), *r*] is the longest affordable run that ends at *r*, and `best` is the maximum over all *r*.
:::

```java {#lst-24-vacation} Andy's vacation (input N, K, M, then the M days)
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        FastScanner fs = new FastScanner(System.in);
        int N = fs.nextInt();                         // input: N, K, M, then the M days
        int K = fs.nextInt();
        int M = fs.nextInt();
        int[] cnt = new int[N + 1];                   // cnt[d] = obligations on day d (1-based)
        for (int i = 0; i < M; i++) cnt[fs.nextInt()]++;
        System.out.println(longestFreeRun(N, K, cnt));
    }

    // Longest run of consecutive days whose obligations add up to at most K. O(N).
    static int longestFreeRun(int N, long K, int[] cnt) {
        long used = 0;                                // cancellations the window needs
        int best = 0;
        for (int l = 1, r = 1; r <= N; r++) {
            used += cnt[r];                           // a day costs ALL of its obligations
            while (used > K) used -= cnt[l++];        // shrink until affordable again
            best = Math.max(best, r - l + 1);
        }
        return best;
    }

    static final class FastScanner {                  // Chapter 1's FastScanner, shortened
        private final BufferedReader br;
        private StringTokenizer st;
        FastScanner(InputStream in) { br = new BufferedReader(new InputStreamReader(in)); }
        String next() throws IOException {
            while (st == null || !st.hasMoreTokens()) {
                String line = br.readLine();
                if (line == null) return null;
                st = new StringTokenizer(line);
            }
            return st.nextToken();
        }
        int nextInt() throws IOException { return Integer.parseInt(next()); }
        long nextLong() throws IOException { return Long.parseLong(next()); }
    }

## Wine buying and selling {#sec-24-wine}

Houses stand in a line, one unit apart. House *i* wants to buy *a*[*i*] bottles if *a*[*i*] > 0, or to sell −*a*[*i*] bottles if *a*[*i*] < 0, and the values add up to 0. Carrying one bottle from a house to its neighbour costs one unit of work. Find the least total work that satisfies every house. The plan reports the problem 6 times (SP, 2022–2026) and names GfG Wine Buying and Selling as its judge. The GfG version asks for a method that receives the array; the program below reads *n* and then the *n* values.

Let *P*ᵢ = *a*[0] + ⋯ + *a*[*i*] be the net demand of houses 0..*i*: positive when they are short of bottles, negative when they have bottles to spare.

:::definition{#def-24-cut} Cut argument
A [[cut argument]] proves a lower bound by splitting the input into two sides and counting what must cross between them. In the wine problem the cut is the gap between house *i* and house *i* + 1.
:::

:::theorem{#thm-24-wine} The work is the sum of the absolute prefix sums
If *a*[0] + ⋯ + *a*[*n* − 1] = 0, the least total work is |*P*₀| + |*P*₁| + ⋯ + |*P*ₙ₋₂|.
:::

:::proof
Describe a plan as a list of single bottles, each carried from a selling house *s* to a buying house *b* at cost |*s* − *b*|. Such a bottle crosses each of the |*s* − *b*| gaps between the two houses once, so the work of a plan is its total number of gap crossings.

*Lower bound.* Fix the gap after house *i*, and let houses 0..*i* buy *B*ᵢ and sell *S*ᵢ bottles, so that *B*ᵢ − *S*ᵢ = *P*ᵢ. If *P*ᵢ > 0, at most *S*ᵢ of the bottles bought on the left can come from the left, so at least *P*ᵢ come across the gap. If *P*ᵢ < 0, at most *B*ᵢ of the bottles sold on the left can stay on the left, so at least −*P*ᵢ cross. Either way at least |*P*ᵢ| bottles cross this gap, and adding over the *n* − 1 gaps, every plan does at least Σ |*P*ᵢ| work.

*A plan that meets the bound.* List the sold bottles from left to right (a house that sells three bottles gives three consecutive numbers), list the bought bottles the same way, and carry sold bottle *t* to bought bottle *t*. At the gap after house *i*, sold bottles 1..*S*ᵢ and bought bottles 1..*B*ᵢ are on the left. Bottle *t* crosses the gap exactly when one of *t* ≤ *S*ᵢ and *t* ≤ *B*ᵢ holds and the other does not, which happens for the |*B*ᵢ − *S*ᵢ| = |*P*ᵢ| values of *t* between the two numbers. So this plan crosses every gap exactly |*P*ᵢ| times, and its work is Σ |*P*ᵢ|.
:::

The theorem gives an O(*n*) program with O(1) extra memory: one running sum and one running total of its absolute values.

```java {#lst-24-wine} Wine buying and selling (input n, then n values)
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        FastScanner fs = new FastScanner(System.in);
        int n = fs.nextInt();                         // input: n, then n values (+ buy, - sell)
        long[] a = new long[n];
        for (int i = 0; i < n; i++) a[i] = fs.nextLong();
        System.out.println(minWork(a));
    }

    // Minimum work when the values add up to 0: the sum of |prefix| over the n - 1 gaps. O(n).
    static long minWork(long[] a) {
        long carry = 0, work = 0;                     // carry = a[0] + ... + a[i]
        for (int i = 0; i + 1 < a.length; i++) {
            carry += a[i];                            // what must cross the gap after house i
            work += Math.abs(carry);
        }
        return work;
    }

    static final class FastScanner {                  // Chapter 1's FastScanner, shortened
        private final BufferedReader br;
        private StringTokenizer st;
        FastScanner(InputStream in) { br = new BufferedReader(new InputStreamReader(in)); }
        String next() throws IOException {
            while (st == null || !st.hasMoreTokens()) {
                String line = br.readLine();
                if (line == null) return null;
                st = new StringTokenizer(line);
            }
            return st.nextToken();
        }
        int nextInt() throws IOException { return Integer.parseInt(next()); }
        long nextLong() throws IOException { return Long.parseLong(next()); }
    }
}

## Arrays where each element divides the next {#sec-24-divchain}

Count the arrays *b*[0..*K* − 1] with values in 1..*N* such that *b*[*i*] divides *b*[*i* + 1] for every *i*, and print the count modulo 10000. With 13 reports (DSE, 2021–2025) this is the most reported of today's problems. The samples are (*N* = 2, *K* = 1) → 2, (2, 2) → 3 and (3, 2) → 5, and the program reads *N* and then *K*. The first sample fixes that order: read the other way round, it would mean *N* = 1 and *K* = 2, which has one array, [1, 1].

Chapter 14 solved the counting. Squash each run of equal neighbours into one value; what remains is a strictly increasing [[divisor chain]] with *s* distinct values, and *s* ≤ ⌊log *N*⌋ + 1 because each step at least doubles the value. A chain with *s* values extends to C(*K* − 1, *s* − 1) arrays of length *K*, one for each choice of the *s* − 1 places, among the *K* − 1 gaps, where the value changes. What the Infosys version adds is the modulus.

:::definition{#def-24-composite} Composite modulus
A modulus *m* is a [[composite modulus]] when it is not prime. Modulo *m*, a number *x* has an inverse exactly when gcd(*x*, *m*) = 1. The modulus 10000 = 2⁴ · 5⁴ is composite: 3 · 6667 = 20001 ≡ 1, so 3 has an inverse, but 2 has none, because 2*y* is even and never leaves remainder 1.
:::

The factorial formula for C(*n*, *r*) needs the inverse of *r*! (*n* − *r*)!, which is even as soon as *r* ≥ 2 or *n* − *r* ≥ 2, and every factorial from 20! on is 0 modulo 10000 (19! leaves 2000). So the binomials come from Pascal's rule (Chapter 10), which only adds. Only C(*K* − 1, *j*) for *j* < *S* = ⌊log *N*⌋ + 1 is needed, so the program keeps the first *S* entries of one row of Pascal's triangle and updates them from right to left, up to row *K* − 1.

:::theorem{#thm-24-divchain} Divisor arrays from chain counts and binomials
Let ch(*s*, *v*) be the number of strictly increasing divisor chains with *s* values in 1..*N* that end at *v*. Then ch(1, *v*) = 1, ch(*s* + 1, *m*) is the sum of ch(*s*, *v*) over the proper divisors *v* of *m*, and the number of arrays is

  Σ over *s* = 1..*S* of (Σ over *v* of ch(*s*, *v*)) · C(*K* − 1, *s* − 1).

Computing every quantity modulo 10000, with the binomials from Pascal's rule, gives the count modulo 10000.
:::

:::proof
A chain with *s* + 1 values that ends at *m* has a unique last-but-one value *v*, a proper divisor of *m*, and removing *m* leaves a chain with *s* values that ends at *v*. Conversely, appending *m* to a chain that ends at a proper divisor of *m* gives a chain that ends at *m*. This proves the recurrence. The formula is Chapter 14's stars-and-bars theorem: an array determines its chain of distinct values and its *s* run lengths, which are positive and add up to *K*; every such pair gives an array; and *K* splits into *s* positive ordered parts in C(*K* − 1, *s* − 1) ways. Chains have at most *S* values, so the sum can stop at *S*. Finally, the remainder of a sum or a product modulo *m* depends only on the remainders of its operands, so reducing after every addition and multiplication gives the true count modulo 10000, and Pascal's rule produces each C(*K* − 1, *j*) from additions alone.
:::

```java {#lst-24-divchain} Arrays where each element divides the next, mod 10000 (input N, then K)
import java.io.*;
import java.util.*;

public class Main {
    static final int MOD = 10000;                     // not prime: no inverses, only additions

    public static void main(String[] args) throws IOException {
        FastScanner fs = new FastScanner(System.in);
        int N = fs.nextInt();                         // input: N, then K
        int K = fs.nextInt();
        System.out.println(countArrays(N, K));
    }

    // Arrays of length K, values in 1..N, each element divides the next, counted mod 10000.
    static int countArrays(int N, int K) {
        int S = 1;
        while ((1L << S) <= N) S++;                   // S = floor(log2 N) + 1: longest chain
        // c[j] = C(K - 1, j) mod 10000 for j < S, by Pascal's rule, one row at a time
        int[] c = new int[S];
        c[0] = 1;
        for (int row = 1; row <= K - 1; row++)
            for (int j = Math.min(row, S - 1); j >= 1; j--) c[j] = (c[j] + c[j - 1]) % MOD;
        // cur[v] = strictly increasing divisor chains with s values that end at v (mod 10000)
        int[] cur = new int[N + 1], next = new int[N + 1];
        Arrays.fill(cur, 1, N + 1, 1);                // s = 1: the chain (v) alone
        long ans = 0;
        for (int s = 1; s <= S; s++) {
            long total = 0;                           // chains with s values, any end
            for (int v = 1; v <= N; v++) total += cur[v];
            ans = (ans + total % MOD * c[s - 1]) % MOD;  // each one gives C(K-1, s-1) arrays
            if (s == S) break;
            Arrays.fill(next, 0);
            for (int v = 1; v <= N; v++) {
                if (cur[v] == 0) continue;
                for (int m = 2 * v; m <= N; m += v)   // append a proper multiple of v
                    next[m] = (next[m] + cur[v]) % MOD;
            }
            int[] t = cur; cur = next; next = t;
        }
        return (int) ans;
    }

    static final class FastScanner {                  // Chapter 1's FastScanner, shortened
        private final BufferedReader br;
        private StringTokenizer st;
        FastScanner(InputStream in) { br = new BufferedReader(new InputStreamReader(in)); }
        String next() throws IOException {
            while (st == null || !st.hasMoreTokens()) {
                String line = br.readLine();
                if (line == null) return null;
                st = new StringTokenizer(line);
            }
            return st.nextToken();
        }
        int nextInt() throws IOException { return Integer.parseInt(next()); }
        long nextLong() throws IOException { return Long.parseLong(next()); }
    }
}
```

The program runs Chapter 14's push loop once per chain length, keeping two rows, `cur` and `next`, and adding up each row before it is replaced. On the three samples it prints 2, 3 and 5. A reduced count can be 0 although chains end at *v*; skipping that `v` is still correct, because adding a residue 0 changes nothing.

## Choosing X ≤ K for a sum of XORs {#sec-24-xorx}

Given *n* values *A*[*i*] and a limit *K*, choose an integer *X* with 0 ≤ *X* ≤ *K* that makes Σ (*X* ⊕ *A*[*i*]) as large as possible. The plan reports the problem 6 times (2021–2025) and gives no input format; this chapter reads *n*, *K* and the *n* values, all below 2³¹, and prints the largest sum. Chapter 8 developed the method; this section turns it into a program and proves the program correct.

Two facts from Chapter 8 do the work. First, each bit of *X* contributes to the sum on its own: if *c*<sub>*b*</sub> of the values have bit *b* set, then *X*<sub>*b*</sub> = 0 contributes keep[*b*] = *c*<sub>*b*</sub> · 2ᵇ and *X*<sub>*b*</sub> = 1 contributes flip[*b*] = (*n* − *c*<sub>*b*</sub>) · 2ᵇ. Second, the numbers below *K* have a fixed shape.

:::definition{#def-24-branch} Branch point
For 0 ≤ *X* < *K*, the [[branch point]] of *X* is the highest bit position *b* at which *X* and *K* differ. At that position *K*<sub>*b*</sub> = 1 and *X*<sub>*b*</sub> = 0; above it *X* copies *K*; below it *X* is arbitrary.
:::

So [0, *K*] splits into *K* itself and one family for each set bit *b* of *K*: the numbers whose branch point is *b*. Inside a family the bits above *b* and the bit *b* are fixed, and the bits below *b* are free.

:::theorem{#thm-24-xorx} One candidate per set bit of K
For a set bit *b* of *K*, let cand(*b*) be the share of the bits above *b* copied from *K*, plus keep[*b*], plus Σ over *j* < *b* of max(keep[*j*], flip[*j*]). The largest sum over 0 ≤ *X* ≤ *K* is the maximum of the sum for *X* = *K* and all cand(*b*), and @lst-24-xorx returns it.
:::

:::proof
By Chapter 8's lemma on the numbers below *K*, every *X* < *K* has exactly one branch point *b*, a set bit of *K*, and every number of that shape is below *K*. The sum of XORs is the sum of the bit contributions. For an *X* with branch point *b*, the bits above *b* contribute the copied share, bit *b* contributes keep[*b*], and each lower bit *j* contributes keep[*j*] or flip[*j*] independently of the other bits. The best member of the family therefore takes the larger value at every *j*, and its sum is cand(*b*). Together with *X* = *K*, the families cover [0, *K*], so the maximum of the candidates is the answer.

In the listing, `above` is the share of the bits above the current *b* when they are copied from *K*: at a 1-bit of *K* it adds flip[*b*], at a 0-bit keep[*b*]. `free[b]` is the free maximum of bits 0..*b* − 1, so the branch line evaluates cand(*b*), and after the loop `above` is the sum for *X* = *K*.
:::

```java {#lst-24-xorx} Choose X <= K maximising the sum of X xor A[i] (input n, K, then n values)
import java.io.*;
import java.util.*;

public class Main {
    static final int B = 31;                          // every A[i] and K is below 2^31

    public static void main(String[] args) throws IOException {
        FastScanner fs = new FastScanner(System.in);
        int n = fs.nextInt();                         // input: n, K, then n values
        long K = fs.nextLong();
        int[] a = new int[n];
        for (int i = 0; i < n; i++) a[i] = fs.nextInt();
        System.out.println(bestSum(K, a));
    }

    // Largest sum of (X xor a[i]) over 0 <= X <= K. O(31 n) to count bits, then O(31).
    static long bestSum(long K, int[] a) {
        int n = a.length;
        long[] keep = new long[B], flip = new long[B];  // bit b's share if X_b = 0 / X_b = 1
        for (int b = 0; b < B; b++) {
            long ones = 0;
            for (int x : a) ones += (x >> b) & 1;
            keep[b] = ones << b;                      // X_b = 0: elements with the bit keep it
            flip[b] = (n - ones) << b;                // X_b = 1: elements without it gain it
        }
        long[] free = new long[B + 1];                // free[b] = best free choice, bits 0..b-1
        for (int b = 0; b < B; b++) free[b + 1] = free[b] + Math.max(keep[b], flip[b]);
        long best = Long.MIN_VALUE, above = 0;        // above = share of the bits copied from K
        for (int b = B - 1; b >= 0; b--) {
            if (((K >> b) & 1) == 1) {
                best = Math.max(best, above + keep[b] + free[b]);  // branch: 0 here, free below
                above += flip[b];                     // or stay equal to K: 1 here
            } else {
                above += keep[b];
            }
        }
        return Math.max(best, above);                 // above is now the sum for X = K
    }

    static final class FastScanner {                  // Chapter 1's FastScanner, shortened
        private final BufferedReader br;
        private StringTokenizer st;
        FastScanner(InputStream in) { br = new BufferedReader(new InputStreamReader(in)); }
        String next() throws IOException {
            while (st == null || !st.hasMoreTokens()) {
                String line = br.readLine();
                if (line == null) return null;
                st = new StringTokenizer(line);
            }
            return st.nextToken();
        }
        int nextInt() throws IOException { return Integer.parseInt(next()); }
        long nextLong() throws IOException { return Long.parseLong(next()); }
    }
}
```

The edge case *K* = 0 needs no special code: the loop never branches, and the answer is the sum for *X* = 0, which is Σ *A*[*i*].

On Chapter 8's example, *A* = [1, 4, 6, 3, 2], the program prints 21 for *K* = 6 and 20 for *K* = 4, the values found there by hand. If your statement asks for *X* instead of the sum, record the *X* of the best candidate: *K*'s bits above *b*, a 0 at *b*, and below *b* a 1 exactly where flip[*j*] > keep[*j*]. For *K* = 6 that gives *X* = 5, as in @fig-24-xorx.

@lst-24-xorx matched a brute force over every *X* on 20,000 random cases with up to 6 values below 64 and *K* < 90. On 20,000 more cases with up to 50 values and *K* anywhere in [0, 2³¹ − 1], it matched an independent DP over the bits with a "still equal to *K*" flag, the digit DP of Chapter 22.

## Increasing subsequences with a bitwise condition {#sec-24-lisbit}

Find the longest increasing subsequence of *a* in which every pair of neighbours *x*, *y* satisfies (*x* & *y*) · 2 < (*x* | *y*). The plan's samples are [15, 6, 5, 12, 1] → 2, [9, 17, 2, 15, 5, 2] → 2 and [17, 16, 12, 2, 8, 17, 17] → 3, and it reports the problem 4 times (SP). The program reads *n* and then the *n* values, all non-negative.

Chapter 13 asks of every new condition what you must know about the subsequence so far to decide whether *x* may be appended. The plan's hint answers it: compare pairs with the same highest set bit and pairs where it differs.

:::definition{#def-24-level} Highest set bit and level
For *x* ≥ 1, the [[highest set bit]] hb(*x*) is the position of the leftmost 1 of *x* in binary, so 2<sup>hb(*x*)</sup> ≤ *x* < 2<sup>hb(*x*)+1</sup>. The *level* of *x* is lev(*x*) = hb(*x*) + 1 for *x* ≥ 1, and lev(0) = 0.
:::

:::lemma{#lem-24-cond} The condition compares highest bits
For non-negative integers *x* and *y*, (*x* & *y*) · 2 < (*x* | *y*) if and only if lev(*x*) ≠ lev(*y*).
:::

:::proof
A bit set in *x* | *y* is set either in both numbers or in exactly one of them, so *x* | *y* = (*x* & *y*) + (*x* ⊕ *y*). The condition 2(*x* & *y*) < (*x* & *y*) + (*x* ⊕ *y*) is therefore the same as *x* & *y* < *x* ⊕ *y*.

If lev(*x*) = lev(*y*) = 0, both numbers are 0, and 0 < 0 is false. If lev(*x*) = lev(*y*) = *h* + 1 ≥ 1, both have bit *h* and no higher bit. Then *x* & *y* has bit *h* set, while *x* ⊕ *y* has no bit at *h* or above, so by Chapter 8's top-bit lemma *x* & *y* > *x* ⊕ *y*, and the condition fails. If the levels differ, say lev(*x*) < lev(*y*) with *h* = hb(*y*), then *x* < 2ʰ, so *x* & *y* ≤ *x* < 2ʰ, while *x* ⊕ *y* has bit *h* (set in *y*, clear in *x*), so *x* ⊕ *y* ≥ 2ʰ > *x* & *y*, and the condition holds.
:::

The plan's author checked the equivalence on every pair up to 600. The lemma proves it for all pairs, and a direct check of all 4,194,304 pairs below 2048 agreed.

For neighbours *x* < *y* with different levels, *y* must have the higher level, because a number of lower level is smaller. So a subsequence is valid exactly when the levels of its elements strictly increase from left to right, and the values then increase by themselves. A non-negative `int` has one of 32 levels, so the answer is at most 32, and the state that matters is the level of the last element. In Java the level of `x` is `32 - Integer.numberOfLeadingZeros(x)`.

:::theorem{#thm-24-lisbit} DP over 32 levels
Read *a* from left to right. For an element *x* of level *l*, set best[*l*] to the larger of best[*l*] and 1 + max(best[0], …, best[*l* − 1]), where the maximum of an empty list is 0. After each step, best[*l*] is the length of the longest valid subsequence of the elements read so far whose last element has level *l*, and the answer is the largest best[*l*].
:::

:::proof
Induction on the number of elements read. At the start every best[*l*] is 0 and there is no subsequence. Let the next element be *x*, of level *l*. A valid subsequence that ends with *x* is either *x* alone, or a valid subsequence of the earlier elements that ends at some level *j* < *l*, followed by *x*. By the induction hypothesis the longest of these has length 1 + max(best[0..*l* − 1]). Subsequences that do not end with *x* are the same as before. So the new best[*l*] is the larger of its old value and this candidate, and every other entry stays correct.
:::

```java {#lst-24-lisbit} LIS with (x & y) * 2 < (x | y) between neighbours (input n, then n values)
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        FastScanner fs = new FastScanner(System.in);
        int n = fs.nextInt();                         // input: n, then n values (all >= 0)
        int[] a = new int[n];
        for (int i = 0; i < n; i++) a[i] = fs.nextInt();
        System.out.println(longestChain(a));
    }

    // Longest increasing subsequence whose neighbouring pairs all have (x & y) * 2 < (x | y).
    // Such a subsequence is one whose levels (1 + highest set bit) strictly increase. O(32 n).
    static int longestChain(int[] a) {
        int[] best = new int[33];                     // best[l]: longest ending at level l
        int ans = 0;
        for (int x : a) {
            int l = 32 - Integer.numberOfLeadingZeros(x);  // 0 for x = 0, else 1 + highest bit
            int prev = 0;
            for (int j = 0; j < l; j++) prev = Math.max(prev, best[j]);
            best[l] = Math.max(best[l], prev + 1);
            ans = Math.max(ans, best[l]);
        }
        return ans;
    }

    static final class FastScanner {                  // Chapter 1's FastScanner, shortened
        private final BufferedReader br;
        private StringTokenizer st;
        FastScanner(InputStream in) { br = new BufferedReader(new InputStreamReader(in)); }
        String next() throws IOException {
            while (st == null || !st.hasMoreTokens()) {
                String line = br.readLine();
                if (line == null) return null;
                st = new StringTokenizer(line);
            }
            return st.nextToken();
        }
        int nextInt() throws IOException { return Integer.parseInt(next()); }
        long nextLong() throws IOException { return Long.parseLong(next()); }
    }
}
```

The time is O(32 · *n*) and the memory 33 integers. The program never computes (*x* & *y*) · 2, which matters for the brute force you write next to it: once *x* & *y* ≥ 2³⁰, the product overflows `int`, turns negative and makes the test true. Compute it in `long` there.

## Three bonus problems: the key observations {#sec-24-bonus}

The three remaining bonus problems get only the observation that opens each of them.

**Smallest base with identical digits.** Given *M* ≤ 10¹², find the smallest base *B* in which every digit of *M* is the same. The plan's samples are 41 → 40 and 34430 → 312, and it reports the problem 10 times (SP, 2021–2026). Checking one base costs O(log *M*) divisions, but *B* can be almost as large as *M*. The plan's hint gives the observation: once *B* > 10⁶, *B*² > 10¹² ≥ *M*, so *M* has at most two digits in base *B*, and a two-digit number with both digits equal to *d* is *d* · *B* + *d* = *d* · (*B* + 1). So only the small bases need the digit-by-digit check, and the large ones turn into a question about the divisors of *M*. On a small example, *M* = 57 written in bases 2 to 7 is 111001, 2010, 321, 212, 133 and 111, so its answer is 7.

**CF 1338A (Powered Addition).** In second *t* you may add 2<sup>*t*−1</sup> to any elements you choose, and the array must become non-decreasing as early as possible. The observation: after *T* seconds an element can have received any amount from 0 to 2ᵀ − 1, chosen independently for each element, because each such amount is a sum of distinct powers among 1, 2, …, 2<sup>*T*−1</sup>. The plan names this as the idea behind the Infosys problem of making a terrain strictly decreasing in the fewest days (6 reports, SP, 2021–2025).

**CF 1514C (Product 1 Modulo N).** Find the longest subsequence of 1, 2, …, *n* − 1 whose product is 1 modulo *n*; the Infosys form asks for the largest such subset (4 reports, 2023–2025). The observation: a number that shares a prime factor *p* with *n* can never be used. The product would then be a multiple of *p*, and a multiple of *p* cannot be 1 more than a multiple of *n*, since *p* divides *n*. Only the numbers coprime to *n* remain, and what is left to decide is what their product forces you to drop.

## Summary

- The repeat problems have no judge. Write a full program that reads one value per line in the order of the samples, keep `solve` apart from `main`, and stress-test it against a brute force in the same file.
- Use `long` for sums, experience, energy, work and XOR totals, cast before multiplying, and keep residues reduced.
- Monsters: with non-negative bonuses, sorting by power and fighting while possible beats a set that contains every beatable set. With negative bonuses the greedy is wrong.
- Gym: list every drain twice; the top-*k* sum is the most that *k* exercises can drain, so take the largest first and print −1 when the whole list is not enough.
- Andy's vacation: a day costs its number of obligations, and the longest window of total cost at most *K* comes from Chapter 3's window in O(*N* + *M*).
- Wine: every gap must carry |*P*ᵢ| bottles, and the left-to-right pairing carries exactly that many, so the answer is Σ |*P*ᵢ|, in `long`.
- Divisor arrays modulo 10000: count chains by pushing to multiples, weight the chains with *s* values by C(*K* − 1, *s* − 1), and build the binomials with Pascal's rule, because 10000 is not prime.
- X ≤ K: the candidates are *K* and one family per set bit of *K*, each maximised bit by bit, in O(31 *n*).
- The bitwise LIS condition holds exactly when the highest set bits differ, so the levels strictly increase and a DP over 32 levels solves the problem in O(32 *n*).

2. Where exactly does the proof of @thm-24-monsters use non-negative bonuses? Find that step in the counterexample *e* = 4, powers [3, 1, 2], bonuses [2, 0, −3].
3. If each exercise in the gym problem could be used at most three times, what would change in @thm-24-gym and @lst-24-gym? What if there were no limit at all?
4. For *N* = 5, *K* = 1 and two obligations on day 3, what is the answer, and what does a window that charges 1 per busy day print? Which part of @thm-24-vacation does that window break?
5. In an optimal wine plan, how many bottles cross the gap after house *i*? Why can no optimal plan cross some gap more often?
6. Modulo 10000, 3 has an inverse but 2 does not. Why does that rule out computing C(*K* − 1, *s* − 1) from factorials, even though some inverses exist?
7. For *K* = 2³¹ − 1, how many candidates does @lst-24-xorx compare, and why is *X* = *K* treated separately from the families?
8. Use @lem-24-cond to decide the condition for the pairs (12, 9) and (5, 12) without computing it. Then check with the operators.

:::answers
1. A copy can drift away from the submitted method, and then a passing stress test says nothing about the submission. Calling `solve` tests the exact code you submit. The loop does not test `main`, that is the reading of the input and the printing; the samples test those.
2. The step "the experience when *u* is fought is at most *E*". In the counterexample *G* = {power 1, power 2} and *E* = 4 + 0 − 3 = 1, but the best order fights power 3, the first monster outside *G*, with experience 4 > *E*. The negative bonus inside *G* pushed *E* below an experience that another order reaches.
3. With three uses, list every drain three times; the proof is unchanged, and the inner loop runs `t < 3`. With no limit, every use takes the largest drain *d*, so the answer is ⌈*E*/*d*⌉ for *E* > 0.
4. The answer is 2 (days 1..2 or 4..5); the buggy window prints 5. It breaks part (a): freeing day 3 needs cnt[3] = 2 cancellations, not 1.
5. Exactly |*P*ᵢ|. Every plan crosses each gap at least |*P*ᵢ| times, and the optimum is Σ |*P*ᵢ| by @thm-24-wine, so one extra crossing anywhere would make the work larger than the optimum.
6. The formula needs the inverse of *r*! (*n* − *r*)!, which is even as soon as *r* ≥ 2 or *n* − *r* ≥ 2, so it shares the factor 2 with 10000 and has no inverse. Also *n*! is 0 modulo 10000 for every *n* ≥ 20, and nothing can recover C(*n*, *r*) from 0.
7. *K* has 31 set bits, so there are 31 families plus *X* = *K*: 32 candidates. A branch point exists only for *X* < *K*, so *K* belongs to no family; the final `Math.max(best, above)` checks it.
8. 12 = 1100₂ and 9 = 1001₂ both have level 4, so the condition fails: 12 & 9 = 8 and 8 · 2 = 16 is not below 12 | 9 = 13. 5 = 101₂ has level 3 and 12 has level 4, so the condition holds: 5 & 12 = 4 and 4 · 2 = 8 < 5 | 12 = 13.
:::

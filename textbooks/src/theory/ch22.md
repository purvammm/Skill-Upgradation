Some problems have a tiny input and a huge space of answers. Twenty items have 2²⁰ ≈ 10⁶ subsets and 20! ≈ 2.4 · 10¹⁸ orders, and the integers up to 10¹⁸ cannot be listed at all. Chapter 9 enumerated complete candidates, every subset with a bitmask loop and every order with recursion and undo. This chapter goes three steps further.

Backtracking builds a candidate one choice at a time and abandons a partial candidate as soon as no completion of it can work. Bitmask DP starts from an observation about searches over orders: often the future depends only on *which* items have been used, not on their order, so one stored answer per set replaces *n*! by 2ⁿ. Digit DP counts the integers up to *N* with a property by walking the digits of *N* from the left; it turns the "follow the limit, then branch off below it" walk of Chapter 8 into a general method.

All three follow the same discipline: say what a state is, prove that the evaluation order is valid, and count the states before you write code.

## Backtracking: depth-first search over partial solutions {#sec-22-backtrack}

A brute force in the style of Chapter 9 generates each complete candidate and then tests it. When a candidate is built from a sequence of choices, the testing can start earlier: if the first three choices already break a rule, no candidate that starts with them needs to be generated.

:::definition{#def-22-backtrack} Backtracking and the search tree
A *partial solution* is the sequence of choices made so far. The [[search tree]] has one node for each partial solution the search visits: the root is the empty partial solution, and the children of a node extend it by one more choice. [[Backtracking|backtracking]] is a depth-first traversal of the search tree that stops descending below a node as soon as a check shows that no extension of it can be a solution.
:::

The search keeps one shared description of the current node, such as a list `cur` of chosen values, and changes it in place: *choose* moves to a child, a recursive call explores it, and *undo* reverses the choice on the way back. Copying the state into every child would cost time proportional to its size at every node.

The running example is a classic. Given a sorted array *a* of distinct positive integers and a target *T*, list every subset whose sum is exactly *T*. A node is a sequence of chosen indices i₁ < i₂ < ⋯ < iₖ, stored as their values in `cur`, together with `remain`, which is *T* minus their sum. Its children choose one more index *i* > iₖ, so each subset is built in exactly one order.

```java {#lst-22-sumsub} Backtracking: every subset of a sorted array of distinct positive values with sum exactly target
static void sumSubsets(int[] a, int start, int remain, List<Integer> cur, List<List<Integer>> out) {
    if (remain == 0) {
        out.add(new ArrayList<>(cur));                  // copy: cur keeps changing
        return;
    }
    for (int i = start; i < a.length; i++) {
        if (a[i] > remain) break;                       // prune: a is sorted, later values are larger
        cur.add(a[i]);                                  // choose
        sumSubsets(a, i + 1, remain - a[i], cur, out);  // recurse: each element at most once
        cur.remove(cur.size() - 1);                     // undo
    }
}
```

Call it as `sumSubsets(a, 0, T, new ArrayList<Integer>(), out)`. It has the shape of the handbook's template for LeetCode 39 (Combination Sum), except that the recursive call passes `i + 1` instead of `i`, because here each element may be used at most once.

:::lemma{#lem-22-undo} Undo restores the state
When a call of `sumSubsets` returns, `cur` holds exactly the values it held when the call started.
:::

:::proof
By induction on the height of the call's subtree. A call that returns at once, because `remain` is 0 or because its loop makes no iteration, does not touch `cur`. Otherwise each iteration appends one value, makes a call whose subtree is lower, and removes the last value. By the induction hypothesis the inner call leaves `cur` as it found it, so the removal deletes exactly the value that was appended, and the iteration ends with `cur` unchanged. Hence so does the whole loop.
:::

:::theorem{#thm-22-sumsub} Correctness of the subset search
@lst-22-sumsub adds to `out` every subset of *a* with sum *T*, each exactly once (as its values in increasing order), and nothing else.
:::

:::proof
By @lem-22-undo, at every node `cur` holds the values at the chosen indices i₁ < ⋯ < iₖ and `remain` is *T* minus their sum. Different nodes have different index sequences, so no subset is added twice, and a subset is added only when `remain` = 0, that is, when its sum is *T*.

Now take any subset with sum *T* and indices i₁ < ⋯ < iₖ. Every proper prefix i₁, …, iⱼ with *j* < *k* has a sum below *T*, because the values left out are positive, so its node does not stop at the `remain == 0` test. Its loop starts at iⱼ + 1, and every index it meets before iⱼ₊₁ holds a smaller value than *a*[iⱼ₊₁], because *a* is sorted. And *a*[iⱼ₊₁] ≤ `remain`, because that value and the rest of the subset add up to exactly `remain`. So the `break` cannot fire before the loop reaches iⱼ₊₁, and the search descends to the next prefix. By induction on *j* it reaches the node of the whole subset, where `remain` = 0 and the subset is added.
:::

:::pitfall
`out.add(cur)` without the copy adds the same list object every time. The search keeps changing that list and empties it at the end, so for *a* = [2, 3, 5, 6, 8] and *T* = 10 the output is [[], []]: the right number of answers, all of them empty.
:::

### Why recursion is fine here

Each call goes one element deeper, so the recursion is at most *n* + 1 calls deep, about 20 frames for *n* ≤ 20. Chapters 9 and 11 measured Java's default stack overflowing only at roughly 10⁴ to 3 · 10⁴ simple calls, so recursion is safe here and is the clearest way to write the search. The limit that matters is time: the tree can have 2ⁿ nodes or more.

## Pruning and the size of the search tree {#sec-22-prune}

The running time of a backtracking search is the number of nodes visited times the work per node. Pruning changes the first factor, so it helps to know how large the trees are without it.

:::claim{#thm-22-nodes} Sizes of the unpruned trees
Without pruning, the subset tree of @lst-22-sumsub has exactly 2ⁿ nodes. The tree that builds the permutations of *n* items one position at a time, as the handbook's `permutations` template does, has Σ from *k* = 0 to *n* of *n*!/(*n* − *k*)! nodes, which is less than *e* · *n*! ≈ 2.72 · *n*!.
:::

:::proof
In the subset tree each node is an increasing sequence of indices, that is, a subset of {0, …, *n* − 1}, and every subset occurs once, so there are 2ⁿ nodes. In the permutation tree the nodes at depth *k* are the ordered sequences of *k* distinct items, and there are *n*(*n* − 1)⋯(*n* − *k* + 1) = *n*!/(*n* − *k*)! of them. Writing *j* = *n* − *k*, the total is *n*! · Σ from *j* = 0 to *n* of 1/*j*!, and that sum is less than the infinite series Σ 1/*j*! = *e*.
:::

For *n* = 8 the permutation tree has 109,601 nodes, which is ⌊*e* · 8!⌋: about *e* nodes per permutation.

:::definition{#def-22-prune} Pruning
[[Pruning|pruning]] a node means not exploring its subtree. A pruning rule is *safe* when it never prunes a node that has a solution in its subtree.
:::

The `break` of @lst-22-sumsub is safe by @thm-22-sumsub: once *a*[*i*] > `remain`, every later value is larger still. A second safe check uses the opposite bound: if the values still available add up to less than `remain`, no extension reaches the target. With suffix sums *suf*[*i*] = *a*[*i*] + ⋯ + *a*[*n* − 1], it is the line `if (suf[start] < remain) return;` right after the `remain == 0` test.

### N-Queens

LeetCode 51 (N-Queens), a bonus problem today, places *n* queens on an *n* × *n* board so that no two attack each other. The key observation is that every row holds exactly one queen, so the search places queens row by row. All squares of one diagonal share *r* − *c* and all squares of one anti-diagonal share *r* + *c*, so three boolean arrays (columns, *r* − *c* + *n* − 1 and *r* + *c*) make the check and the undo O(1). For *n* = 8 such a search visits 2,057 nodes, against 109,601 in the permutation tree and 8⁸ ≈ 1.7 · 10⁷ ways to put one queen in each row.

## From orders to sets: DP over masks {#sec-22-masks}

Chapter 9's brute force for the monster-fighting repeat problem tried every order of fights. A node of that search knows the set of monsters beaten so far and the current experience, which is the starting value plus the bonuses of the beaten monsters, a function of the set alone. So two nodes with the same set have identical subtrees, and one answer per set, 2ⁿ of them, is enough.

```java {#lst-22-fights} Chapter 9's search over fight orders, memoised on the set of monsters beaten: O(2^n * n)
static int bestFightsMemo(long e0, int[] power, int[] bonus) {
    int[] memo = new int[1 << power.length];
    Arrays.fill(memo, -1);
    return fights(0, e0, power, bonus, memo);
}

static int fights(int used, long e0, int[] power, int[] bonus, int[] memo) {
    if (memo[used] != -1) return memo[used];
    long e = e0;                                        // the experience depends only on the set used
    for (int i = 0; i < power.length; i++) if ((used & (1 << i)) != 0) e += bonus[i];
    int best = 0;
    for (int i = 0; i < power.length; i++) {
        if ((used & (1 << i)) != 0 || e < power[i]) continue;
        best = Math.max(best, 1 + fights(used | (1 << i), e0, power, bonus, memo));
    }
    return memo[used] = best;
}
```

On 5,000 random instances with up to 8 monsters, including negative bonuses, it agreed with Chapter 9's search over all orders.

:::definition{#def-22-maskdp} Bitmask DP
A [[bitmask DP|bitmask DP (DP over subsets)]] is a dynamic programme whose state contains a subset of a small ground set {0, …, *n* − 1}, stored as an integer *mask* whose bit *j* is 1 exactly when item *j* is in the subset (Chapter 8). The table is an array indexed by the mask, possibly with more indices, as in dp[*mask*][*last*].
:::

Chapter 11's recipe needs an evaluation order in which every state comes after the states it reads. For masks one order always works.

:::theorem{#thm-22-order} Increasing masks form a valid order
If *S* ⊊ *T* are subsets of {0, …, *n* − 1}, the mask of *S* is numerically smaller than the mask of *T*. Consequently, a bitmask DP whose transitions read only masks that are proper subsets of the current one (equivalently, push values only to proper supersets) is evaluated correctly by the loop `for (int mask = 0; mask < (1 << n); mask++)`.
:::

:::proof
The bits of *S* and of *T* \ *S* are disjoint, so adding the two masks produces no carries, and mask(*T*) = mask(*S*) + Σ over *j* ∈ *T* \ *S* of 2ʲ. The sum is positive because *T* \ *S* is not empty, so mask(*T*) > mask(*S*). Every state a transition reads therefore comes earlier in the increasing loop. That is condition (c) of the template theorem in Chapter 11, which then gives correctness from a correct recurrence.
:::

The order also serves transitions that add a whole group (@sec-22-submask). It fails only when a transition can stay at the same mask (@sec-22-last).

### The assignment problem

There are *n* workers and *n* jobs, and worker *w* charges cost[*w*][*j*] for job *j*; each worker gets exactly one job and each job one worker. Serve the workers in a fixed order 0, 1, 2, …. Once *k* workers are served, the cost of finishing depends only on which jobs are taken, and *k* is the number of set bits of that mask, so the mask alone is the state.

1. **State**: dp[*mask*] = the least total cost of giving the workers 0, …, *k* − 1 the jobs in *mask*, one each, where *k* = |*mask*|.
2. **Transition**: worker *k* takes a job *j* ∉ *mask*: dp[*mask* ∪ {*j*}] ≤ dp[*mask*] + cost[*k*][*j*].
3. **Base**: dp[0] = 0.
4. **Order**: increasing masks, by @thm-22-order.
5. **Answer**: dp[2ⁿ − 1].

:::theorem{#thm-22-assign} The assignment recurrence
For every non-empty mask with *k* = |*mask*|, dp[*mask*] = min over *j* ∈ *mask* of dp[*mask* \ {*j*}] + cost[*k* − 1][*j*].
:::

:::proof
Split the assignments counted by dp[*mask*] by the job *j* of the last worker, *k* − 1. Removing that worker leaves workers 0..*k* − 2 holding the jobs of *mask* \ {*j*}, one each, which is an assignment counted by dp[*mask* \ {*j*}]; conversely, any such assignment plus "worker *k* − 1 takes job *j*" is counted by dp[*mask*]. So the cheapest assignment whose last job is *j* costs dp[*mask* \ {*j*}] + cost[*k* − 1][*j*], and dp[*mask*] is the smallest of these over all *j* ∈ *mask*.
:::

The handbook's template pushes instead of pulling: each finished mask relaxes every mask with one more bit, which considers the same pairs (*mask*, *j*) as @thm-22-assign, so it computes the same minimum.

```java {#lst-22-assign} Assignment by bitmask DP (handbook template)
// n <= 20: a subset is an int mask. Assign n jobs to n workers at minimum total cost.
static int minAssignment(int[][] cost) {
    int n = cost.length;
    int[] dp = new int[1 << n];                        // dp[mask] = jobs in mask are taken
    Arrays.fill(dp, Integer.MAX_VALUE);
    dp[0] = 0;
    for (int mask = 0; mask < (1 << n); mask++) {
        if (dp[mask] == Integer.MAX_VALUE) continue;
        int worker = Integer.bitCount(mask);           // workers 0..worker-1 are done
        if (worker == n) continue;
        for (int job = 0; job < n; job++) {
            if ((mask & (1 << job)) != 0) continue;
            int next = mask | (1 << job);
            dp[next] = Math.min(dp[next], dp[mask] + cost[worker][job]);
        }
    }
    return dp[(1 << n) - 1];
}
```

A mask with *k* bits relaxes *n* − *k* masks, so the total is Σ over masks of (*n* − |*mask*|) = *n* · 2ⁿ⁻¹ relaxations: 10,485,760 for *n* = 20, which took 59 ms on the sandbox. The table holds 2ⁿ ints, 4 MB for *n* = 20. The brute force would face 20! ≈ 2.4 · 10¹⁸ assignments.

LeetCode 1879 (Minimum XOR Sum of Two Arrays) is this listing with cost[*i*][*j*] = nums1[*i*] ⊕ nums2[*j*]: element *i* of the first array plays worker *i*, and rearranging the second array assigns it a job. The square-free subsets problem of Chapter 10 has a mask state too, the set of primes used so far.

## A last element, and BFS over masks {#sec-22-last}

When the cost of the next item depends on the previous one, as a route's cost depends on the *last* city, the state must also say where the partial solution ends. The shortest Hamiltonian path visits every vertex of a complete graph exactly once, starting anywhere, with distances dist[*u*][*v*]. Let dp[*mask*][*v*] be the length of the shortest path that visits exactly the vertices of *mask*, each once, and ends at *v* ∈ *mask*. A path of one vertex has length 0, and the answer is the minimum over *v* of dp[2ⁿ − 1][*v*].

:::theorem{#thm-22-ham} The path recurrence
For |*mask*| ≥ 2 and *v* ∈ *mask*, dp[*mask*][*v*] = min over *u* ∈ *mask* \ {*v*} of dp[*mask* \ {*v*}][*u*] + dist[*u*][*v*].
:::

:::proof
On a path counted by dp[*mask*][*v*], let *u* be the vertex just before *v*. Removing *v* leaves a path that visits exactly *mask* \ {*v*} and ends at *u*, shorter by dist[*u*][*v*]. Conversely, appending *v* to any path counted by dp[*mask* \ {*v*}][*u*] gives a path counted by dp[*mask*][*v*], because *v* is not yet on it. So the best path through *u* costs dp[*mask* \ {*v*}][*u*] + dist[*u*][*v*], and dp[*mask*][*v*] is the minimum over *u*. The mask *mask* \ {*v*} is smaller than *mask*, so by @thm-22-order the increasing loop has finished it.
:::

```java {#lst-22-ham} Shortest path visiting every vertex once: dp[mask][last] (handbook template)
// Shortest path visiting every node once (start anywhere): dp[mask][last]
static long shortestHamiltonianPath(long[][] dist) {
    int n = dist.length;
    long INF = Long.MAX_VALUE / 4;
    long[][] dp = new long[1 << n][n];
    for (long[] row : dp) Arrays.fill(row, INF);
    for (int v = 0; v < n; v++) dp[1 << v][v] = 0;
    for (int mask = 1; mask < (1 << n); mask++)
        for (int last = 0; last < n; last++) {
            if (dp[mask][last] >= INF) continue;
            for (int nxt = 0; nxt < n; nxt++) {
                if ((mask & (1 << nxt)) != 0) continue;
                int m2 = mask | (1 << nxt);
                dp[m2][nxt] = Math.min(dp[m2][nxt], dp[mask][last] + dist[last][nxt]);
            }
        }
    long best = INF;
    for (int v = 0; v < n; v++) best = Math.min(best, dp[(1 << n) - 1][v]);
    return best;
}
```

The listing agreed with a brute force over all orders on 5,000 random graphs with up to 7 vertices. It has 2ⁿ · *n* states with up to *n* transitions each, so O(2ⁿ · *n*²) time: for *n* = 18 it ran in 136 ms on the sandbox, and for *n* = 20 the inner loop body can run up to 2²⁰ · 20 · 20 ≈ 4.2 · 10⁸ times.

:::pitfall Check the memory first
For *n* = 20 the table holds 2²⁰ · 20 values of type `long`, about 168 MB. On the sandbox JVM `new long[1 << 20][20]` took 188 MB (each of its 2²⁰ rows is an array object with a header), `new long[20][1 << 20]` 167 MB and `new int[20][1 << 20]` 83 MB. Use `int` if the values fit, and put the small dimension first.
:::

### When the mask can stay the same: BFS over (node, mask)

LeetCode 847 (Shortest Path Visiting All Nodes), a bonus problem, has unweighted edges and lets a walk pass through a vertex more than once. Stepping onto a visited vertex leaves the mask unchanged, so @thm-22-order does not apply and the states form cycles. Its key observation is that every step costs 1, so BFS (Chapter 15) over the states (current vertex, set of visited vertices), started from all *n* states (*v*, {*v*}) at once, reaches the first full mask at the answer's distance. For 12 vertices there are 12 · 2¹² = 49,152 states.

## A pair as the state: work sessions {#sec-22-pairs}

LeetCode 1986 (Minimum Number of Work Sessions to Finish the Tasks) gives *n* tasks with positive durations *d*₀, …, *d*ₙ₋₁ and a session length *T* ≥ every *d*ⱼ. A session holds tasks whose durations add up to at most *T*, and the question is the fewest sessions, the same question as "fewest elevator rides" or "fewest bins".

Think of a schedule as an order of the tasks plus *sequential filling*: put the next task into the current session if it fits, otherwise open a new session for it. After filling some set of tasks, the situation is a pair (*k*, *t*): *k* sessions are open and the last one is filled to *t*. Fewer sessions is better, and with equally many, a smaller *t* leaves more room. That is the lexicographic order on pairs: (*k*, *t*) < (*k*′, *t*′) when *k* < *k*′, or *k* = *k*′ and *t* < *t*′. One filling step is

  step((*k*, *t*), *d*) = (*k*, *t* + *d*) if *t* + *d* ≤ *T*, and (*k* + 1, *d*) otherwise.

:::lemma{#lem-22-mono} Filling is monotone
If (*k*, *t*) ≤ (*k*′, *t*′) in lexicographic order and 0 ≤ *t*, *t*′ ≤ *T*, then step((*k*, *t*), *d*) ≤ step((*k*′, *t*′), *d*) for every duration *d* with 1 ≤ *d* ≤ *T*.
:::

:::proof
Suppose first that *k* < *k*′. The left side has at most *k* + 1 ≤ *k*′ sessions and the right side at least *k*′. If the left side has fewer, it is smaller. If both have exactly *k*′ sessions, the left side is (*k* + 1, *d*) and the right side is (*k*′, *t*′ + *d*), and *d* ≤ *t*′ + *d*. Now suppose *k* = *k*′ and *t* ≤ *t*′. If *t*′ + *d* ≤ *T*, then also *t* + *d* ≤ *T*, and (*k*, *t* + *d*) ≤ (*k*, *t*′ + *d*). Otherwise the right side is (*k* + 1, *d*), and the left side is either (*k*, *t* + *d*), which is smaller, or the same pair (*k* + 1, *d*).
:::

:::lemma{#lem-22-fill} Some order is optimal
If the tasks fit into *m* sessions, then some order of the tasks makes sequential filling open at most *m* sessions.
:::

:::proof
Take a schedule with sessions *S*₁, …, *S*ₘ and order the tasks session by session. Let σᵢ be the total duration of *S*ᵢ. We show by induction on *i* that after the tasks of *S*₁, …, *S*ᵢ the filling state is at most (*i*, σᵢ). For *i* = 1, all of *S*₁ fits in the first session, and the state is (1, σ₁). For the step, the state *s* after *S*ᵢ satisfies *s* ≤ (*i*, σᵢ) ≤ (*i*, *T*). Starting instead from (*i*, *T*), the first task of *S*ᵢ₊₁ does not fit (its duration is positive), so it opens session *i* + 1, and the rest of *S*ᵢ₊₁ fits behind it, ending at (*i* + 1, σᵢ₊₁). Applying @lem-22-mono task by task, the real state ends at most (*i* + 1, σᵢ₊₁). For *i* = *m* the state has at most *m* sessions.
:::

Sequential filling always gives a valid schedule, so the optimum is the fewest sessions it reaches over all *n*! orders; by @lem-22-mono only the best pair for each *set* of tasks matters.

:::theorem{#thm-22-sessions} The pair recurrence
Let best(*mask*) be the smallest pair, in lexicographic order, that sequential filling reaches over all orders of the tasks in *mask*, with best(∅) = (1, 0), one empty session. Then for every non-empty *mask*,
best(*mask*) = min over *j* ∈ *mask* of step(best(*mask* \ {*j*}), *d*ⱼ),
and the first component of best(all tasks) is the fewest sessions.
:::

:::proof
Any order of *mask* ends with some task *j*, and its first |*mask*| − 1 tasks are an order of *mask* \ {*j*} that reaches some pair *p* ≥ best(*mask* \ {*j*}). By @lem-22-mono the final pair step(*p*, *d*ⱼ) is at least step(best(*mask* \ {*j*}), *d*ⱼ), so no order beats the minimum in the formula. Conversely, the order that reaches best(*mask* \ {*j*}) followed by *j* reaches exactly step(best(*mask* \ {*j*}), *d*ⱼ), so the minimum is achieved. For the last claim, every order gives a valid schedule, so best(all).*k* is at least the optimum *m*; by @lem-22-fill some order uses at most *m* sessions, so best(all).*k* ≤ *m*.
:::

```java {#lst-22-sessions} Fewest sessions with dp[mask] = (sessions, time used in the last one)
// Fewest sessions of length T that hold all tasks (every task <= T, every task >= 1).
static int minSessions(int[] task, int T) {
    int n = task.length;
    int[] cnt = new int[1 << n], last = new int[1 << n];
    cnt[0] = 1;                                     // one empty session is open
    for (int mask = 1; mask < (1 << n); mask++) {
        cnt[mask] = Integer.MAX_VALUE;
        for (int j = 0; j < n; j++) {
            if ((mask & (1 << j)) == 0) continue;
            int prev = mask ^ (1 << j);             // task j is the one placed last
            int c = cnt[prev], t = last[prev] + task[j];
            if (t > T) {                            // it does not fit: open a new session
                c++;
                t = task[j];
            }
            if (c < cnt[mask] || (c == cnt[mask] && t < last[mask])) {
                cnt[mask] = c;
                last[mask] = t;
            }
        }
    }
    return cnt[(1 << n) - 1];
}
```

The time is O(2ⁿ · *n*) and the memory two `int` arrays of 2ⁿ entries. The listing agreed with a backtracking oracle (place each task into an open session or a new one) on 10,000 random instances with up to 9 tasks, and it returns 2, 2 and 1 on the three samples of LeetCode 1986.

:::

## Submasks in O(3ⁿ) {#sec-22-submask}

Some DPs remove a whole group of items in one step. "Split the items into as few valid groups as possible" has the recurrence dp[*mask*] = min over valid groups *g* ⊆ *mask* of dp[*mask* \ *g*] + 1, so each mask needs a loop over the groups inside it.

:::definition{#def-22-submask} Submask
A mask *s* is a [[submask]] of *m* when every set bit of *s* is also set in *m*, that is, `(s & ~m) == 0`; as sets, *s* ⊆ *m*.
:::

The handbook's loop visits them without testing all 2ⁿ masks:

```java {.fragment}
int mask = 0b1101;
for (int s = mask; s > 0; s = (s - 1) & mask) {
    System.out.println(Integer.toBinaryString(s));   // every non-empty submask, largest first
}
// the empty submask s = 0 is not visited: handle it separately if it matters
```

For *mask* = 1101 it prints 1101, 1100, 1001, 1000, 101, 100 and 1, that is 13, 12, 9, 8, 5, 4 and 1.

:::lemma{#lem-22-submask} The submask step
If *s* > 0 is a submask of *m*, then (*s* − 1) & *m* is the largest submask of *m* that is smaller than *s*. Hence the loop above visits every non-empty submask of *m* exactly once, in decreasing order.
:::

:::proof
Let *b* be the lowest set bit of *s*. Subtracting 1 borrows through the zeros below *b*, so *s* − 1 is *s* with bit *b* cleared and bits 0..*b* − 1 set. After `& m`, the candidate *c* = (*s* − 1) & *m* agrees with *s* above *b* (those bits of *s* are in *m*), has 0 at *b*, and has exactly the bits of *m* below *b*. It is a submask of *m*, and *c* < *s* because the highest bit where they differ is *b*, where *s* has the 1 (the top-bit lemma of Chapter 8).

Now let *u* < *s* be any submask of *m*, and let *p* be the highest bit where they differ; *s* has 1 there and *u* has 0, so *p* ≥ *b*. If *p* > *b*, then *c* agrees with *s* at and above *p*, so *u* and *c* first differ at *p*, where *c* has the 1: *u* < *c*. If *p* = *b*, then *u* agrees with *c* at and above *b*, and below *b* its bits are bits of *m*, all set in *c*: *u* ≤ *c*. So *c* is the largest submask below *s*. The loop starts at *m*, the largest submask, steps down one submask at a time, and after the smallest non-empty one reaches 0 and stops.
:::

:::theorem{#thm-22-three} All submasks of all masks: 3ⁿ
Over all 2ⁿ masks of *n* bits, the number of pairs (*s*, *m*) with *s* a submask of *m* is 3ⁿ. The loop above therefore runs 3ⁿ − 2ⁿ times in total.
:::

:::proof
A pair (*s*, *m*) with *s* ⊆ *m* is the same as giving each of the *n* items one of three labels: "in *s*" (and so in *m*), "in *m* but not in *s*", or "not in *m*". The labels determine *s* and *m*, and every labelling gives a valid pair, so there are 3ⁿ pairs. The loop skips *s* = 0, which occurs once for each of the 2ⁿ masks, leaving 3ⁿ − 2ⁿ iterations. (Equivalently, a mask with *k* bits has 2ᵏ submasks, and Σ C(*n*, *k*) 2ᵏ = (1 + 2)ⁿ by the binomial theorem.)
:::

A run over all masks of up to 12 bits counted exactly 3ⁿ − 2ⁿ iterations each time (65 for *n* = 4); testing every pair of masks would cost 4ⁿ. For *n* = 16, 3¹⁶ ≈ 4.3 · 10⁷ is fast, but for *n* = 20, 3²⁰ ≈ 3.5 · 10⁹ is far too slow. So an O(3ⁿ) DP fits *n* ≤ 16 or so, while an O(2ⁿ · *n*) DP fits *n* ≤ 20.

### Example: the fewest colours

Colour the vertices of a graph with *n* ≤ 16 vertices with as few colours as possible, adjacent vertices getting different colours. Each colour class is an independent set (no edge inside it), so a colouring of *mask* is a partition of *mask* into independent sets. To build each partition only once, choose first the class that contains the lowest vertex of *mask*.

:::claim{#thm-22-colour} The colouring recurrence
Let dp[*mask*] be the fewest independent sets that partition *mask*, with dp[∅] = 0, and let *v* be the lowest vertex of a non-empty *mask*. Then dp[*mask*] = 1 + min over independent *s* ⊆ *mask* with *v* ∈ *s* of dp[*mask* \ *s*].
:::

:::proof
In any partition of *mask* into independent sets, exactly one class *s* contains *v*, and the other classes partition *mask* \ *s*, so the partition has at least 1 + dp[*mask* \ *s*] classes. Conversely, adding *s* to a best partition of *mask* \ *s* gives a partition of *mask* with 1 + dp[*mask* \ *s*] classes. The set {*v*} is independent, so the minimum is over a non-empty range, and *mask* \ *s* is a proper subset of *mask*, so @thm-22-order makes the increasing loop valid.
:::

```java {#lst-22-colour} The fewest colours for a graph on n <= 16 vertices, in O(3^n)
// adj[v] = mask of the neighbours of v
static int chromaticNumber(int[] adj) {
    int n = adj.length, full = (1 << n) - 1;
    boolean[] indep = new boolean[1 << n];          // indep[s]: no edge joins two vertices of s
    indep[0] = true;
    for (int s = 1; s <= full; s++) {
        int v = Integer.numberOfTrailingZeros(s);   // the lowest vertex of s
        int rest = s & (s - 1);                     // s without v
        indep[s] = indep[rest] && (adj[v] & rest) == 0;
    }
    int[] dp = new int[1 << n];                     // fewest colours for the vertices of mask
    for (int mask = 1; mask <= full; mask++) {
        dp[mask] = Integer.MAX_VALUE;
        int low = mask & -mask;                     // the class that contains the lowest vertex
        for (int s = mask; s > 0; s = (s - 1) & mask)
            if ((s & low) != 0 && indep[s]) dp[mask] = Math.min(dp[mask], dp[mask ^ s] + 1);
    }
    return dp[full];
}
```

The table `indep` is itself a small bitmask DP: *s* is independent when *s* without its lowest vertex *v* is independent and *v* has no neighbour in the rest. The listing agreed with a brute force over all colourings on 5,000 random graphs with up to 7 vertices, returns 3 for a cycle of 5 vertices, and took 32 ms on a random graph with 16 vertices.

## Digit DP: counting numbers up to N {#sec-22-digit}

The last pattern counts integers instead of subsets. How many *x* in [0, *N*] have a digit sum divisible by *D*? For *N* = 10¹⁸ a loop over *x* is impossible, but *N* has only 19 digits.

Write *N* with *L* digits *n*₀ *n*₁ … *n*<sub>*L*−1</sub>, most significant first, and pad every *x* ≤ *N* with leading zeros to *L* digits. Two digit strings of the same length compare like words in a dictionary: the first position where they differ decides, for the same reason as the top-bit lemma of Chapter 8 (a digit is worth more than all lower digits together).

:::definition{#def-22-digit} Digit DP and the tight flag
A [[digit DP]] builds *x* one digit at a time from the left. Its state is (*pos*, *tight*, *extra*): *pos* digits are fixed; [[tight|tight (digit DP)]] says whether those digits equal the first *pos* digits of *N*; and *extra* holds what the property needs to know about the prefix, here the digit sum modulo *D*. In a tight state the next digit may be at most *n*<sub>*pos*</sub>; in a free (not tight) state it may be any of 0..9.
:::

:::theorem{#thm-22-tight} Tight and free partition [0, N]
Every *x* in [0, *N*] other than *N* itself has exactly one position *p* such that *x* agrees with *N* at positions 0..*p* − 1 and *x*ₚ < *n*ₚ, and its digits after *p* are arbitrary. Conversely every digit string of that form is a number below *N*. Hence [0, *N*] is the disjoint union of {*N*} and the blocks *B*(*p*, *d*) = "the prefix *n*₀ … *n*ₚ₋₁, then the digit *d*, then any *L* − *p* − 1 digits", for 0 ≤ *p* < *L* and 0 ≤ *d* < *n*ₚ.
:::

:::proof
If *x* < *N*, let *p* be the first position where the two strings differ. They agree before *p*, so the digit at *p* decides the comparison, and *x* < *N* forces *x*ₚ < *n*ₚ. The position is unique because it is the first difference. Conversely, a string that agrees with *N* before *p* and has a smaller digit at *p* is smaller than *N* whatever follows. As a check on the count, *B*(*p*, *d*) has 10<sup>*L*−*p*−1</sup> members, so the blocks together hold Σₚ *n*ₚ · 10<sup>*L*−*p*−1</sup> = *N* numbers, and with *N* itself that is *N* + 1, the size of [0, *N*].
:::

The search follows this partition. In the tight state at position *p* it tries the digits 0..*n*ₚ: a digit *d* < *n*ₚ enters the block *B*(*p*, *d*), where every later state is free, and the digit *n*ₚ stays tight. So every *x* ≤ *N* is generated exactly once, and nothing above *N*.

:::lemma{#lem-22-free} Free states can be memoised by (pos, rem)
The number of ways to complete a free state depends only on *pos* and the remainder *rem*: it is the number of strings of *L* − *pos* digits whose digit sum *s* satisfies (*rem* + *s*) mod *D* = 0.
:::

:::proof
In a free state each of the remaining *L* − *pos* positions may hold any digit 0..9, independently of the prefix and of *N*, and the property depends on the prefix only through *rem*. So two free states with the same (*pos*, *rem*) count the same strings.
:::

A tight state's count also depends on the later digits of *N*, so it must not share the memo table. Nothing is lost: the tight states form one path, one state per position, each computed once.

```java {#lst-22-digitsum} Digit DP: how many x in [0, N] have a digit sum divisible by D (handbook template)
// How many x in [0, N] have a digit sum divisible by D?  For a range [L, R]: f(R) - f(L - 1).
// State: (position, remainder so far, tight = "prefix equals N's prefix").
static char[] dig;
static long[][] digMemo;
static int digMod;

static long countUpTo(long N, int D) {
    dig = Long.toString(N).toCharArray();
    digMod = D;
    digMemo = new long[dig.length][D];
    for (long[] row : digMemo) Arrays.fill(row, -1);
    return digitGo(0, 0, true);
}

static long digitGo(int pos, int rem, boolean tight) {
    if (pos == dig.length) return rem == 0 ? 1 : 0;
    if (!tight && digMemo[pos][rem] != -1) return digMemo[pos][rem];   // memo only free states
    int limit = tight ? dig[pos] - '0' : 9;
    long res = 0;
    for (int d = 0; d <= limit; d++) res += digitGo(pos + 1, (rem + d) % digMod, tight && d == limit);
    if (!tight) digMemo[pos][rem] = res;
    return res;
}
// Add a "started" flag to the state when leading zeros change the answer.
```

The listing agreed with a direct count on 5,000 random pairs (*N* ≤ 2 · 10⁵, *D* ≤ 30). There are *L* · *D* free states and *L* tight ones, each trying at most 10 digits: O(10 · *L* · *D*) time, at most 19 · 100 · 10 = 19,000 digit steps for *N* < 10¹⁹ and *D* ≤ 100. For *N* = 10¹⁸ − 1 and *D* = 7 it made 1,371 calls, never more than *L* + 1 ≤ 20 deep.

## Ranges, leading zeros and extra state {#sec-22-extra}

Three refinements turn the template into a tool for most digit problems.

### Ranges

Let *f*(*x*) be the number of integers in [0, *x*] with the property, and *f*(−1) = 0. For 0 ≤ *L* ≤ *R*, the interval [0, *R*] is the disjoint union of [0, *L* − 1] and [*L*, *R*], so the count in [*L*, *R*] is *f*(*R*) − *f*(*L* − 1). For digit sums divisible by 3 in [100, 352] that is 118 − 34 = 84, the number of multiples of 3 from 102 to 351.

:::pitfall
When *L* = 0, return 0 for *f*(*L* − 1) instead of calling the counter on −1: `Long.toString(-1)` is "-1", and the digit loop would read '-' as a digit. For bounds given as long strings, use *f*(*R*) − *f*(*L*) plus 1 if *L* itself has the property.
:::

### Leading zeros and the started flag

Padding with leading zeros is harmless for digit sums but wrong when zeros matter: in "no digit repeats", 007 would have two zeros; in "as many even digits as odd", a leading zero would count as even; in "every digit comes from a given set", 0 may not be in the set.

:::definition{#def-22-started} Started flag
The [[started flag]] of a digit-DP state says whether a non-zero digit has been placed yet. While it is false, the zeros placed so far are padding and are ignored by the property; the first non-zero digit sets it, and from then on every digit, zeros included, belongs to *x*.
:::

The next listing counts the numbers in [1, *N*] with no repeated digit. Its extra state is a bitmask of the digits used so far, so it combines both halves of the chapter.

```java {#lst-22-distinct} Digit DP with a started flag and a mask of used digits
// How many x in [1, N] have no repeated digit?  State: (pos, digits used, tight, started).
static char[] dg;
static long[][] memoD;                          // memoD[pos][used], free and started states only

static long countDistinct(long N) {
    dg = Long.toString(N).toCharArray();
    memoD = new long[dg.length][1 << 10];
    for (long[] row : memoD) Arrays.fill(row, -1);
    return goDistinct(0, 0, true, false);
}

static long goDistinct(int pos, int used, boolean tight, boolean started) {
    if (pos == dg.length) return started ? 1 : 0;      // x = 0 is not counted
    if (!tight && started && memoD[pos][used] != -1) return memoD[pos][used];
    int limit = tight ? dg[pos] - '0' : 9;
    long res = 0;
    for (int d = 0; d <= limit; d++) {
        boolean st = started || d != 0;                 // leading zeros are not digits of x
        if (st && (used & (1 << d)) != 0) continue;     // d already appears in x
        res += goDistinct(pos + 1, st ? used | (1 << d) : used, tight && d == limit, st);
    }
    if (!tight && started) memoD[pos][used] = res;
    return res;
}
```

Not-started states need no memo: the first digit of *N* is not 0, so they are "all zeros so far", one per position. The listing agreed with a direct count for 5,000 random *N* ≤ 10⁶. It returns 269 for *N* = 352 and 8,877,690 for *N* = 10¹⁸ (no number with more than ten digits qualifies). Without the started flag the count for *N* = 100 drops from 90 to 72, because 7 is read as 007.

### Extra state

The extra component is whatever the property needs to remember about the prefix, and its size multiplies the cost.

* **The remainder of the number**: appending *d* to a prefix of value *v* gives 10*v* + *d*, so the remainder modulo *k* moves from *r* to (10*r* + *d*) mod *k*.
* **A balance of digit counts**, such as even minus odd digits, in −*L*..*L*: store it with an offset of *L*.
* **A set of digits** (1024 values, as in @lst-22-distinct) or **the last digit** (10 values, for rules about neighbours).

LeetCode 2827 (Number of Beautiful Integers in the Range), a bonus problem, counts numbers with as many even as odd digits that are also divisible by *k*. Its key observation is the state (position, even − odd balance, remainder modulo *k*, tight, started), counting a number when balance and remainder are both 0 at the end.

LeetCode 902 (Numbers At Most N Given Digit Set) is left to you. It uses the started flag with digits from a given set: numbers with fewer digits than *N* are all allowed, and numbers with as many digits as *N* follow the tight path.

### Choosing the method from the limits

Table: {#tbl-22-limits} The chapter's methods and the limits they fit (about 10⁸ simple steps per second)
| Limits and question | Method | Work at the limit |
|---|---|---|
| *n* ≤ 10, order matters | permutations by backtracking | about *e* · 10! ≈ 10⁷ nodes |
| *n* ≤ 20, list or count subsets | bitmask loop, or backtracking with pruning | 2²⁰ ≈ 10⁶ subsets |
| *n* ≤ 20, the future depends on a set | dp[*mask*], O(2ⁿ · *n*) | *n* · 2ⁿ⁻¹ ≈ 10⁷ |
| *n* ≤ 16 to 18, a set and a last item | dp[*mask*][*last*], O(2ⁿ · *n*²) | 2¹⁸ · 18² ≈ 8.5 · 10⁷ |
| *n* ≤ 16, transitions remove a group | submasks, O(3ⁿ) | 3¹⁶ ≈ 4.3 · 10⁷ |
| values up to 10¹⁸, a digit property | digit DP, O(10 · *L* · states) | 19 · *S* · 10 for *S* extra states |

## Summary

- Backtracking is a depth-first search over partial solutions: choose, recurse, undo (@lem-22-undo). The output gets a copy of the shared state.
- A pruning rule is safe when it never cuts a subtree that contains a solution; measure its effect by counting nodes. The depth is at most *n* + 1, so recursion is fine for *n* ≤ 20.
- When the future depends only on the set of items used, memoise on the set: 2ⁿ states instead of *n*! orders.
- A proper subset has a smaller mask, so increasing masks are a valid order whenever transitions add bits (@thm-22-order); transitions that can keep the mask need BFS.
- Assignment needs only dp[*mask*], because the next worker is |*mask*|. Paths need dp[*mask*][*last*]; check the memory of 2ⁿ · *n* entries first.
- A state can be a pair compared lexicographically, such as (sessions, time used in the last one), when the transition is monotone in that order (@lem-22-mono).
- The loop `s = (s - 1) & mask` visits every non-empty submask once; over all masks that is 3ⁿ − 2ⁿ steps, so O(3ⁿ) DPs fit *n* ≤ 16.
- Digit DP follows the tight path of *N* and branches into free states, which partition [0, *N*] (@thm-22-tight). Memoise free states only, use *f*(*R*) − *f*(*L* − 1) for ranges, and add a started flag when leading zeros matter.

## Review questions

1. In @lst-22-sumsub, the pruning test uses `break`. Why would `break` be wrong if *a* were not sorted, and what would be a safe replacement?
2. Why is increasing numeric order a valid evaluation order for the assignment DP, but not for the BFS over (vertex, mask) of LeetCode 847?
3. The assignment DP has *n* workers and *m* > *n* jobs, and each worker must still take exactly one job. How do you change @lst-22-assign, and what does it cost?
4. How many iterations does the submask loop make for *mask* = 10110₂? And in total over all masks of 4 bits?
5. In @lst-22-digitsum, the memo is read and written only when `tight` is false. What does the method return for *N* = 10 and *D* = 1 if both `!tight` conditions are deleted, and why?
6. Why does @lst-22-distinct need the started flag, while @lst-22-digitsum does not?
7. Which method from @tbl-22-limits fits each task? (a) 18 cities, the shortest round trip through all of them; (b) 15 items, split into the fewest groups of at most 4 pairwise compatible members; (c) count the numbers up to 10¹⁵ whose digits never decrease.

:::answers
1. Without sorting, a later value can fit even though the current one is too large, so `break` would cut subtrees that contain solutions. `continue` is safe in any order (it is how the handbook's Combination Sum template is written); sorting first and keeping `break` visits fewer nodes.
2. Every assignment transition adds a job, so it moves to a proper superset, which has a larger number (@thm-22-order). In LeetCode 847 a walk may step onto a visited vertex, which keeps the mask the same, so the state graph has cycles; because every step costs 1, BFS still finds shortest distances.
3. Use masks over the *m* jobs with worker = `Integer.bitCount(mask)`, stop extending a mask once it has *n* bits, and return the minimum of dp[*mask*] over the masks with exactly *n* bits: O(2ᵐ · *m*) time and 2ᵐ ints.
4. 10110₂ has 3 set bits, so 2³ − 1 = 7 non-empty submasks. Over all masks of 4 bits, 3⁴ − 2⁴ = 65.
5. 20 instead of 11. The free branch "first digit 0" stores 10 (the numbers 0..9) under (1, 0); the tight branch "first digit 1" reaches the same key and reads 10, although only the number 10 itself is left.
6. A leading zero adds nothing to a digit sum. In @lst-22-distinct padding zeros would count as uses of the digit 0, so 7 = 007 would seem to repeat a digit; the started flag keeps them out of the mask.
7. (a) dp[*mask*][*last*] with a fixed start city: 2¹⁸ · 18² ≈ 8.5 · 10⁷ steps. (b) Submask DP with "at most 4 members, pairwise compatible" as the group test: 3¹⁵ ≈ 1.4 · 10⁷ steps. (c) Digit DP with the last digit as extra state and a started flag: 16 positions × about 10 last digits × 10 choices.
:::

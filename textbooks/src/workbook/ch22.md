:::exercise{#exr-22-bug} Find the bug
This method should count the *x* in [0, *N*] whose digit sum is divisible by *D*. It compiles, and for *D* = 2 it returns the right answer for every *N* from 0 to 19 and for *N* = 99. Find an input with *N* < 30 where it fails, say what it returns there and what it should return, explain the cause, and fix it.

```java
static char[] dig;
static long[][] memo;
static int mod;

static long countUpToBuggy(long N, int D) {
    dig = Long.toString(N).toCharArray();
    mod = D;
    memo = new long[dig.length][D];
    for (long[] row : memo) Arrays.fill(row, -1);
    return go(0, 0, true);
}

static long go(int pos, int rem, boolean tight) {
    if (pos == dig.length) return rem == 0 ? 1 : 0;
    if (memo[pos][rem] != -1) return memo[pos][rem];
    int limit = tight ? dig[pos] - '0' : 9;
    long res = 0;
    for (int d = 0; d <= limit; d++) res += go(pos + 1, (rem + d) % mod, tight && d == limit);
    memo[pos][rem] = res;
    return res;
}
```

:::answers
**Exercise 22.1.** (1) `dp[0] = 0`; (2) `Integer.bitCount(mask)`; (3) `(mask & (1 << job)) != 0`; (4) `mask | (1 << job)`; (5) `dp[(1 << n) - 1]`. Increasing order is valid by @T:thm-22-order: every transition adds a bit, and a proper superset has a larger number, because adding disjoint bits produces no carries.

**Exercise 22.4.**

| position | digit of N | allowed smaller digits | free completions | contribution | tight path continues? |
|---|---|---|---|---|---|
| 0 | 5 | 0, 1, 2, 4 (4 digits) | 9³ = 729 | 2916 | yes, with 5 |
| 1 | 3 | 0, 1, 2 (3 digits) | 9² = 81 | 243 | no: the digit 3 is forbidden |
| 2 | 7 | – | – | – | – |
| 3 | 2 | – | – | – | – |
| end | | | | *N* itself: 0 | |

So *f*(5372) = 2916 + 243 = 3159: the tight path dies at position 1, because every *x* that keeps the prefix 53 contains a 3, and so 5372 itself is not counted. For 999 every position allows 8 smaller digits: 8 · 81 + 8 · 9 + 8 · 1 + 1 = 648 + 72 + 8 + 1 = 729 (which is 9³, as it must be: all three-digit strings over the 9 allowed digits). The count in [1000, 5372] is 3159 − 729 = 2430. A direct count by computer gives the same three numbers.

**Exercise 22.5.** (1) False: a skipped value creates no node either way; `continue` only makes the loop run longer (on this input both visit 12 nodes). (2) True: it has ⌊*e* · 10!⌋ = 9,864,101 nodes. (3) False: 011 = 3 < 100 = 4, but 011 is not a submask of 100. The converse holds (@T:thm-22-order). (4) False: dp[*mask*] is the minimum over all ways to assign the first |*mask*| workers to those jobs; the order is not part of the state. (5) False: the loop stops when *s* becomes 0, so the empty submask is never visited. (6) True: keyed by (*pos*, *rem*, tight) the table is correct, but it saves nothing, because each tight state is reached once. (7) True: with *L* = 0 the formula reads *f*(*R*) − *f*(−1), and the count of [0, −1], the empty range, is 0.

**Exercise 22.6.** State: dp[*mask*] = the least cost of pairing up exactly the students in *mask*. Transition: let *i* be the lowest student not in *mask*; for every other *j* not in *mask*, dp[*mask* ∪ {*i*, *j*}] ≤ dp[*mask*] + *c*[*i*][*j*]. Base dp[0] = 0, increasing masks, answer dp[2ⁿ − 1]. Student *i* must be paired with someone, and pairing them now loses nothing, because the order in which the pairs are formed does not change the cost; insisting on the lowest one builds each pairing exactly once instead of in every order. Time O(2ⁿ · *n*), about 2²⁰ · 20 ≈ 2.1 · 10⁷ steps at most, against 19 · 17 · ⋯ · 1 = 654,729,075 ways to split 20 students into pairs. For the instance, the best pairing is 0–1, 2–4, 3–5 with cost 4 + 3 + 2 = 9; the 15 pairings of 6 students cost between 9 and 23, and the DP and a brute force both return 9.

**Exercise 22.7.** For *N* = 23 and *D* = 2 it returns 15; the right answer is 12 (0, 2, 4, 6, 8, 11, 13, 15, 17, 19, 20, 22). Every *N* from 20 to 27 fails. The memo is shared by tight and free states. At position 0 the free branches for the first digits 0 and 1 store the counts of (1, 0) and (1, 1), five each; the tight branch with first digit 2 reaches the key (1, 0) and reads 5, although only 20 and 22 remain below 23. For *N* from 10 to 19 the tight branch reaches the key (1, 1), which no free branch has stored yet, and when *N* ends in 9 the tight count equals the free count; that is why 0..19 and 99 pass. Fix: read and write the memo only when `tight` is false, as in @T:lst-22-digitsum: `if (!tight && memo[pos][rem] != -1) ...` and `if (!tight) memo[pos][rem] = res;`.

**Exercise 22.8.** (1) Backtracking over permutations, pruning an item that differs by 1 from the last one: at most ⌊*e* · 8!⌋ = 109,601 nodes. (2) Assignment DP, @T:lst-22-assign: 20 · 2¹⁹ = 10,485,760 relaxations and 4 MB. (3) dp[*mask*][*last*], @T:lst-22-ham: 2¹⁸ · 18² ≈ 8.5 · 10⁷ steps. A path has at most 17 edges of at most 10⁶, so 1.7 · 10⁷ fits in an `int`; the table takes 2¹⁸ · 18 · 4 bytes ≈ 18.9 MB. (4) Submask DP as in @T:lst-22-colour, with `ok` in place of `indep`: 3¹⁶ ≈ 4.3 · 10⁷ steps, after computing `ok` once for all 2¹⁶ groups. (5) Digit DP with the state (position, *x* mod 7, digit sum mod 5, tight): about 19 · 7 · 5 · 10 ≈ 6,650 digit steps per call, and *f*(*R*) − *f*(*L* − 1). (6) None of this chapter's methods: 2⁴⁰ ≈ 1.1 · 10¹² subsets is far too many. Meet in the middle, from the "Complete search" chapter of the *Competitive Programmer's Handbook*, splits the values into two halves of 2²⁰ subsets each.

**Exercise 22.9.** Compare with @T:lst-22-sessions. The places that matter: `cnt[0] = 1` with `last[0] = 0`, the new session `c++; t = task[j];` when `t > T`, and the comparison `c < cnt[mask] || (c == cnt[mask] && t < last[mask])`. Without its second part the method returns 3 instead of 2 for [1, 3, 2, 2, 2] and *T* = 5.

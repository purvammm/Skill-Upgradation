:::exercise{#exr-17-concept} Concept check
Answer true or false, and give a one-line reason or a counterexample.

1. Dijkstra's algorithm may mark a vertex as finished when it is first pushed, as BFS does.
2. If the stale check is deleted from @T:lst-17-dijkstra, some distances come out wrong.
3. With one zero-weight edge, the counting rule of @T:lst-17-count can return a wrong count.
4. Updating the array in place during *K* + 1 Bellman–Ford rounds gives the cheapest route with at most *K* + 1 flights.
5. Two elements are in the same union-find group when `parent[a] == parent[b]`.
6. With union by size, a `find` on 9 elements never visits more than 4 vertices, even without path halving.
7. If two edges of a connected graph have the same weight, the minimum spanning tree is never unique.
8. Kruskal's algorithm, unlike Dijkstra's, still works when some weights are negative.

:::exercise{#exr-17-bug} Find the bug
This method is meant to count shortest paths for LeetCode 1976. It compiles, and on the graph of @T:ex-17-count it returns the correct count 3 for vertex 4. Find a small undirected graph on which it returns a wrong count, say which value it returns and what is correct, and fix it with one line.

```java
static long[] countWaysBuggy(List<int[]>[] g, int src, long mod) {
    int n = g.length;
    long[] d = new long[n], ways = new long[n];
    Arrays.fill(d, Long.MAX_VALUE);
    d[src] = 0;
    ways[src] = 1;
    PriorityQueue<long[]> pq = new PriorityQueue<>((x, y) -> Long.compare(x[0], y[0]));
    pq.add(new long[]{0, src});
    while (!pq.isEmpty()) {
        long[] cur = pq.poll();
        int u = (int) cur[1];
        for (int[] e : g[u]) {
            int v = e[0];
            long nd = d[u] + e[1];
            if (nd < d[v]) {
                d[v] = nd;
                ways[v] = ways[u];
                pq.add(new long[]{nd, v});
            } else if (nd == d[v]) {
                ways[v] = (ways[v] + ways[u]) % mod;
            }
        }
    }
    return ways;
}
```

**Exercise 17.1.** (1) `d[src] = 0`; (2) `Long.compare(x[0], y[0])`; (3) `cur[0] != d[u]`; (4) `d[u] + e[1]`; (5) `pq.add(new long[]{nd, e[0]})`. The subtraction overflows once two distances differ by more than 2³¹ − 1. For *x*[0] = 3 000 000 000 and *y*[0] = 0, `(int) (x[0] - y[0])` is −1 294 967 296, so the comparator claims that 3 · 10⁹ is smaller than 0, and the heap order is broken.

**Exercise 17.5.** (1) False: in @exr-17-dijkstra vertex 1 is first pushed with 9, but its distance is 5. (2) False: the answers stay correct, because a stale pair relaxes with the current `d[u]` and every relaxation fails; only the running time grows. (3) True: with *s* → *a* (1), *s* → *b* (1), *a* → *b* (0), *b* → *t* (1), settling *b* before *a* loses a path (the pitfall after @T:thm-17-count). (4) False: a value improved early in a round is reused later in the same round, so one round can add several edges (@T:fig-17-stops). (5) False: after union(8, 1) in @exr-17-dsu, `parent[5]` = 4 and `parent[1]` = 3, yet 5 and 1 are in one group; compare `find(a) == find(b)`. (6) True: by @T:lem-17-logn the depth is at most log₂ 9 ≈ 3.17, so at most 3 edges and 4 vertices on the path. (7) False: @exr-17-kruskal has three edges of weight 3 and two of weight 4, and its MST is unique. (8) True: the cut property only compares the weights of two edges and never adds weights along a path, so it holds for any real weights.

**Exercise 17.6.** State: (*v*, *c*) with *c* = 1 if the van has passed a station, so 2*n* vertices; give (*v*, 0) the id *v* and (*v*, 1) the id *v* + *n*. For every road *u*–*v* of time *w*, in both directions: (*u*, 0) → (*v*, 1) if *v* has a station, otherwise (*u*, 0) → (*v*, 0); and (*u*, 1) → (*v*, 1). All with weight *w*. Start at (*s*, 1) if *s* has a station, else (*s*, 0). The answer is *d*[(*t*, 1)], or −1 if it is still ∞. The new graph has 2*n* vertices and 4*m* directed edges, so Dijkstra costs O((*n* + *m*) log *n*) time and O(*n* + *m*) memory, with `long` distances. (Because roads are two-way, two Dijkstra runs from *s* and from *t* also work: the answer is the minimum over stations *c* of dist(*s*, *c*) + dist(*c*, *t*).) In the example the plain shortest route is 0–1–5 with time 5, but it passes no station. Through station 2 the best is 0–2–3–5, 4 + 2 + 3 = 9; through station 6 it is 5 + 6 = 11 (0–1–4–6 and back 6–4–1–5). The answer is 9, which a Floyd–Warshall check agrees with; the layered method also matched Floyd–Warshall on 5000 random graphs.

**Exercise 17.7.** The stale check is missing. A vertex whose distance improves after its first push leaves an old pair in the heap; when that pair surfaces, the loop scans the vertex's edges again, and every tight edge adds `ways[u]` a second time. Take the undirected graph 0–1 (5), 0–2 (1), 2–1 (1), 1–3 (1) with source 0. Vertex 1 is pushed with 5, then improved to 2 through vertex 2. After 1 and 3 are settled, the stale pair (5, 1) surfaces, finds 2 + 1 = 3 = *d*[3], and adds `ways[1]` again. The method returns ways[3] = 2, but there is only one shortest path, 0–2–1–3 of length 3. Fix: insert `if (cur[0] != d[u]) continue;` after `int u = (int) cur[1];`, as in @T:lst-17-count. On 3000 random small graphs the fixed method matched a brute force that enumerates all simple paths, and the buggy one was wrong on 267 of them.

**Exercise 17.8.** (1) Dijkstra, @T:lst-17-dijkstra: at most *E* + 1 = 200 001 pushes and as many polls, each about 18 comparisons, so a few million steps. Trap: a distance can reach 99 999 · 10⁹ ≈ 10¹⁴, so use `long`. (2) 0-1 BFS: 10⁶ cells and at most 4 · 10⁶ moves, O(*V* + *E*) with a deque. Trap: push to the front after a 0-move and to the back after a 1-move, and skip a cell whose distance has already improved. (3) Prim's array version, @T:lst-17-prim: 2000 steps of two scans each, about 8 · 10⁶ operations, three arrays of 2000. Kruskal would build 1 999 000 edges (about 72 MB as `int[3]` objects) and sort them with about 4 · 10⁷ comparisons. Trap: compute the distance when needed instead of storing the matrix. (4) Bellman–Ford: *V* − 1 = 499 rounds of 5000 relaxations, about 2.5 · 10⁶. Trap: Dijkstra's (P1) fails with negative edges. (5) *K* + 1 = 51 Bellman–Ford rounds with a copied array (@T:thm-17-rounds): 51 · 10⁴ = 510 000 relaxations. Trap: in-place updates allow too many flights. (6) Union-find: start with *n* groups and subtract 1 for every `union` that returns `true`; 2 · 10⁵ operations of almost O(1) each (@T:thm-17-ackermann). Trap: count only the successful unions. (7) Offline: sort the edges by weight and the queries by *T*, then sweep, adding edges up to each *T* before answering (@T:sec-17-offline): two sorts of 10⁵ items and 10⁵ unions plus 2 · 10⁵ finds. Trap: answer the queries in sorted order, and print them back in input order.

**Exercise 17.9.** Compare with @T:lst-17-dsu. The lines that matter are `parent[x] = parent[parent[x]]` before `x = parent[x]` in `find`, the swap so that the smaller tree goes under the larger, `size[a] += size[b]`, and the final check `used == n - 1`.

## Exercises

:::pitfall Do these only after the mock
Every exercise below uses the solutions in @T:sec-25-after. Sit the paper first, fill in the score sheet and the post-mortem above, and only then start here.
:::

These exercises turn the walkthroughs into something you can reproduce without the book. The first four make you run each solution by hand on an input that is not a sample, so that you see every number the program computes. The last two ask you to write the brute forces from memory and to classify the mistakes you made today.

:::exercise{#exr-25-brute} Write the brute forces from memory

:::answers
**Exercise 25.1.** Factorisations and kernels: 72 = 2³ · 3² → 2; 50 = 2 · 5² → 2; 98 = 2 · 7² → 2; 45 = 3² · 5 → 5; 20 = 2² · 5 → 5; 8 = 2³ → 2; 1 → 1; 49 = 7² → 1; 3 054 243 → 3 (the cofactor 1009² is a square and vanishes); 1 032 247 → 1 032 247 (the cofactor 1013 · 1019 is not a square and stays); 4 128 988 → 1 032 247 (2² vanishes, the cofactor stays); 1 018 081 → 1. The groups are kernel 2: {72, 50, 98, 8}, kernel 5: {45, 20}, kernel 1: {1, 49, 1 018 081}, kernel 1 032 247: {1 032 247, 4 128 988}, kernel 3: {3 054 243}. The number of square products is C(4, 2) + C(2, 2) + C(3, 2) + C(2, 2) + 0 = 6 + 1 + 3 + 1 = 11, which a direct check of all 66 products confirms.

**Exercise 25.2.** The kernels of nodes 1 to 8 are 2, 5, 2, 5, 5, 3, 3, 2.

| child → parent | child's map | parent's map before | swap? | cross | pairs[parent] after | parent's map after |
|---|---|---|---|---|---|---|
| 6 → 3 | {2:1, 3:2} | {2:1} | yes | 1 | 2 | {2:2, 3:2} |
| 2 → 1 | {5:3} | {2:1} | no | 0 | 3 | {2:1, 5:3} |
| 3 → 1 | {2:2, 3:2} | {2:1, 5:3} | no | 2 | 7 | {2:3, 3:2, 5:3} |

beauty = 7, 3, 2, 0, 0, 1, 0, 0 for nodes 1 to 8, and the answer is 13; a brute force over all subtrees and pairs gives 13 too. The swap happens at 6 → 3: node 3's map {2:1} has one key and node 6's has two, so the parent's single entry is poured into the child's map, which becomes node 3's map. At 3 → 1 both maps have two keys, so there is no swap and the child's two entries move; key 2 meets 2 copies against 1, giving the cross count 1 · 2 = 2.

**Exercise 25.3.**

| update | array after | leaves t[4..7] | t[2] | t[3] | g | notDiv | rule | answer |
|---|---|---|---|---|---|---|---|---|
| (3, 45) | [18, 30, 45] | 18 30 45 0 | 6 | 45 | 3 | 0 | drop-one | NO |
| (1, 9) | [9, 30, 45] | 9 30 45 0 | 3 | 45 | 3 | 0 | drop-one | YES |
| (2, 7) | [9, 7, 45] | 9 0 45 0 | 9 | 45 | 9 | 1 | *g* ≠ *p* | NO |
| (3, 12) | [9, 7, 12] | 9 0 12 0 | 9 | 12 | 3 | 1 | `notDiv` > 0 | YES |

The output is 2, the same as the brute force over all proper subsets. The drop-one check runs twice. After (3, 45) it computes gcd(30, 45) = 15, gcd(18, 45) = 9 and gcd(18, 30) = 6, none equal to 3, so the answer is NO although the whole array has gcd 3. After (1, 9) it computes gcd(30, 45) = 15, gcd(9, 45) = 9 and gcd(9, 30) = 3, and stops with YES.

**Exercise 25.4.**

| element | cand[0] | cand[1] | cand[2] | cand[3] |
|---|---|---|---|---|
| A[2] = 1 | 2 | 1 | 0 | 0 |
| A[3] = 2 | 0 | 0 | 3 | 2 |
| A[4] = 2 | 4 | 3 | 3 | 2 |
| best | 4 | 3 | 3 | 2 |

The answer is 2, the best entry with XOR ≥ 3; the bitmask brute force agrees. One optimal subsequence is 1, 2 (indices 0 and 3, XOR 3). The longest non-decreasing subsequence 1, 1, 2, 2 has XOR 0 < 3, and the best lengths with XOR 1 and 2 (3 each, for example 1, 2, 2 and 1, 1, 2) are also below *M*. Only XOR 3 qualifies, and its best is 2.

**Exercise 25.5.** Easy: for every node, collect its subtree with an explicit stack, then for every pair test whether the `long` product is a perfect square, correcting `Math.sqrt` with two `while` loops; O(Σ size²), about *n*³/3 on a chain, so a chain of about 1,000 nodes or a random tree of about 10⁴ nodes. Medium: after each update, try every mask from 1 to 2ⁿ − 2, compute the gcd of the chosen values and stop at the first gcd equal to *p*; about *q* · 2ⁿ · *n* steps, so *n* ≈ 16 with 100 updates. Hard: every mask from 1 to 2ᴺ − 1, check non-decreasing and the XOR; O(2ᴺ · *N*), about *N* = 24 on a sorted array, and guard against `1 << n` with *n* ≥ 32. Complex: backtrack over the edges (*Parent*[*v*], *v*), taking an edge only when both ends are unused; for each matching build every root-to-leaf string with the flipped values and test each pattern with `String.contains`; keep the largest count and, on ties, the fewest flips; *N* ≤ 15. Compare your versions with @T:lst-25-mockfile and @T:lst-25-complex.

**Exercise 25.6.** (1) Input: run every sample before writing logic, and trust the samples over the format text. (2) Stack: on parent-array trees, build a BFS order and loop over it backwards, never recurse. (3) Overflow: compute products of values up to 10⁹ as `(long) a * b`. (4) Idea (the DP's evaluation order): compute every candidate for an element before writing any of them. (5) Edge: test *n* = 1, where the only shorter subsequence is empty. (6) Misread: "exactly *p*" excludes 2*p*, so underline every "exactly", "at most" and "strictly" while reading. (7) Time: the Complex problem gets only the time left after the other three have submissions.

:::exercise{#exr-23-tiers} Design the tiers before you code

:::exercise{#exr-23-bug} Find the bug: subtree sizes from a parent array
This method passes the samples of a problem whose parent array has the root at 0 and every parent smaller than its child. The hidden tests do not promise the second property.

```java
static int[] subtreeSizes(int[] par) {        // par[root] = -1, root = 0
    int n = par.length;
    int[] size = new int[n];
    Arrays.fill(size, 1);
    for (int v = n - 1; v >= 1; v--) size[par[v]] += size[v];
    return size;
}
```

:::answers
**Exercise 23.1.** The ratios are A 0.6, B 0.45, C 0.5, D 0.7 and E 0.2, so the ratio order is D, A, C, B, E with finishing times 15, 45, 90, 110 and 170. Σ *w*·*C* is 6022.5 for the ratio order and 6322.5 for A, B, C, D, E (finishing times 30, 50, 95, 110, 170); a brute force over all 120 orders confirms that 6022.5 is the minimum. Secured by minute 60: 28.5 against 27; by minute 90: 51 against 27; by minute 120: 60 in both. With 150 working minutes, E (ending at 170) is unfinished in both orders. The lemma does decide D and B: D is shorter (15 ≤ 20) and worth more (10.5 ≥ 9), so D first is never behind at any moment.

**Exercise 23.2.** Tier 1, no restriction beyond small sizes: walk up *k* parents per query, O(*q* · depth); for *n*, *q* ≤ 3000 that is at most 3000 · 3000 = 9 · 10⁶ steps. Detect it from *n* and *q*. Tier 2, the tree is a path (par[*v*] = *v* − 1 for every *v* ≥ 1, checked in one O(*n*) loop): the ancestors of *u* are *u* − 1, …, *u* − *k*, so prefix sums answer each query in O(1). Tier 3, the full solution: sums from the root (Chapter 18) give the sum of a vertical path as rootSum[*u*] − rootSum[parent of the *k*-th ancestor], and binary lifting finds the *k*-th ancestor in O(log *n*); about (*n* + *q*) · 18 ≈ 7.2 · 10⁶ steps for *n* = *q* = 2 · 10⁵. Sums need `long` (up to 2 · 10⁵ values of 10⁹). In a mock, write tier 1 first: about ten lines, nearly certain, and it is the oracle for testing the others; then tier 3 if the reading-phase estimate gives it a good ratio, or tier 2 if binary lifting is shaky. Walking without a restriction at the full limits would be up to 2 · 10⁵ · 2 · 10⁵ = 4 · 10¹⁰ steps.

**Exercise 23.3.** With par = [−1, 2, 0] (vertex 2 hangs below the root, vertex 1 below vertex 2) the loop handles *v* = 2 before *v* = 1, so vertex 1's size reaches vertex 2 after vertex 2 has already been added to the root. It returns [2, 1, 2]; the correct sizes are [3, 1, 2]. The check `check(size[0] == n, "root size " + size[0] + " != n")` after the loop catches it: in 20,000 random trees rooted at 0 with shuffled labels, the method was wrong on 13,269 and the check fired on all 13,269. A check `par[v] < v` for every *v* fires on exactly the same trees (all 20,000 agreed): when a parent is numbered above its child, it is processed first, and the child's size never reaches the root. Fix: add sizes in reverse BFS order (Chapter 18), which finishes every child before its parent whatever the numbering; the fixed method matched a brute force on 20,000 random trees.

| 2 | 6 | [−1, 0, 1, 1, 3, 1] | 3 | 3 | no |

The start has buggy 4 and true 5. The final tree is [−1, 0, 1, 1, 3, 2], the tree of @T:fig-23-shrunk. Its only leaves are 4 and 5, and deleting either makes the two diameters agree, so a full pass keeps nothing and the loop ends (@T:lem-23-shrink).

**Exercise 23.5.** (1) True: 9/15 = 0.6 per minute against 8.75/50 = 0.175, and the brute force is also shorter and worth more, so it is never behind. (2) False: spent minutes are gone whatever you choose; only the minutes still needed enter the ratio. (3) False: `assert` runs only with the `-ea` flag, which you normally cannot set on a judge. (4) False: Codeforces compares standard output only, although heavy debug output still costs time. (5) False: on correct tiers the answers are the same, and the brute force costs at most about 4.5 · 10⁶ pair checks per test, far below the time limit. (6) False: under Plan B, Mock 3 is dropped, 28 November is the Day 29 rest routine and 29 November is the exam.

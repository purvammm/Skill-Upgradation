:::exercise{#exr-concept} Concept check
Answer true or false, and give a one-line reason.

1. If every element is positive, a sliding window can count subarrays with sum *k* in O(*n*).
2. For "longest subarray with sum *k*", the map should store the latest index of each prefix.
3. `HashMap<Long, Integer>` is a better choice than `int[]` when the keys are remainders 0..*k* − 1 with *k* ≤ 10⁶.
4. A difference array can answer "what is *a*[4] now?" between two updates in O(1).
5. The number of odd-sum subarrays equals (number of even prefixes) × (number of odd prefixes), with *P*[0] counted as even.

:::answers
**Exercise 2.1.** (1) `seen.put(0L, 1)`; (2) `seen.getOrDefault(prefix - k, 0)`; (3) `seen.merge(prefix, 1, Integer::sum)`. The look-up must come first so that the current prefix is never matched with itself; otherwise, for *k* = 0, every position adds a phantom empty subarray.

**Exercise 2.2.**

| i | a[i] | prefix | prefix − k | found | total |
|---|---|---|---|---|---|
| 0 | 3 | 3 | −4 | 0 | 0 |
| 1 | 4 | 7 | 0 | 1 | 1 |
| 2 | −7 | 0 | −7 | 0 | 1 |
| 3 | 3 | 3 | −4 | 0 | 1 |
| 4 | 1 | 4 | −3 | 0 | 1 |
| 5 | 3 | 7 | 0 | 2 | 3 |
| 6 | 1 | 8 | 1 | 0 | 3 |
| 7 | −4 | 4 | −3 | 0 | 3 |
| 8 | −2 | 2 | −5 | 0 | 3 |
| 9 | −2 | 0 | −7 | 0 | 3 |

The answer is 3. At row 5 the value 0 has been seen twice (the empty prefix and the prefix after index 2), so two subarrays end there: *a*[0..5] = 3 + 4 − 7 + 3 + 1 + 3 and *a*[3..5] = 3 + 1 + 3. The third is *a*[0..1] = 3 + 4, found at row 1.

**Exercise 2.3.** Rows 3–5: remainders 2, 4, 0; counts found before 0, 3, 1; totals 3, 6, 7; `cnt` after row 5 is [2, 0, 1, 0, 4]. The answer is 7, which matches LeetCode 974's first example. With plain `%`, row 4 computes (2 + (−3)) % 5 = −1, and `cnt[-1]` throws an `ArrayIndexOutOfBoundsException`. `Math.floorMod(−1, 5)` is 4, the correct key.

**Exercise 2.4.** *d* = [2, −1, 5, −5, 1, 0, −2] and *a* = [2, 1, 6, 1, 2, 2]. Check *a*[2]: +2 (from [0..3]), +5, −1, so 6.

**Exercise 2.5.** *S* rows 1–3 are [0, 3, 3, 4], [0, 8, 14, 18], [0, 9, 17, 21]. The query is 21 − 4 − 9 + 3 = 11, and directly 6 + 3 + 2 + 0 = 11.

**Exercise 2.6.** (1) True: with positive values the window sum is monotone in each pointer (Chapter 3). (2) False: store the *first* index; later indices give shorter subarrays. (3) False: an `int[]` of size *k* is faster and has no boxing or worst case. (4) False: *a*[4] is a prefix sum of *d*, which costs O(*n*) to recompute; use a Fenwick tree. (5) True: a subarray's sum is odd exactly when its two end prefixes have different parity.

**Exercise 2.7.** Map 0 → −1 and 1 → +1; a substring is balanced when its sum is 0, so its two end prefixes are equal. Store each prefix value with a **count**, look up the **same** value, seed {0: 1}. For `0011010` the prefixes are 0, −1, −2, −1, 0, −1, 0, −1. The value −1 occurs 4 times and 0 occurs 3 times, so the answer is C(4, 2) + C(3, 2) = 6 + 3 = 9.

**Exercise 2.8.** Negative elements break it. With *a* = [−1, 1] and *k* = 5 the prefix remainder becomes −1, the loop stops, and the method returns 0 instead of 1 (the subarray [−1, 1] has sum 0). Fix: `prefix = Math.floorMod(prefix + x, k);` and delete the `if`.

## Exercises

Work these after reading Theory Chapter 12 and before the problem worksheets. The first four make you fill tables by hand: three two-string tables and one interval table. Filling a table once by hand is the quickest way to see which neighbour each entry reads and why the walk back works. :::exercise{#exr-12-concept} Concept check
Answer true or false, and give a one-line reason or a counterexample.

1. When *s*[*i* − 1] ≠ *t*[*j* − 1], the LCS entry dp[*i*][*j*] always equals dp[*i* − 1][*j* − 1].
2. The edit distance from *s* to *t* equals the edit distance from *t* to *s*.
3. The edit distance is never larger than max(*n*, *m*).
4. @T:lst-12-rows can print the edits if you also keep its final row.
5. Every longest common subsequence of *s* and reverse(*s*) is a palindrome.
6. For the palindrome table, the order "*l* from 0 upwards, *r* from *l* + 1 upwards" is valid.
7. The fewest deletions that leave a palindrome equal the fewest insertions that make one.

:::exercise{#exr-12-bug} Find the bug
This two-row edit distance compiles, and it returns the right answer whenever *s* has at most one character. Find the shortest input on which it fails, say what it returns there, explain the cause, and fix it.

```java
static int editDistanceBuggy(String s, String t) {
    int n = s.length(), m = t.length();
    int[] prev = new int[m + 1], cur = new int[m + 1];
    for (int j = 0; j <= m; j++) prev[j] = j;
    for (int i = 1; i <= n; i++) {
        cur[0] = i;
        for (int j = 1; j <= m; j++) {
            if (s.charAt(i - 1) == t.charAt(j - 1)) cur[j] = prev[j - 1];
            else cur[j] = 1 + Math.min(prev[j - 1], Math.min(prev[j], cur[j - 1]));
        }
        prev = cur;                       // keep the new row
    }
    return prev[m];
}
```

:::answers
**Exercise 12.1.** (1) `i > 0 && j > 0`; (2) `s.charAt(i - 1) == t.charAt(j - 1)`; (3) `i--; j--;` (both); (4) `dp[i - 1][j] >= dp[i][j - 1]`; (5) `sb.reverse().toString()`. When *i* = 0 or *j* = 0, one prefix is empty and dp[*i*][*j*] = 0, so no further character can be common; by @T:thm-12-walk the collected characters already form an LCS.

**Exercise 12.2.**

| | `""` | p | o | t | a | t | o |
|---|---|---|---|---|---|---|---|
| `""` | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| t | 0 | 0 | 0 | 1 | 1 | 1 | 1 |
| e | 0 | 0 | 0 | 1 | 1 | 1 | 1 |
| a | 0 | 0 | 0 | 1 | 2 | 2 | 2 |
| p | 0 | 1 | 1 | 1 | 2 | 2 | 2 |
| o | 0 | 1 | 2 | 2 | 2 | 2 | 3 |
| t | 0 | 1 | 2 | 3 | 3 | 3 | 3 |

The LCS length is 3. The walk visits (6,6) up, (5,6) match `o`, (4,5) up, (3,5) left, (3,4) match `a`, (2,3) up, (1,3) match `t`, and prints `tao`. The other longest common subsequences are `pot` and `tat`. At (6,6) both neighbours hold 3. Going left there and keeping the rule afterwards gives `tat`; breaking every tie to the left (at (6,6) and again at (5,4), where both neighbours hold 2) gives `pot`, which uses positions 3, 4, 5 of `teapot` and 0, 1, 2 of `potato`.

**Exercise 12.3.**

| | `""` | l | a | d | d | e | r |
|---|---|---|---|---|---|---|---|
| a | 3 | 3 | 2 | 3 | 4 | 5 | 6 |
| d | 4 | 4 | 3 | 2 | 3 | 4 | 5 |
| l | 5 | 4 | 4 | 3 | 3 | 4 | 5 |
| e | 6 | 5 | 5 | 4 | 4 | 3 | 4 |

The edit distance is 4. One walk back (trying match, then replace, then delete, then insert) gives, from the corner: insert `r`, match `e`, replace `l` by `d`, match `d`, match `a`, replace `r` by `l`, delete `c`. Applied from left to right: `cradle` → `radle` (delete c) → `ladle` (replace r by l) → `ladde` (replace the second l by d) → `ladder` (insert r). The two-row version also returns 4.

**Exercise 12.4.**

| l \ r | 0 c | 1 b | 2 b | 3 d | 4 c | 5 b |
|---|---|---|---|---|---|---|
| 0 c | 1 | 1 | 2 | 2 | 4 | 4 |
| 1 b | — | 1 | 2 | 2 | 2 | 3 |
| 2 b | — | — | 1 | 1 | 1 | 3 |
| 3 d | — | — | — | 1 | 1 | 1 |
| 4 c | — | — | — | — | 1 | 1 |
| 5 b | — | — | — | — | — | 1 |

LPS = 4, and the only longest palindromic subsequence is `cbbc` (a brute force over all 64 subsequences agrees; so does LCS(`cbbdcb`, `bcdbbc`) = 4). The corner is max(dp[1][5], dp[0][4]) = max(3, 4) = 4 because the ends `c` and `b` differ; dp[0][4] = dp[1][3] + 2 = 2 + 2 because its ends are both `c`. The fewest insertions are 6 − 4 = 2. Following the proof of @T:thm-12-ins: drop the last `b` and add a copy in front, make `cbbdc` a palindrome by keeping the ends `c` and turning `bbd` into `dbbd`. The result is `bcdbbdcb`, a palindrome of length 8 that contains `cbbdcb`.

**Exercise 12.5.** (1) False: for `ab` and `ba`, dp[2][2] = 1 but dp[1][1] = 0. (2) True: each edit is undone by one edit (insert and delete swap, a replacement is reversed), so a script from *s* to *t* reversed is a script from *t* to *s* of the same length. (3) True: replace the first min(*n*, *m*) characters where they differ and insert or delete the remaining |*n* − *m*|; at most max(*n*, *m*) edits. A test on 5000 random pairs confirmed |*n* − *m*| ≤ distance ≤ max(*n*, *m*). (4) False: the walk back needs every row, and only the last two survive. (5) False: for `bacba`, `acb` is a longest common subsequence of the string and its reverse `abcab`. (6) False: dp[0][*r*] reads dp[1][*r*] before row 1 is filled; on `badcab` it returns 2 instead of 5. (7) True: both are *n* − LPS(*s*).

**Exercise 12.6.** The best common substring of two prefixes may end anywhere, so knowing its length does not tell you whether it can be extended by the next pair of equal characters; the state must say where the substring **ends**. State: e[*i*][*j*] = length of the longest common suffix of *s*[0..*i* − 1] and *t*[0..*j* − 1], that is, of the longest common substring ending exactly at *s*[*i* − 1] and *t*[*j* − 1]. Transition: e[*i*][*j*] = e[*i* − 1][*j* − 1] + 1 if *s*[*i* − 1] = *t*[*j* − 1], else 0. Base: row 0 and column 0 are 0. Order: row by row. Answer: the **maximum over all entries**, not e[*n*][*m*]. Time O(*nm*) = 2.5 · 10⁷ for 5000 × 5000; memory two rows of `int`, about 40 KB. For `xabcdy` and `abcxabd` the table reaches 3 twice: at (3, 6) for `xab` (positions 0..2 of *s*, 3..5 of *t*) and at (4, 3) for `abc`. So the answer is 3, while the LCS is 4 (for example `abcd` or `xabd`): a subsequence may skip characters, a substring may not.

**Exercise 12.7.** The shortest failing input is *s* = `aa`, *t* = `a`: it returns 2 instead of 1. After row 1, `prev = cur;` makes both names refer to the same array, [1, 0]. In row 2, `cur[0] = 2` also overwrites `prev[0]`, which the diagonal still needs, so the match gives `cur[1] = prev[0]` = 2. In general, from row 2 on, `prev[j - 1]` has already been overwritten by the current row's `cur[j - 1]` when it is read. With one character in *s* only one pass runs, so nothing is read after the aliasing, which is why short tests pass. On 4000 random pairs of length up to 6 it was wrong 2188 times; for example `abc` against `abc` gives 2 instead of 0. Fix: swap the references, `int[] tmp = prev; prev = cur; cur = tmp;`.

**Exercise 12.8.** (1) @T:lst-12-lcs with two rows: 2.5 · 10⁷ steps (about 0.15 s measured), 40,008 bytes; the full `int` table would also fit (100,040,004 bytes) but uses most of the limit for nothing. (2) The walk needs the whole table: a `short` table (50,020,002 bytes, about 50 MB) or one direction byte per cell (25,010,001 bytes) next to two rows. (3) 10¹⁰ steps, about 60 s even at the measured speed, so no O(*nm*) DP can work. If both strings are permutations of 1..*n*, replace each value of *t* by its position in *s*; a common subsequence is then an increasing subsequence of those positions, and the LIS methods of Chapter 13 give the answer in O(*n* log *n*). (4) Put the short string across the top: 100,001 × 11 ≈ 1.1 · 10⁶ cells, and even the full table is 4,400,044 bytes. (5) The interval table: 500,500 entries in use, a 1001 × 1001 `int` array of 4,008,004 bytes; or LCS with the reverse, 10⁶ steps. (6) @T:lst-12-count with every entry reduced modulo 10⁹ + 7, adding the modulus back after the subtraction; 10⁶ steps, and the `long` table is 8,016,008 bytes (two rows also work).

**Exercise 12.9.** Compare with @T:lst-12-rows. The lines that matter are `cur[0] = i;` at the start of each row, the `prev[j - 1]` in both branches, and the three-line swap at the end of the row.

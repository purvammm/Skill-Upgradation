## Exercises

Work these after reading Theory Chapter 19 and before the problem worksheets. The first four make you run a tree DP, the two passes of rerooting and a small-to-large merge by hand, each on a tree given as a parent array and its BFS order, exactly as the code sees it. Keep the order of the rows: in every one of these loops a value is only correct at the moment the loop reaches it. The rest ask you to judge, design and debug on your own.

:::exercise{#exr-19-concept} Concept check
Answer true or false, and give a one-line reason or a counterexample.

1. In the independent-set DP, take[*v*] adds max(take[*c*], skip[*c*]) over the children *c*.
2. Pass 2 of rerooting may walk the BFS order backwards, as long as pass 1 is complete.
3. In @T:lst-19-matching, `gain[p]` can end up negative.
4. In @T:lst-19-ecc, the line `up[v] = 1 + Math.max(up[p], down1[p])` (without the "sideways" check) gives the same eccentricities.
5. If the child's set is larger but you copy it into the parent's smaller set anyway, @T:lst-19-distinct returns wrong answers.
6. On a star with centre 0 and 9 leaves, @T:lst-19-distinct moves 8 entries in total.
7. On the path 0–1–2–3, the edge operations of LeetCode 3068 can flip exactly the vertices {1, 3}, but never exactly {0, 1, 2}.
8. `new int[n][26]` for *n* = 10⁵ needs about 10 MB for the counters alone.

:::exercise{#exr-19-bug} Find the bug
This method should return the number of distinct colours in every subtree. It compiles, and for par = [−1, 0, 0] with colours [1, 2, 2] it returns the correct [2, 1, 1]. Find a tree with four vertices on which it is wrong, say what it returns there and what is correct, and fix it with one line.

:::nobreak
```java
static int[] distinctBuggy(int[] par, int[] order, int[] color) {
    int n = par.length;
    int[] ans = new int[n];
    @SuppressWarnings("unchecked")
    HashSet<Integer>[] set = new HashSet[n];
    for (int i = n - 1; i >= 0; i--) {
        int v = order[i];
        if (set[v] == null) set[v] = new HashSet<>();
        set[v].add(color[v]);
        ans[v] = set[v].size();
        int p = par[v];
        if (p == -1) continue;
        if (set[p] == null) {
            set[p] = set[v];
        } else {
            HashSet<Integer> big = set[p], small = set[v];
            if (big.size() < small.size()) {
                HashSet<Integer> t = big;
                big = small;
                small = t;
            }
            big.addAll(small);
        }
        set[v] = null;
    }
    return ans;
}
```

:::exercise{#exr-19-limits} Complexity and limits
For each task, choose the technique with @T:tbl-19-choose and justify it with an operation count.

1. *n* = 10⁵: for every vertex, the number of distinct values (up to 10⁹) in its subtree.
2. *n* = 2 · 10⁵ given as an edge list: for every vertex, the sum of its distances to all others.
3. *n* = 10⁵ vertices labelled with lowercase letters: for every vertex, how many vertices of its subtree carry its letter.
4. *n* = 10⁵ with weights: the largest total weight of vertices with no two adjacent.

:::answers
**Exercise 19.1.** (1) `Arrays.fill(size, 1)`; (2) `n - 1`; (3) `down[v] + size[v]`; (4) `ans[order[0]] = down[order[0]]`; (5) `ans[par[v]] - size[v] + (n - size[v])`. Removing the edge between *v* and its parent splits the tree into the same two parts whatever the root is: the subtree of *v* (rooted at `order[0]`) and the rest. The formula only needs the size of the part on *v*'s side, so the original size[*v*] is correct (@T:thm-19-reroot).

**Exercise 19.2.**

| v | w[v] | take[v] | skip[v] | adds to take[par] | adds to skip[par] |
|---|---|---|---|---|---|
| 7 | 3 | 3 | 0 | 0 | 3 |
| 6 | 2 | 2 | 0 | 0 | 2 |
| 8 | 4 | 4 | 0 | 0 | 4 |
| 5 | 6 | 6 | 5 | 5 | 6 |
| 4 | 1 | 1 | 0 | 0 | 1 |
| 3 | 4 | 4 | 0 | 0 | 4 |
| 2 | 5 | 10 | 10 | 10 | 10 |
| 1 | 2 | 2 | 5 | 5 | 5 |
| 0 | 3 | 18 | 15 | — | — |

The best weight is max(18, 15) = 18. Walking forwards: take 0 (18 > 15); skip 1 and 2 because 0 is taken; 3, 4, 5 and 8 have skipped parents and take > skip, so take them; 6 and 7 are skipped because 5 is taken. The set is {0, 3, 4, 5, 8}, weight 3 + 4 + 1 + 6 + 4 = 18, and a brute force over all 2⁹ subsets finds it as the only optimum. Vertex 2 has take = skip = 10, but its parent is taken, so it must be skipped anyway.

The swap happened at the last merge: vertex 1's map had 3 entries and vertex 0's map (handed up from 2) had 2, so 2 entries moved instead of 3. The cross count 4 is the pairs between {2, 6} and {4, 8}, the vertices with key 5 on each side. **Exercise 19.5.** (1) False: if *v* is taken, no child may be, so take[*v*] adds skip[*c*]; the max belongs in skip[*v*] (@T:thm-19-mis). (2) False: ans[*v*] is computed from ans[par[*v*]], which must already be final, and only the forward walk guarantees that. (3) False: `gain` starts at 0 and is only ever raised by `Math.max`, which encodes "match *p* to no child" as the option of gaining 0. (4) False: on the two-vertex tree 0–1 the longest chain from 0 goes through 1 itself, so up[1] becomes 1 + 1 = 2, and ecc[1] = 2 instead of 1. (5) False: the answers stay correct, but on a caterpillar every step copies the long set and the time becomes quadratic (the pitfall after @T:lst-19-distinct). (6) True: the first leaf hands its set over, and each of the other 8 leaves moves one entry. A count in code gives 8. (7) True: by @T:lem-19-even, exactly the even-sized sets can be flipped. {1, 3} comes from operating on the edges 1–2 and 2–3, and {0, 1, 2} has odd size. (8) True: 2.6 · 10⁶ `int`s are 10.4 MB, plus about 1.6 MB of row headers.

**Exercise 19.6.** Replace size[*v*] by *W*[*v*], the number of parcels in the subtree of *v*, with total *W* = *W*[root]. Let down[*v*] = Σ *w*[*x*] · dist(*v*, *x*) over the subtree of *v*. Pass 1 (backwards): *W*[*p*] += *W*[*v*] and down[*p*] += down[*v*] + *W*[*v*], because every parcel below *v* travels one more road to reach *p*. Pass 2 (forwards): ans[root] = down[root] and ans[*v*] = ans[*p*] − *W*[*v*] + (*W* − *W*[*v*]): moving the warehouse from *p* to *v* saves one road for the *W*[*v*] parcels on *v*'s side and adds one for the rest. Root the edge list with `parentsFromEdges` first; then both passes are O(*n*) time and memory. A cost can reach about 10⁴ · 10⁵ · 10⁵ = 10¹⁴, so `long` is needed. For the example, *W* = [14, 4, 9, 1, 1, 9, 5] and down = [29, 2, 14, 0, 0, 5, 0], and the costs are ans = [29, 35, 25, 47, 47, 21, 25]. The best town is 5, with cost 21. A BFS from every town gives the same costs, and the method matched that brute force on 4000 random weighted trees.

**Exercise 19.7.** After the swap, `big` may be the child's set, but `set[p]` still points at the parent's old, smaller set, and the merged contents are lost. Take par = [−1, 0, 0, 1] with colours [1, 2, 3, 4]. Vertex 3 hands {4} to 1, and vertex 2 hands {3} to 0. Then vertex 1 has the set {2, 4}, which is larger than 0's set {3}, so the references swap and {3} is poured into {2, 4}; but `set[0]` stays {3}. The method returns [2, 2, 1, 1] instead of [4, 2, 1, 1]. Fix: add `set[p] = big;` after `big.addAll(small);`, as in @T:lst-19-distinct. On 3000 random trees with up to 10 vertices the buggy method was wrong on 905.

**Exercise 19.8.** (1) Small-to-large sets, @T:lst-19-distinct: at most about *n* log₂ *n* ≈ 1.7 · 10⁶ moves (@T:thm-19-s2l). (2) Rerooting, @T:lst-19-sumdist: two passes of 2 · 10⁵ steps. Sums reach 19 999 900 000 (from the end of a chain), more than an `int` holds, so use `long`. (3) Count arrays merged upwards, 26 · 10⁵ = 2.6 · 10⁶ additions and 10.4 MB; or @T:thm-19-before with one global array of 26 counters and O(*n*) memory. (4) The two-state tree DP, @T:lst-19-mis: O(*n*). (5) No: (3 · 10⁴)² = 9 · 10⁸ steps, far over the budget; rerooting does it in O(*n*). (6) The tree drops out (@T:lem-19-even): the parity greedy of @T:thm-19-parity in O(*n*), with a `long` sum. (7) Rerooting with the two best chains, @T:lst-19-ecc: three O(*n*) loops.

**Exercise 19.9.** Compare with @T:lst-19-pairs. The points that matter: add the vertex's own key (and its `same` pairs) before the hand-over, pass `pairs[v]` up in both branches, swap the references when the parent's map is smaller, add `have * e.getValue()` to `cross` before updating `big`, store `big` in `mp[p]`, and set `mp[v] = null`.

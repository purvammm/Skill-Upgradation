3. *n* ≤ 14 sights and the travel time between every pair are given. Starting at sight 0, visit every sight once in the least total time.

```java
static int boatsLightestFirst(int[] people, int limit) {
    Arrays.sort(people);
    int i = 0, boats = 0;
    while (i < people.length) {
        boolean pair = i + 1 < people.length && people[i] + people[i + 1] <= limit;
        i += pair ? 2 : 1;                  // the two lightest together if they fit
        boats++;
    }
    return boats;
}
```

**Exercise 28.3.**

1. Previous strictly smaller element: monotonic stack (Chapter 7), O(*n*). Signal: "most recent earlier day with a lower price".
2. Prefix XOR with a hash map of earlier prefix values (Chapters 2 and 8): a block XORs to zero exactly when its two end prefixes are equal. O(*n*) expected. Signal: "contiguous blocks" plus "XOR".
3. Bitmask DP over (set visited, last sight) (Chapter 22): 2¹⁴ · 14 · 14 = 3,211,264 steps. Signal: *n* ≤ 14 and "visit every sight once".
4. BFS order from the parent array, walked backwards to add each salary to the parent (Chapter 18), O(*n*), no recursion. Signal: a parent array and "everyone below".
5. Binary search on the answer *T* (Chapter 6): the check Σ ⌊*T*/*t*[*i*]⌋ ≥ *m* is monotone in *T*. The answer is at most *m* · min *t* ≤ 10¹⁸, so about 60 checks of O(*n*), 6 · 10⁶ steps. Use `long`, and stop adding once the sum reaches *m*: 10⁵ terms of up to 10¹⁸ would overflow even a `long`. Signal: "how soon" with a monotone check.
6. Dijkstra (Chapter 17): non-negative weights, about (*n* + *m*) log *n* ≈ 5.1 · 10⁶ steps; distances up to 10⁵ · 10⁹ need `long`.
7. Lazy segment tree with range add and range maximum (Chapter 21): O((*n* + *q*) log *n*) ≈ 3.4 · 10⁶ steps. Signal: range updates mixed with range queries.
8. Digit DP (Chapter 22) with the state (position, last digit or "not started", tight), answering count(*R*) − count(*L* − 1): about 19 · 11 · 2 · 10 = 4,180 steps. Signal: *R* ≤ 10¹⁸ and a digit property.
9. Interval DP (Chapter 14): the last merge splits the row into two parts, so cost[*l*][*r*] = min over the split *k* of cost[*l*][*k*] + cost[*k* + 1][*r*] + sum(*l*..*r*). O(*n*³) = 2.7 · 10⁷. Signal: *n* ≤ 300 and "merge neighbours".
10. Two-string DP (Chapter 12): the answer is |*s*| + |*t*| − 2 · LCS(*s*, *t*), an O(*nm*) = 9 · 10⁶ table. Signal: two strings and "turn one into the other".
11. Union-find (Chapter 17): start with *n* groups and subtract one for every union that joins two different groups. Nearly O(1) per event.
12. Small-to-large merging of colour sets (Chapter 19): each colour moves O(log *n*) times, O(*n* log *n*) expected in total, over a BFS order without recursion. Signal: "for every node … in its subtree" with a set-valued answer.

**Exercise 28.5.** *Part 1.* Sorted, the weights are [1, 2, 3, 3, 4, 5, 6].

| boat | i | j | p[i] + p[j] | boat holds |
|---|---|---|---|---|
| 1 | 0 | 6 | 7 | {6} |
| 2 | 0 | 5 | 6 | {1, 5} |
| 3 | 1 | 4 | 6 | {2, 4} |
| 4 | 2 | 3 | 6 | {3, 3} |

Four boats; the fifth row stays empty because the loop ends with *i* = 3 > *j* = 2. Both lower bounds are 4: the total weight is 24 and ⌈24/6⌉ = 4, and ⌈7/2⌉ = 4. So the answer is optimal, and the brute force agrees.

*Part 2.* [1, 1, 2, 2] with *limit* = 3: the greedy pairs {1, 1}, then 2 + 2 > 3 leaves {2} and {2}, three boats; {1, 2} and {1, 2} need only two. A search over every input with at most three people and *limit* ≤ 8 finds no failure, so the smallest failures have four people; on 10,000 random inputs with up to nine people the greedy is wrong on 2,694. The cause is a **wrong idea**: pairing the two lightest people spends a light person who could have carried a heavy one, the opposite of the exchange argument in @T:thm-28-boats. Rule: a greedy is either proved by an exchange argument or stress-tested against a brute force before it is submitted.

:::answers
**Exercise 3.1.** (1) `cnt.merge(a[r], 1, Integer::sum)`; (2) `cnt.size() > k`; (3) `cnt.remove(a[l])`; (4) `l++`; (5) `Math.max(best, r - l + 1)`. To count all valid windows, replace line (5) by `count += r - l + 1` (with a `long count`), because every window [*l*′, *r*] with *l* ≤ *l*′ ≤ *r* is valid.

**Exercise 3.2.**

| i | a[i] | removed at back | removed at front | deque (indices) | max |
|---|---|---|---|---|---|
| 0 | 3 | — | — | 0 | — |
| 1 | 1 | — | — | 0 1 | — |
| 2 | 5 | 1, 0 | — | 2 | 5 |
| 3 | 2 | — | — | 2 3 | 5 |
| 4 | 2 | 3 | — | 2 4 | 5 |
| 5 | 6 | 4, 2 | — | 5 | 6 |
| 6 | 0 | — | — | 5 6 | 6 |
| 7 | 4 | 6 | — | 5 7 | 6 |

The output is [5, 5, 5, 6, 6, 6]. In this input no index ever leaves at the front, because each front is removed at the back by a larger value before it expires. At *i* = 4 the `<=` removes index 3: the newer copy at index 4 has the same value and stays in the window longer, so the older copy can never be needed.

**Exercise 3.3.** *r* = 3: *l* 0 → 2, counts {1: 1, 3: 1}, length 2, best 3. *r* = 4: *l* stays 2, {1: 1, 3: 2}, length 3, best 3. *r* = 5: *l* 2 → 3, {2: 1, 3: 2}, length 3, best 3. *r* = 6: *l* stays 3, {2: 2, 3: 2}, length 4, best 4. *r* = 7: *l* 3 → 5, {2: 2, 4: 1}, length 3, best 4. The answer is 4, the window [3, 3, 2, 2].

**Exercise 3.4.** (1) Monotone: a sub-window has no more zeros; grow-and-shrink. (2) Not monotone: [4, 6] is valid but its sub-window [4] is not. Extending a valid window keeps it valid, so shrink-while-valid finds the shortest. (3) Not monotone ([4, 6] is valid, [4] is not) and not closed under extension ([4, 6, 1] is invalid). Neither loop works directly; count it as (windows with sum ≤ 10) − (windows with sum ≤ 9), two monotone scans, or use prefix sums. (4) Monotone: a sub-window's maximum is no larger and its minimum no smaller; grow-and-shrink (with two deques, Exercise 3.6). (5) Not monotone, but closed under extension; shrink-while-valid with need/have counters. (6) Not monotone: [20, −15] has sum 5, its sub-window [20] has sum 20; neither loop, use prefix sums.

**Exercise 3.5.** atMost(2): *l* = 0, 0, 0, 2, 2 and additions 1, 2, 3, 2, 3, total 11. atMost(1): *l* = 0, 0, 2, 3, 4 and additions 1, 2, 1, 1, 1, total 6. Exactly two distinct values: 11 − 6 = 5. They are [2, 2, 1], [2, 1], [1, 3], [1, 3, 1] and [3, 1].

**Exercise 3.6.** Removing an end element cannot raise the maximum or lower the minimum, so sub-windows of valid windows are valid: grow-and-shrink applies. Keep two monotonic deques of indices: one with decreasing values (its front is the window maximum) and one with increasing values (its front is the minimum). When *a*[*r*] enters, pop dominated indices from the back of each and append *r*. While front-max − front-min > *d*, advance *l* and pop the front of either deque if its index is now < *l*. Each index enters and leaves each deque once, so the total is O(*n*). For the example the answer is 3, for instance [4, 6, 5] or [9, 7, 8].

**Exercise 3.7.** The method never removes a key whose count drops to 0, so `cnt.size()` never decreases. As soon as the array contains more than *k* distinct values, the `while` loop keeps advancing *l* past *r* and off the end of the array. For *a* = [1, 2, 3] and *k* = 2 it throws `ArrayIndexOutOfBoundsException` at *r* = 2. The samples it passed, such as [1, 2, 1, 2] and [5, 5, 5] with *k* = 2, never exceed *k* distinct values. Fix: `if (cnt.merge(a[l], -1, Integer::sum) == 0) cnt.remove(a[l]);`.

**Exercise 3.8.** (1) Negative values break windows: prefix sums with a hash map, O(*n*) expected. (2) All values positive, so "sum ≥ *S*" survives extension: shrink-while-valid window, O(*n*). (3) Order does not matter: sort, fix *i*, then count pairs with sum < *T* − *a*[*i*] using `countPairsAtMost` on the suffix; O(*n*²) ≈ 4.5 · 10⁶ steps. (4) Fixed window size: monotonic deque with the comparison flipped, O(*n*). (5) "At most 3 distinct" is monotone: grow-and-shrink with an `int[]` of counts, O(*n*).

**Exercise 3.9.** Compare with @T:lst-3-windowmax. Invariant: the deque holds indices of the current window in increasing order with strictly decreasing values, and every window index not in it is dominated by a later, at least as large index. Each index is added once and removed at most once, so there are at most 2*n* deque operations.
